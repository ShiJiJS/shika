# P2 · 留白交互原型

入口：**http://127.0.0.1:8766/p2/**。这是完整的 HTML 演示原型，用于试用界面与操作流程，不是 Flutter App，也未连接真实 NAS。

用户已确认 B 的视觉风格。本版完成已约定的原型范围，等待实际试用反馈；GitHub [P2 #3](https://github.com/ShiJiJS/video_viewer/issues/3) 保持打开。Flutter 的 D1 仍由 P2 的用户验收阻塞。

## 先试这几条

1. 顶栏从左到右：当前页名、轮次位置 / 数量，右侧严格为**文件夹、随机 / 顺序、更多**三个按钮。第二个按钮不是浏览 / 整理切换。
2. 文件夹按钮 → 视频收藏 → 收集 → 花草 → 竖版 → 使用此目录。可选任意层级，也可回到「媒体目录」使用全部目录；范围包含下级目录。当前目录作为标签行的小范围项显示，再点可重新选择。
3. 标签点击即筛选，再点取消；多标签同时满足，并与目录范围和视频属性组合。原型提供横竖版素材，点画面播放/暂停，上下滑动切换，桌面也可拖动、滚轮或用上下键。轮次向前不重复，允许回看，末尾显示完成；当前视频播完循环，切换从头开始。
4. 第二个顶栏按钮切换随机 / 顺序播放，顺序按目录和文件名排列。选择改变时开始新轮次；普通重开继续原轮次与位置。新增扫描结果留待下一轮。
5. 横版视频显示「横屏」按钮。点击进入浏览器全屏并尝试锁定横向；系统不支持锁方向时使用横向舞台布局。退出后不重置当前视频。已在隔离桌面浏览器验证原生全屏进出和 844 × 390 横向布局；没有声称验证过 Android 真机方向锁。
6. 更多菜单中有打标签、归档、详情、整理模式、新轮次与移入回收站；普通浏览不常驻这些操作。整理模式会额外突出删除，和顶栏的播放模式是两件事。
7. 视频库 → 多选 → 选择视频 → 打标签 / 归档 / 移入回收站。批量标签追加或移除指定标签，不覆盖其余关联。属性筛选提供方向、时长和类型；标题搜索与标签筛选分开。
8. 标签页可新建、改名、删除，点标签进入对应视频结果。删除标签只解除关联。
9. 设置中可进入连接、媒体目录、归档分类、回收站、备份恢复。归档先预览，再明确执行；冲突不覆盖。删除后可撤销；回收站可恢复或确认后永久删除，不自动清空。
10. 备份可实际下载 JSON，再从文件导入，校验、核对目录映射并确认完整替换；保留恢复前快照，不把口令和媒体字节放入备份。

## 演示数据与复位

- 6 个可播放条目、1 个缺失条目、1 个初始回收站条目，分布于 `/videos`、`/collection` 两个虚拟挂载目录。多条记录复用同一个 MDN 视频及衍生竖版，封面使用不同时间帧，名称/目录/标签用于演示操作，并非新增的实拍素材。
- 用户操作通过浏览器 localStorage 保存，刷新后可读回；密码不保存。模拟连接的口令为 `demo`，默认已填。输入其它口令可看失败状态；地址填 `unreachable` 可看不可达状态。
- **所有扫描、归档、删除、恢复只修改演示记录，绝不读写 NAS 文件。** 原视频引用的是仓库附带素材，原型没有上传和文件共享权限。
- [复位并回到浏览](http://127.0.0.1:8766/p2/?reset=1)。仅复位本原型自己的存储键，不清理浏览器其它站点数据。
- 首次直接进入可试用状态；首次连接和异常可从设置进入，或用以下开发状态地址。状态地址只写在交付文档，不放进产品页面。

| 地址参数 | 用途 |
| --- | --- |
| `?page=library` / `tags` / `settings` / `connection` / `roots` / `trash` / `categories` / `backup` | 直接查看对应页面 |
| `?state=folders` | 目录层级选择 |
| `?state=landscape` | 定位到横版视频 |
| `?state=filtered` | 标签筛选状态 |
| `?scenario=empty` | 空库（临时内存状态，复位可恢复） |
| `?scenario=offline` | 服务连接失败 |
| `?scenario=root-unavailable&page=roots` | 整个目录不可用、缺失记录保留 |
| `?scenario=write-failure` | 删除、移动、恢复操作失败 |
| `?scenario=conflict` | 归档目标 / 回收站恢复同名冲突 |
| `?scenario=storage-failure` | 保存失败回滚，无假成功 |
| `?scenario=loading` | 短暂加载进度 |

`scenario` 只控制本次页面运行，未作为用户设置保存。测试或截图使用可丢弃浏览器上下文，和用户正在试用的状态相互独立。

## 本机启动与验证

从 `prototypes` 目录启动静态文件服务：

```powershell
& 'C:\Users\Todoki\.cache\codex-runtimes\codex-primary-runtime\dependencies\python\python.exe' -m http.server 8766 --bind 127.0.0.1
```

在仓库根目录运行 `node prototypes/p2/validate.mjs`。脚本默认使用本机 Edge 和已随工作环境提供的 Playwright 包；可用 `VIDEO_VIEWER_BROWSER`、`VIDEO_VIEWER_PLAYWRIGHT`、`VIDEO_VIEWER_PREVIEW` 指定其它路径。它只操作本机 HTML 和可丢弃浏览器数据，不访问 NAS。

8 条端到端用户流程连续 3 轮通过，结果保存于 `validation-run-1.json` 到 `validation-run-3.json`。验证覆盖：目录逐层选择与刷新恢复、随机无重复/顺序/回看/全屏、标签与批量修改、删除撤销/回收站/永久删除确认、归档预览无副作用、备份下载/错误文件/确认恢复、写入失败回滚，以及连接错误/不可用目录/空筛选恢复。

测试断言可见界面、视频播放状态、真实下载和刷新后读回，不以调用了哪个内部方法作为通过依据。初轮发现的是测试选择了当前视频没有的标签、以及未等待视图切换就计数；修正测试后连续 3 轮通过。后来通知层级、触达和封面调整针对变化区域重新检查了实际画面。

截图工具曾在与多轮测试并行运行时报告本机素材瞬时连接拒绝，串行重截后已全部通过；没有为此改动项目环境或生产配置。

## 文件与证据

- `index.html` / `style.css` / `app.js`：原型界面、视觉语言与演示状态。沿用 P1 的 Alpine 与媒体素材，没有修改 Flutter 工程。
- `DESIGN.md`：选定设计规范、确认过的交互和评审修订。
- `screenshots/`：默认页、文件夹、顺序播放、横版/全屏、归档冲突、回收站、目录不可用、窄屏等实际画面与检查报告。
- `evidence/`：首屏与文件夹面板的 1×/2× 图、出场和展开录屏及运动检查报告。录屏首中末帧与一致性报告已检查；没有用静态截图宣称完成了真机手势验证。
- `review.md`：1 轮独立画面评审与 2 轮复核的发现、修正和范围限制。存量风格扩展，不打分；功能验证由主 Agent 的浏览器流程检查承担。

尚未验证真实 NAS 文件事务、服务鉴权、媒体兼容、Android 原生手势和真机方向锁；这些是后续客户端、服务端和联调任务的验收内容。P2 本身仍等待用户确认使用体验。
