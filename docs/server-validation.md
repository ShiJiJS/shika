# 服务端实现与验证

S1 已实现并通过 WSL2 Docker 验证。S2–S6、Flutter 真实网络联调与最终 NAS/目标 Android 验收继续按 GitHub 任务推进。本文件只记录已有证据，完整计划见 [服务端方案](server-plan.md)。

## S1：认证、扫描、目录与列表

实现位于 `services/server`，通过根目录 Compose 单服务、单端口运行。提供个人口令登录与凭据撤销、允许挂载范围内的媒体目录管理、目录层级、递归扫描、媒体元数据、授权缩略图、组合属性查询和分页列表。

扫描使用单个后台执行器，任务阶段和结果持久化；重复手动/定时刷新合并正在运行的扫描。文件以跨两次观察及处理前后的属性校验确认稳定，未变化文件复用探测结果和缩略图。目录不可访问、递归失败和扫描中断保留原记录；只有成功完整扫描才能标记未发现视频缺失。路径遍历与符号链接拒绝，文件读取通过不跟随链接的目录描述符进行。

已有文件保存稳定 ID、文件属性、快速及完整 SHA-256 证据。外部移动后的身份匹配与标签继承仍属于 S5；同路径内容替换不会沿用旧记录。原文件在本阶段只读，不执行目录整理、回收站或永久删除。

## 验证环境与结果

- WSL2 Ubuntu-24.04，Docker 29.9.1，Compose 5.6.0；Linux amd64。
- Python 3.13.16，SQLite 3.40.1（默认回滚日志），FFmpeg 5.1.9；Python 依赖和基础镜像摘要已锁定。SQLite 事务由服务串行短写，未启用 WAL。
- Ruff 检查与格式检查通过；**13 项 API 集成测试通过**。同一 runtime 构建测试镜像，以 UID/GID 1000、只读根文件系统和临时测试目录运行，未使用个人媒体。结果见 [测试输出](server-evidence/s1-api-tests.txt)。
- 覆盖媒体发现/元数据/原字节保留、分页、空目录、子树及属性范围、两独立目录和重叠目录、鉴权与撤销、容器重开后的持久记录、定期新增、写入中文件延迟、越界与符号链接、目录断开/权限失败、扫描中途目录断开及中断后重扫。
- 实际 Compose runtime 在 Windows 获得授权列表和 JPEG 缩略图；模拟器经 `10.0.2.2:8760` 获得认证 API 的 HTTP 200，返回同一服务标识。容器强制重建后，服务标识、8 个视频 ID 和有效会话保留。见 [运行检查摘要](server-evidence/s1-live.json)。
- 在稳定观察阶段对实际 Compose 容器发送 SIGKILL，重启后原任务标为 interrupted/service_restarted，未产生缺失记录，8 个 ID 保留，随后重扫完成。见 [强制终止恢复摘要](server-evidence/s1-crash-recovery.json)。

当前锁定 Starlette 对 HTTPX TestClient 发出一项弃用提示，所有测试通过；后续升级时需要同步检查测试传输兼容。模拟器 shell 探针需要让输入保持到响应返回；这只验证认证网络可达，Flutter 网络提供方仍待 I1。

## 已验证媒体样本

这些都是测试中生成的 1 秒素材，服务端探测及缩略图均通过。没有据此声称 Android 解码、原视频网络播放或真实收藏兼容已通过。

| 容器/样本 | 视频编码 | 音频编码 | 附加检查 |
| --- | --- | --- | --- |
| MP4 | H.264 Baseline | AAC | 竖版、faststart |
| MOV | H.264 | AAC | 横版、faststart |
| MOV | H.264 | AAC | 90° 旋转矩阵，按显示方向交换尺寸 |
| MOV | HEVC / hvc1 | AAC | 与 H.264 MOV 分开记录 |
| MOV | ProRes Proxy | PCM s16le | 10 bit、4:2:2 |
| MKV | H.264 | AAC | 容器区分 |
| WebM | VP9 | Opus | 容器及音频区分 |
| AVI | MPEG-4 Part 2 | MP3 | 容器及视频编码区分 |

损坏 MOV 返回媒体探测失败，不妨碍其他素材入库。Android 实际播放、Range 拖进度、倍速和不支持格式的反馈由 S2/I2 继续验证；真实 NAS、目标手机、较大文件和实际码率条件仍属 V1。

## 运行与复现

启动、配置、测试命令和当前 API 说明见 [服务端 README](../services/server/README.md)。开发数据保存在 WSL 原生目录 `~/.local/share/video-viewer-dev`，管理数据与口令均不入库。额外预加载性能优化按后续事项评估，当前没有虚构 NAS 延迟或资源阈值。
