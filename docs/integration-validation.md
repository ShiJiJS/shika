# Flutter 与真实服务联调

服务端 S1–S6 已通过 WSL Docker 验证。I1 连接/列表、I2 真实播放和 I3 标签已完成，接下来推进 I4 文件操作、I5 外部变化和 I6 备份恢复。这里仅登记实际验证结果；完整 NAS 和目标手机验收属于 V1。

## I1：连接、扫描、目录与列表（完成）

`ServerLibraryRepository` 通过 HTTP API 连接服务。Android 保存可撤销访问凭据与实例 ID，不保存口令；凭据失效清理会话，保留地址供重新连接。请求有绝对超时、响应大小限制和取消机制；地址跳转不会转发访问凭据。首帧先显示界面，再异步恢复连接。

视频列表按 24 条分页；启动只读取元数据、计数和最多 3 条播放摘要。目录按层级加载，并使用服务返回的稳定目录 ID。筛选或搜索变化会取消旧读取，迟到结果不覆盖当前范围。正式标签以 ID 关联，名称单独映射；演示模式仍使用原来的独立数据存储。

已通过 Flutter 静态分析及 17 项单元/界面测试，其中 7 项使用真实回环 HTTP 验证鉴权、AND 参数、超时、正文取消、大小限制和禁止跨源重定向，另 2 项验证空轮次及旧分页取消。服务端目录 ID 查询新增公开 API 测试，全部 77 项服务端回归通过。

Android 16 模拟器两个原生端到端流程均通过，见 [完整输出](integration-evidence/i1-android.txt) 和 [结果及物理重启事件](integration-evidence/i1-summary.json)：

- 正确/错误口令、错误保留输入、口令遮挡；首次只取播放窗口。27 条真实媒体显示授权缩略图，首批 24 条、下一页补齐。未授权缩略图确实返回 401。
- 按挂载目录进入两层子目录，得到 25 条；空目录保持 0，返回全部目录得到 27 条。连续输入时刻意延迟旧查询，迟到结果没有覆盖新搜索。
- 外部增加视频后通过公开 UI 扫描，列表变为 28 条，旧轮次仍为 27 条，新增留到新轮次。断开一个根目录显示不可用，缺失计数保持 0；重新接入恢复。
- 真实停止 Docker 容器约 9 秒，UI 刷新失败而连接配置保留；重启后重试恢复同一服务实例。服务主动撤销会话后返回连接页，清理凭据并保留地址，口令为空。
- 强制停止 Android 进程，另一次原生测试启动后直接恢复加密凭据及深层目录的 25 条轮次，未再发送登录请求。

发现并修复了空播放摘要中 `current=null` 的客户端解析错误；为此增加空轮次恢复及筛选回归。普通开发服务也已重建，8 个原格式样本保留，目录 ID 查询可用，测试控制路由在生产镜像中为 404。

已检查实际模拟器画面：[真实缩略图列表](integration-evidence/i1-library.png)、[目录断开反馈](integration-evidence/i1-roots.png)。本阶段未代替 I2–I6 或真实 NAS/手机验收。

## I2：授权播放、手势、轮次与资源边界（完成）

实现与修复已推送 `5b47e82`、`3cb9907`。Android 16 模拟器完整 4 段网络流程及独立进程重开流程全部通过，见 [完整输出](integration-evidence/i2-android.txt)、[28 项单元/界面回归](integration-evidence/i2-unit.txt) 和 [结果、样本及物理重启事件](integration-evidence/i2-summary.json)。原有演示手势与控件回归另记录于 [模拟器输出](integration-evidence/i2-demo-regression.txt)。

网络播放器接入真实授权流；原有纵向跟手分页、短拖回弹、前后回看、横向拖进度、长按临时倍速和横屏亮度/音量手势继续沿用。默认最多初始化当前及前后各一条，设置中可关闭相邻准备。交接串行等待其他实例暂停并静音，过期初始化不启动旧条目；离开浏览、换范围、会话失效和网络播放进入后台释放旧实例。前台恢复保留常规倍速、保持暂停，横屏页面跟随新实例。

模拟器中的真实流程已覆盖 25 条目录 + 双标签交集 + 竖版 MP4 候选，7 次前后滑动与服务端随机顺序/全局位置核对、重新随机及切换顺序，慢初始化时换片、关闭相邻准备后仅 1 个播放器、后台长按取消、实际横屏和亮度/音量恢复。持续检查最多 3 个已注册播放器，最多 1 个处于播放且音量大于零的状态；延迟原生暂停的单元测试另验证新音频必须等待旧暂停确认。

120 秒生成样本在限速响应中从未缓冲位置拖动后，实际发起带鉴权的 Range GET，返回 206 并继续解码。真实停止测试容器约 21 秒后，页面提示可重试；恢复后同一轮次、条目和全局位置保持不变。把当前源文件移出挂载范围后，客户端通过 HEAD 识别不可用、读取服务端轮次、跳到下一条并解释原因。格式错误或断网保留重试和上下滑动能力。

单条范围向上滑动会持久化耗尽状态，继续循环最后一条，开始新一轮需明确操作。强制停止 Android 进程后重新启动，恢复同一轮次、非零全局位置、深层目录及加密凭据，不重新登录；服务撤销凭据后，真实播放器释放、保存的访问凭据清理并回到连接页。

回归中修复了单条列表不能触发边缘滑动、缓冲被当作用户暂停、迟到选择暂停新条目、相邻准备回收当前初始化实例，以及播放失败后页面仍引用已释放实例的问题。当前页面单独保存播放意图；初始化和暂时暂停的当前实例也受保护；失败先移除页面引用再释放。GET/HEAD 传输中断最多重试一次，总超时不变，写入由各调用方持有请求标识。对这些行为增加了延迟原生确认、原生缓冲事件及真实截断 HTTP 响应的回归。

### 格式实测条件

Android 16 API 36 x86_64 模拟器、软件渲染，WSL Docker 直传原文件，无转码。以下 8 个生成样本均约 1 秒，不能据此承诺大码率、长视频或实际手机兼容性；短样本只记录实际拖动结果，未缓冲 Range 另用上述 120 秒样本验证。

| 样本 | 视频 / 音频编码 | 解码画面 | 显示尺寸 / 旋转 |
| --- | --- | --- | --- |
| h264.mkv | H.264 / AAC | 可播放 | 160 × 96 |
| h264.mov | H.264 / AAC | 可播放 | 160 × 96 |
| hevc.mov | HEVC（hvc1）/ AAC | 可播放 | 160 × 96 |
| mpeg4.avi | MPEG-4 / MP3 | 可播放 | 160 × 96 |
| portrait.mp4 | H.264 / AAC | 可播放 | 96 × 160 |
| prores.mov | ProRes Proxy / PCM | 不支持，显示重试提示 | 原生初始化只得到音频、尺寸为零，按无视频解码处理 |
| rotated.mov | H.264 / AAC | 可播放 | 原始 160 × 96，旋转 90° 后显示 96 × 160 |
| vp9.webm | VP9 / Opus | 可播放 | 160 × 96 |

真实收藏的 MOV 需结合其内部编码测试，不以文件扩展名判断支持范围。NAS 吞吐、手机硬解码能力和扩大预加载带来的收益留到目标设备测量；现有上限仅约束播放器数量，不承诺固定缓冲字节数。

## I3：标签、批量标记和交集筛选（完成）

单条快捷标记、标签管理和列表批量添加/移除接入真实 API。标签写入串行执行；响应丢失或读取结果失败时，重试保留同一个命令标识，成功读取权威状态后才清除。批量 ID 排序保持命令内容一致。改名保留标签 ID；删除后清理标签名称及已访问视频缓存，避免旧关联继续显示。服务端批量标签写入为原子操作，失败不展示虚假的部分成功。

Android 16 模拟器原生流程及独立进程重开流程均通过，见 [完整输出](integration-evidence/i3-android.txt)、[结果与真实重启事件](integration-evidence/i3-summary.json) 和 [实际标签页](integration-evidence/i3-tags.png)。验证包括单条三标签、列表批量添加与移除、未选择标签保留、重复名称错误保留输入、目录层级加双标签 AND 与横竖/时长/类型属性组合、空结果保持为空，以及筛选后实际播放器初始化。I2 的真实随机播放验证与这里使用同一范围契约。

测试故意在服务已提交批量写入后丢失成功响应，公开界面显示失败并可重试；请求轨迹中的命令哈希相同，关联没有重复。改名后范围仍引用原 ID；删除标签后范围和候选随权威状态更新。实际停止 Docker 约 8.5 秒并重启，再强制停止 Android 进程重开，同一轮次、筛选及标签关联仍在。全部 27 个测试视频在操作前后及 Docker 重启后的路径、大小和 SHA-256 一致。

Flutter 静态分析无问题，完整 31 项单元/界面测试通过，其中新增 3 项使用真实回环 HTTP 验证写入响应丢失、批量重试及旧缓存失效。测试控制故障只存在于隔离镜像中，不向生产服务添加控制入口。此处不代替 I4 文件操作或实际 NAS/手机验收。

## 端到端实例与复现

测试使用 `compose.client-e2e.yaml`，在 WSL 原生目录 `~/.local/share/video-viewer-e2e` 建立独立数据和媒体。Windows 端口 8761，模拟器使用 `10.0.2.2:8761`；正常开发服务继续使用 8760。固定口令和控制键仅限此可丢弃测试实例。测试控制路由位于测试镜像中，生产 runtime 镜像不包含这些路由。

初始为两个媒体目录、25 个竖版 MP4、一个横版 MP4 和一个 H.264/AAC MOV，另有嵌套及空目录。素材来自仓库已注明来源的公开视频和 FFmpeg 生成样本。测试使用专用加密存储命名空间，不覆盖普通 App 的已保存连接。

在仓库根目录执行（模拟器须已启动）：

```powershell
python scripts/run-client-connection-test.py
python scripts/run-client-connection-test.py --playback
python scripts/run-client-connection-test.py --tags
```

本机如未配置 `python`，可使用已安装的 Python 可执行文件。脚本使用 `~/develop/flutter` 和 `~/develop/android-sdk`，适配当前开发环境。它先调用 `prepare-client-e2e.sh --reset`，只清理固定测试实例的数据及素材；不操作主服务目录或个人收藏。测试运行时会真实停止并重启名为 `video-viewer-client-e2e-server-1` 的容器，并强制关闭 Android App，再用另一进程验证凭据及深层目录恢复。两次运行必须保留 `--no-uninstall`：当前 Flutter 的集成测试默认在结束时卸载 App，会清空加密存储，不能用于验证普通重开。日志、脱敏请求轨迹和模拟器截图写入被 Git 忽略的 `tmp/client-e2e`，审核后选择需要的证据纳入文档。

模拟器使用软件渲染，因此这里的耗时不能用作 NAS、手机解码或网络性能结论。
