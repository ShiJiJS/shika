# 0.1.4：批量永久删除、外部删除同步与悬浮提示

2026-10-17 用户反馈：回收站永久删除 160 个视频耗时很久；希望同步 NAS 外部删除并可清理失效记录；查询文件操作结果锁住所有按钮；顶部提示仍挤占视频面积。

## 原因与修改

只读检查实际 NAS 任务：160 条全部成功，耗时 281.7 秒，涉及 22,066,810,241 字节。旧版永久删除前仍逐条重读全文计算 SHA-256，因此成本随视频总容量增长。

新版对设备号、inode、大小、mtime、ctime 与已索引记录完全一致的文件使用快速删除：在打开的文件描述符下复核来源，通过受控暂存位置认领，再次检查 inode/大小/mtime，持久化清除阶段，按当前完整属性签名 unlink。自己的 rename 会改变 ctime，后续 unlink 仍检查认领后的 ctime。这个路径不重读视频全文；同路径替换、属性变化、已有中间文件或崩溃恢复仍走内容核验/拒绝流程。该策略信任未变化文件的索引校验结果，不声称每次删除都重新验证全部字节。

批量永久删除跟恢复一样在后台处理，仅禁用冲突的回收站控件；可继续浏览和切换页面。进度保存在服务端任务中。

“查询结果”不再使用全局 busy，也不再等最长 10 分钟的轮询：查询一次当前任务状态，未结束则保留回执，用户继续使用 App。已不存在的历史任务只清除本地待确认提示，不重新发送旧删除命令。

删除/撤销提示改成内容区域顶部的悬浮层，不改变视频区域尺寸。8 秒自动消失、下一次删除替换上一条；“本轮已看完”使用同一悬浮层，3 秒消失，保留开始新一轮入口。

## NAS 外部删除

在 NAS 删除文件或文件夹后，进入 **设置 → 媒体目录 → 同步外部变更**。扫描完整成功后，对应记录转为缺失并从普通库及播放候选中排除；先保留标签，方便找回同一文件。

需要丢弃这些关联时，点击 **清除失效记录** 并确认。新增 `POST /api/v1/videos/forget-missing`，需要授权、请求 ID 和 `confirmed: true`：

- 只清理已确认缺失的元数据及标签关联；不调用 unlink、rename 或复制，不触碰真实视频。
- 活跃扫描期间拒绝清理，避免打断外部改名/移动后的身份匹配。
- 未映射、离线、未完成首次扫描的根目录跳过；重新出现的路径也跳过，应该重新扫描。
- 清理前后复核根目录身份，处理中掉盘则回滚。
- 用不可见的删除记录保留历史任务/轮次引用，旧操作不会因清理而再次执行；找回同一文件将重新入库，不自动恢复已清除标签。
- 只提供手动入口，部署时不替用户执行清理。

## 验证

- 服务端公开 API 用生成文件验证批量永久删除不调用全文哈希；同大小且恢复原 mtime 的内容修改仍被拒绝并保留文件。
- 外部删除整目录 → 扫描为缺失 → 确认清除 → 再放回时为新身份、无旧标签；原有其他文件保持不变。另验证离线根目录、返回文件跳过及重复请求幂等。
- 旧版物理回收记录与 SIGKILL 后永久删除恢复继续通过专项回归。
- Flutter 组件测试比较提示出现前后视频区域矩形完全相同；“本轮已看完”3 秒消失，删除提示8秒消失；阻塞查询响应时仍能进入设置。
- 原生 Android 模拟器公开 API 完整流程 56 秒通过，包含后台永久删除、外部移走文件后同步/清理、丢失提交响应后查询且仍可导航。清理前后测试媒体路径/大小/SHA-256 均一致。
