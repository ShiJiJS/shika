# 0.1.3：逻辑回收站与非阻塞浏览

2026-10-17 用户明确修正：回收站只记录标记，不搬动视频。此约定取代旧版物理移入回收目录的实现和旧验收记录中的对应描述。

## 行为

- 加入回收站：修改服务端数据库状态，路径、内容、inode、mtime 和 ctime 不变；播放和普通视频库排除已标记条目。
- 恢复和撤销：取消标记，保留视频 ID、路径、标签；批量恢复在一个数据库事务内完成，不逐个读取或校验原视频，也不需要并发搬运。
- 永久删除：仍需明确确认，执行前验证受控路径、文件身份和内容；拒绝删除外部替换的文件。
- 扫描识别仍在原位置的已标记视频，不重新入库、不重复探测。SQLite 数据目录、备份及容器重建继续保存这些标记。
- 不改变数据库表结构。新版回收记录的 `trash_path == original_path` 表示原地标记；旧版不同路径记录及未完成的物理操作意图继续按原安全流程处理。旧记录恢复可能仍需搬回原位置，不能仅改标记假装恢复。
- 管理备份保留逻辑标记及目录映射，不能因为原路径仍有文件就取消标记；备份本身不移动或删除媒体。

## 客户端

`BrowsingSession` 将当前画面与网络位置回执分开：滑动立即选中新条目，后台串行同步并合并过时的位置请求；播放器初始化或缓冲不禁用 PageView 滚动。旧回执不能拉回用户已经滑到的页面。

通过已有轮次 entries 接口每批预取 48 条元数据，围绕可见位置保存有限窗口；提前预热后续缩略图。缩略图未到时显示灰色，加载和失败均允许滑动。视频解码器仍最多三个，不把元数据预取当成同时播放 48 个视频。

删除立即从可见列表移开并选择下一条，后台复用原幂等回执机制。连续点击可排队；已知失败恢复可见条目，未知结果保留待查询回执，不误报成功。App 重启不擅自重放未确认的文件命令。

删除提示放在顶栏下方，8 秒自动消失，下一次点击删除立即替换上一条。旧响应不会复活已超时的提示；撤销绑定服务端最近一次成功操作。更多菜单保留撤销入口。

回收站全选主动读取所有分页，不只选择当前已显示的 24 条。最多每请求 1000 个条目，超出时分批提交。恢复期间仅禁用冲突的回收站控件，允许离开继续浏览；不进入全局阻塞状态。

## 验证

- Flutter 64 个单元/组件测试通过；额外用始终不发出初始化完成事件的播放器测试连续滑动，用未完成的删除回执测试连续删除、顶部提示替换和超时。
- Android API 36 原生模拟器公开 API 流程通过，运行 36 秒：阻塞位置回执时连续滑动三条；阻塞第一条删除时再删除第二条；离开再返回后保持画面；顶部提示自动消失。
- 同一原生流程全选跨页的 25 个回收条目，通过一次 POST 恢复，处理期间可离开继续浏览；比较操作前后全部演示文件路径、大小和 SHA-256，均一致。
- 服务端专项覆盖逻辑标记/恢复不调用文件传输、扫描不重新导入、永久删除确认及外部替换保护、备份映射和缺失标记保留、旧版物理意图恢复与 SIGKILL 后逻辑操作恢复。
- 服务端分组回归 94 项通过（目录扫描组 13 项，其余 81 项），Ruff 与 Flutter 静态检查通过。完整同进程运行曾出现多目录扫描首次计数不足、一次副本身份判定失败；独立复测及分组均通过，尚未确认时序原因，保留在 V1 后续检查中，不宣称同进程全套稳定通过。
- 图片均来自独立生成的测试媒体，不含个人 NAS 内容：[顶部提示](integration-evidence/nonblocking-delete.png)、[全选及后台恢复](integration-evidence/trash-select-all.png)。

执行：`python scripts/run-client-connection-test.py --interactions`。测试只重置独立的 8761 服务，保持 WSL 活跃直至 Android 流程结束，避免 Windows 打包等待时虚拟机闲置退出；不会在个人 NAS 上试删视频。

真实 NAS/Find X8 的操作延迟与资源使用仍需实测；模拟器结果不能作为真实设备性能结论。旧验收记录保留作版本历史。
