# Flutter 客户端数据边界

当前阶段：D1、C1–C6 的客户端演示已获用户整体确认；S1–S6 服务端已实现，正在进行 I1–I6，逐项结果见 [联调记录](integration-validation.md)。界面以用户确认的 P2 为基线。组件通过 `LibraryRepository` 读取不可变快照和提交操作；入口选择真实网络提供方或独立演示提供方。

## 领域数据与查询

外观和播放资源偏好独立于媒体管理数据。`UiPreferences` 在客户端私有 `appearance.json` 保存暗黑选择及「准备相邻视频」开关，更多菜单与设置共享同一实例，切换主题不重建播放控制器；它不参与 NAS 数据备份。横屏设备控制通过 Android 方法通道设置当前窗口亮度和媒体音量，退出/后台恢复窗口亮度，音量保留用户调整。

- 视频以稳定 ID 关联标签和轮次；文件路径只用于显示和目录范围，不作为永久身份。可用、缺失、回收站三种状态；媒体目录不可用单独表达。
- 播放源独立于 NAS 路径，可为打包素材或由提供方返回的同源授权媒体 URL。运行时请求头不写入本地快照或普通备份；可撤销访问凭据单独放入 Android 加密存储，口令不保存。401 清理会话；普通断网保留凭据供重试。
- 目录查询只返回已配置媒体目录内的直接下级，选择范围包含子树。视频查询组合目录、标签交集、方向、时长和类型；列表另有名称搜索以及 offset/limit。空结果保持为空。
- 演示目录树来自固定视频记录，不会枚举 Windows 或 NAS 的文件系统；真实空目录和层级身份由服务端返回。

## 操作语义

| 能力 | 输入和结果 |
| --- | --- |
| 连接 | 地址、端口、口令；成功保存连接状态，错误保留输入。演示口令为 `demo`，不发送网络请求、不保存口令。 |
| 筛选与播放模式 | 保存组合范围和随机/顺序模式，同时建立新轮次；顺序按目录和文件名。重开恢复轮次及位置，不恢复单视频时间进度。 |
| 轮次 | 候选 ID 顺序和当前位置持久化，向前不重复、允许回看；耗尽明确提示。扫描新增留到下一轮，不静默重新随机。 |
| 标签 | 平铺标签增改删、单条精确编辑、批量追加/移除；操作关联集合，不能覆盖未指定的其他标签或移动文件。 |
| 删除与撤销 | 删除带请求 ID；重复请求不重复删除，成功后才切下一条。撤销明确绑定删除操作 ID，恢复原轮次、位置和标签；旧撤销不能误撤新的删除。 |
| 回收站 | 恢复逐项返回冲突原因，不覆盖同名文件；永久删除须经界面确认，只作用于指定回收站条目，重复操作不扩大范围。 |
| 外部变化 | 演示刷新可返回稳定 ID 的改名/移动、缺失找回、同路径替换和重复副本；无法确认身份时保留旧记录，新记录不继承旧标签。真实内容指纹由服务端实现。 |
| 备份恢复 | 有格式版本和完整性校验；先预览目录映射、确认替换，保存恢复前快照后提交。失败保留现有数据，不执行历史删除或物理文件移动。 |

演示写操作串行处理，先完成保存再发布新快照；失败不改变可见数据。加载不清空已有对象，错误保留在相关表单或页面。真实 API 后续需保留相同可观察行为，并补足服务任务、幂等键、逐项结果及重连后的状态核对。

## 真实网络适配要求（2026-10-16 已确认）

服务端采用 [已确认技术栈](server-plan.md)，通过公开 API 接入客户端。`LibraryRepository.loadVideos`、`loadFolders`、`loadTrash` 和 `loadMissing` 是异步公开读取边界；网络提供方的同步快照只包含已访问分页及有限播放窗口，不能用作完整媒体库。标签以稳定 ID 保存，界面通过名称映射显示；服务端计数不从局部缓存推断。`exportBackupFile` 和 `inspectBackupFile` 已演进为异步传输边界，对应真实恢复流程继续由 I6 验证。演示提供方为这些方法提供兼容实现。

- I1 按服务端的稳定目录/视频标识和分页加载，标签在 S3/I3 接入稳定标识；界面处理初次加载、刷新、空结果、失败和重试。切换目录或筛选后，旧请求的迟到结果不能覆盖当前范围，不要求启动时加载全库视频。
- 标签写操作重试返回原操作结果，客户端随后刷新权威标签列表及相关分页；名称映射以稳定标签 ID 关联，避免把历史结果当作当前完整状态。
- I6 异步导出真实备份文件、上传所选文件、展示服务端校验与目录映射结果，并跟踪恢复任务。断线后按任务标识核对结果，失败不显示成功，重连不重复提交已接受的恢复；演示备份格式与正式备份格式明确区分。
- I2 沿用现有手势和控件交互，验证真实网络下的跟手切换、横向拖进度、长按临时 2 倍速和取消恢复。缓冲或失败时保留当前页面，只有当前视频发声，已初始化的相邻播放器保持静音并及时释放。
- 相邻准备与预加载范围有限且可停用；切换范围、删除、凭据失效和进入后台时清理过期请求。预加载不改变轮次位置或扩大筛选范围。更大的缓存/自适应预取仍属 [待实测优化](backlog.md#nas-能力与短视频预加载优化)。
- 暗黑模式、控件显隐和设备亮度/音量继续由客户端负责；联网后的回归同时验证它们，服务端不保存窗口或设备状态。

### I2 播放资源边界

一个 `LibraryHome` 共享一个 `PlaybackSession`，最多持有 3 个原生播放器：当前条目及前后各一条。设置中关闭相邻准备后只初始化当前条目。交接串行等待其他播放器暂停和静音后才播放当前条目，迟到的初始化必须再次校验页面和选择版本；准备相邻视频不提交服务端位置。这里限制的是播放器数量，不是固定字节缓存；播放器内部缓冲由 Android 媒体组件管理。

当前正在初始化或暂时暂停的播放器也受到名额保护；准备相邻视频不能回收它。失败时先清除页面引用，再释放实例和查询服务状态；已失效的选择请求不暂停新的当前条目。

页面单独保存用户的播放/暂停选择，不用原生解码器在缓冲、循环交接时短暂变化的 `isPlaying` 代替用户意图。因此缓冲时仍能暂停、拖动后按原意图恢复、长按临时加速；用户明确暂停时长按不开始播放。生命周期由页面统一处理，禁用播放器插件的独立自动恢复，避免两套逻辑重复启动旧实例。

离开浏览、切换范围或凭据失效会释放旧实例；网络视频进入后台也释放实例，前台重新建立并保持暂停，保留常规倍速，不带回长按的临时倍速。横屏页面跟随重新建立的播放器。播放失败以带鉴权的限时 HEAD 请求区分会话过期、文件不可用和连接问题；文件不可用后读取服务端权威轮次，不擅自重新随机。单个文件不支持解码时可重试或继续上下滑动。

新轮次提交丢失响应时，同一实例内重试复用请求 ID；轮次位置来自服务端，播放摘要只是相邻窗口，界面数量使用全局位置与总数。耗尽也向服务端持久化完成状态。断网重试和重开恢复轮次及条目位置，不恢复单视频时间进度。

GET/HEAD 遇到传输中断时最多自动重试一次，两次尝试共用原始总超时，取消和会话关闭仍立即生效；结构化 HTTP 错误不自动重试。写入不由传输层重放，由轮次、标签或文件操作调用方持有对应请求标识并核对结果。

### I4 文件操作与结果核对

回收站通过 `loadTrash` 异步分页读取，每页 24 条；视频 ID 与服务端回收站条目 ID 分开保存。恢复和永久删除只提交已读取并明确选中的条目，不从已访问视频缓存推断完整回收站。换页离开、连接失效及新读取取消旧请求，迟到结果不能修改当前列表。

真实文件写入前先把命令标识、内容和少量显示名称保存到 Android 加密存储；作用域同时包含服务地址与实例 ID，不保存口令或媒体内容。响应未确认时保留该记录，相同操作重试复用原命令；其他文件操作先核对旧结果。已返回任务 ID 时按任务查询；提交响应丢失时使用只读 `GET /api/v1/file-requests/{request_id}` 查询。App 重开只恢复待确认提示，由“查询结果”读取状态，不自动重放删除。原服务已不认识该请求时不补执行，提示核对后重新确认。

只有任务结果和权威媒体状态读回后才显示操作完成。部分成功逐项说明失败，最近删除记录只包含成功子集；撤销按钮绑定真实服务端操作 ID，而不是客户端请求 ID。“更多”中也可撤销已保存的最近删除，服务端继续校验是否仍是最新可撤销操作。失败、冲突及处理中均不显示全部成功；恢复不覆盖同名文件，永久删除仍须界面明确确认。

### I5 扫描与外部文件状态

缺失记录从真实 API 单独分页读取，在媒体目录页显示路径与标签名称。整个媒体目录不可访问单独表示，不把所有视频推断成缺失。扫描结束后重新读取服务端权威状态并清理旧路径缓存；同一文件身份、替换内容和重复副本的判定由服务端负责，客户端不按文件名继承标签，也不把文件移回原路径。

扫描阶段及计数通过独立的状态通知显示，进度轮询不反复重读媒体列表。同一客户端的并发刷新共享正在查询的任务；等待超过两分钟时说明服务仍可能处理中，后续刷新继续查询。任务失败、中断或部分目录不可用先核对已发布状态，再显示说明，不提示全部成功。新增媒体目录由服务端分配 ID，演示提供方也会生成自己的本地 ID，界面不预先构造网络实体 ID。

### I6 真实备份与待确认恢复

`ServerBackups` 管理同一服务的导出、校验与恢复任务。少量命令标识、任务 ID 和文件摘要独立保存于 Android 加密存储，作用域同时包括地址及实例 ID；备份正文不放入凭据存储。上传和下载上限均为 32 MiB，传输和任务等待分别有两分钟边界。下载字节先与服务端任务中的 SHA-256 核对，再交给文件保存界面；取消保存不报告文件已保存。选择文件后校验正式服务格式、版本及服务端完整性结果，演示文件不能混入正式恢复。

映射表显示原目录、建议目标及视频/标签/回收站数量。确认前可取消，完整替换必须勾选确认。提交前先保存已确认命令；恢复响应或任务读取失败后，界面保留待确认提示。重开只恢复提示，点击查询后按已知任务 ID 或只读 `GET /api/v1/backup-requests/restore/{request_id}` 读取原结果，不重新提交恢复。不认识的旧命令也不补执行，需重新选择文件并确认。

处理及待确认期间禁用冲突写入，仍允许返回设置、只读导航、查询和重新连接；恢复面板处理期间不能用返回、拖动、背景或关闭按钮取消已提交任务。只有任务完成且权威状态读回后才报告成功，同时清理本机旧删除/撤销记录和过期缓存。失败和中断不误报完成，恢复前快照与历史操作不重放继续由服务端保障。外观偏好和设备状态不由 NAS 管理数据恢复覆盖。

## 实现与验证边界

演示存储使用 App 私有目录中的 JSON 文件，先写临时文件再替换，并保留上一份与恢复前快照；不是 NAS 数据库。Flutter 调试工程的 `--dart-define=DEMO_SCENARIO=...` 和设置中的开发工具提供可重复场景。注入 `LibraryRepository` 与 `BackupFiles` 是测试及后续适配的边界，不通过组件内部方法的调用次数验收。

本阶段真实验证的是 Android 播放器、打包媒体、Flutter 手势/页面和本地演示数据保存。媒体目录扫描、回收站移动、文件身份识别、备份数据库事务、认证和流媒体服务仍由后续服务端与联调任务完成。按标签调整文件夹不在第一阶段。
