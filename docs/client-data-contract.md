# Flutter 客户端数据边界

当前阶段：D1、C1–C6 的客户端演示已获用户整体确认；S1–S6 服务端已实现，正在进行 I1–I6，逐项结果见 [联调记录](integration-validation.md)。界面以用户确认的 P2 为基线。组件通过 `LibraryRepository` 读取不可变快照和提交操作；入口选择真实网络提供方或独立演示提供方。

## 领域数据与查询

外观和播放资源偏好独立于媒体管理数据。`UiPreferences` 在客户端私有 `appearance.json` 保存暗黑选择及「准备相邻视频」开关，更多菜单与设置共享同一实例，切换主题不重建播放控制器；它不参与 NAS 数据备份。横屏设备控制通过 Android 方法通道设置当前窗口亮度和媒体音量，退出/后台恢复窗口亮度，音量保留用户调整。

- 视频以稳定 ID 关联标签和轮次；文件路径只用于显示和目录范围，不作为永久身份。可用、缺失、回收站三种状态；媒体目录不可用单独表达。
- 播放源独立于 NAS 路径，可为打包素材或由提供方返回的同源授权媒体 URL。运行时请求头不写入本地快照或普通备份；可撤销访问凭据单独放入 Android 加密存储，口令不保存。401 清理会话；普通断网保留凭据供重试。
- 目录查询只返回已配置媒体目录内的直接下级，选择范围包含子树。视频查询组合目录、标签交集、方向、时长和类型；列表另有名称搜索以及 offset/limit。空结果保持为空。
- 演示目录树来自固定视频记录，不会枚举 Windows 或 NAS 的文件系统；真实空目录和层级身份由服务端返回。

## 操作语义

LF4 新工作区的列表查询草稿与播放范围分离，固定预览从当前来源创建。批选“全选匹配项”调用声明 `catalog_selection` 的鉴权 `GET /api/v1/videos/selection` 或 `/api/v1/packs/selection`；沿用各自完整筛选，在一次数据库读取中返回 `{kind, ids, total}`，不创建播放、阅读或最近记录。视频同时保留来源和排序；图包使用独立标签和阅读状态。客户端只接受类型正确、ID唯一且数量完整的结果；超过五万项服务端明确拒绝并要求缩小范围，不截断后称全选。旧服务可继续手工选择，跨页全选明确提示升级。

完整选择是读入时的ID快照，可单项排除。新查询、来源/类型退出、手工操作及连接变更取消迟到的全选；取消和普通错误保留原选择。批量标签按稳定顺序每1000项提交，继续使用幂等回执，每批核对原连接和恢复门禁；部分或不确定结果保留选择并显示已确认进度。列表批选即使只剩一项也按追加处理，卡片单项编辑保持精确替换。

声明 `pack_tag_names` 时，图包摘要的 `tag_ids` 与 `tag_names` 来自同一读取，客户端要求名称完整对应这些ID。编辑/筛选原选择通过鉴权 `GET /api/v1/pack-tags/resolve?tag_ids=…` 精确读取，返回独立的 `kind=pack`、`items` 和 `missing_ids`；每次最多256项，需要时在同一连接下分批，不遍历整个标签库或借用视频标签名。名称与标签分页有独立取消范围，恢复发布前也取消旧名称请求。

名称未确认或原选择已被删除时保留草稿并提示解决后保存；较早响应不能覆盖后来的名称，换连接清除旧名称并禁止沿用旧ID保存。成功编辑的ID/名称会更新仍打开的详情，再次进入编辑保留新选择；卡片由服务端读回。旧服务可以通过已读标签页确认名称，未确认项不会静默保存。

| 能力 | 输入和结果 |
| --- | --- |
| 连接 | 地址、端口、口令；成功保存连接状态，错误保留输入。演示口令为 `demo`，不发送网络请求、不保存口令。 |
| 筛选与播放模式 | 保存组合范围和随机/顺序模式，同时建立新轮次；顺序按目录和文件名。重开恢复轮次及位置，不恢复单视频时间进度。 |
| 轮次 | 候选 ID 顺序和当前位置持久化，向前不重复、允许回看；耗尽明确提示。扫描新增留到下一轮，不静默重新随机。 |
| 标签 | 平铺标签增改删、单条精确编辑、批量追加/移除；操作关联集合，不能覆盖未指定的其他标签或移动文件。 |
| 删除与撤销 | 删除带请求 ID；重复请求不重复删除，立即切下一条，后台提交回收站标记，只有权威回执成功才提示完成；加载和位置同步不锁定滑动。撤销明确绑定删除操作 ID，恢复原轮次、位置和标签；旧撤销不能误撤新的删除。 |
| 回收站 | 全选包含未加载页；批量恢复只取消标记，不移动原文件；旧版物理回收记录仍按不覆盖规则恢复；永久删除须经界面确认，只作用于指定回收站条目，重复操作不扩大范围。 |
| 外部变化 | 演示刷新可返回稳定 ID 的改名/移动、缺失找回、同路径替换和重复副本；无法确认身份时保留旧记录，新记录不继承旧标签。真实内容指纹由服务端实现。 |
| 备份恢复 | 有格式版本和完整性校验；先预览目录映射、确认替换，保存恢复前快照后提交。失败保留现有数据，不执行历史删除或物理文件移动。 |

演示写操作串行处理，先完成保存再发布新快照；失败不改变可见数据。加载不清空已有对象，错误保留在相关表单或页面。真实 API 后续需保留相同可观察行为，并补足服务任务、幂等键、逐项结果及重连后的状态核对。

## 真实网络适配要求（2026-10-16 已确认）

服务端采用 [已确认技术栈](server-plan.md)，通过公开 API 接入客户端。`LibraryRepository.loadVideos`、`loadFolders`、`loadTrash` 和 `loadMissing` 是异步公开读取边界；网络提供方的同步快照只包含已访问分页及有限播放窗口，不能用作完整媒体库。标签以稳定 ID 保存，界面通过名称映射显示；服务端计数不从局部缓存推断。`exportBackupFile` 和 `inspectBackupFile` 已演进为异步传输边界，对应真实恢复流程继续由 I6 验证。演示提供方为这些方法提供兼容实现。

- I1 按服务端的稳定目录/视频标识和分页加载，标签在 S3/I3 接入稳定标识；界面处理初次加载、刷新、空结果、失败和重试。切换目录或筛选后，旧请求的迟到结果不能覆盖当前范围，不要求启动时加载全库视频。
- 标签写操作重试返回原操作结果，客户端随后刷新权威标签列表及相关分页；名称映射以稳定标签 ID 关联，避免把历史结果当作当前完整状态。
- I6 异步导出真实备份文件、上传所选文件、展示服务端校验与目录映射结果，并跟踪恢复任务。断线后按任务标识核对结果，失败不显示成功，重连不重复提交已接受的恢复；演示备份格式与正式备份格式明确区分。
- I2 沿用现有手势和控件交互，验证真实网络下的跟手切换、横向拖进度、长按临时 2 倍速和取消恢复。缓冲或失败时保留当前页面，只有当前视频发声，已初始化的相邻播放器保持静音并及时释放。
- 元数据按每批 48 条预取、预热当前及附近共 9 条缩略图；视频解码器相邻准备范围仍有限且可停用；切换范围、删除、凭据失效和进入后台时清理过期请求。预加载不改变轮次位置或扩大筛选范围。更大的缓存/自适应预取仍属 [待实测优化](backlog.md#nas-能力与短视频预加载优化)。
- 暗黑模式、控件显隐和设备亮度/音量继续由客户端负责；联网后的回归同时验证它们，服务端不保存窗口或设备状态。

### I2 播放资源边界

一个 `LibraryHome` 共享一个 `PlaybackSession`，最多持有 3 个原生播放器：当前条目及前后各一条。设置中关闭相邻准备后只初始化当前条目。交接串行等待其他播放器暂停和静音后才播放当前条目，迟到的初始化必须再次校验页面和选择版本；准备相邻视频不提交服务端位置。这里限制的是播放器数量，不是固定字节缓存；播放器内部缓冲由 Android 媒体组件管理。

当前正在初始化或暂时暂停的播放器也受到名额保护；准备相邻视频不能回收它。失败时先清除页面引用，再释放实例和查询服务状态；已失效的选择请求不暂停新的当前条目。

页面单独保存用户的播放/暂停选择，不用原生解码器在缓冲、循环交接时短暂变化的 `isPlaying` 代替用户意图。因此缓冲时仍能暂停、拖动后按原意图恢复、长按临时加速；用户明确暂停时长按不开始播放。生命周期由页面统一处理，禁用播放器插件的独立自动恢复，避免两套逻辑重复启动旧实例。

离开浏览、切换范围或凭据失效会释放旧实例；网络视频进入后台也释放实例，前台重新建立并保持暂停，保留常规倍速，不带回长按的临时倍速。横屏页面跟随重新建立的播放器。播放失败以带鉴权的限时 HEAD 请求区分会话过期、文件不可用和连接问题；文件不可用后读取服务端权威轮次，不擅自重新随机。单个文件不支持解码时可重试或继续上下滑动。

新轮次提交丢失响应时，同一实例内重试复用请求 ID；轮次位置来自服务端，播放摘要只是相邻窗口，界面数量使用全局位置与总数。耗尽也向服务端持久化完成状态。断网重试和重开恢复轮次及条目位置，不恢复单视频时间进度。

GET/HEAD 遇到传输中断时最多自动重试一次，两次尝试共用原始总超时，取消和会话关闭仍立即生效；结构化 HTTP 错误不自动重试。写入不由传输层重放，由轮次、标签或文件操作调用方持有对应请求标识并核对结果。

### I4 文件操作与结果核对

回收站通过 `loadTrash` 异步分页读取，每页 24 条；视频 ID 与服务端回收站条目 ID 分开保存。恢复和永久删除只提交已读取并明确选中的条目，不从已访问视频缓存推断完整回收站。换页离开、连接失效及新读取取消旧请求，迟到结果不能修改当前列表。

真实文件写入前先把命令标识、内容和少量显示名称保存到 Android 加密存储；作用域同时包含服务地址与实例 ID，不保存口令或媒体内容。响应未确认时保留该记录，相同操作重试复用原命令；其他文件操作先核对旧结果。已返回任务 ID 时按任务查询；提交响应丢失时使用只读 `GET /api/v1/file-requests/{request_id}` 查询。App 重开只恢复待确认提示，由“查询结果”读取状态，不自动重放删除。原服务已不认识该请求时不补执行，提示核对后重新确认。

只有任务结果和权威媒体状态读回后才显示操作完成。部分成功逐项说明失败，最近删除记录只包含成功子集；撤销按钮绑定真实服务端操作 ID，而不是客户端请求 ID。“更多”中也可撤销已保存的最近删除，服务端继续校验是否仍是最新可撤销操作。失败、冲突及处理中均不显示全部成功；恢复不覆盖同名文件，永久删除仍须界面明确确认。

### I5 扫描与外部文件状态

缺失记录从真实 API 单独分页读取，在媒体目录页显示路径与标签名称。整个媒体目录不可访问单独表示，不把所有视频推断成缺失。扫描结束后重新读取服务端权威状态并清理旧路径缓存；同一文件身份、替换内容和重复副本的判定由服务端负责，客户端不按文件名继承标签，也不把文件移回原路径。

扫描阶段及计数通过独立的状态通知显示，进度轮询不反复重读媒体列表。界面刷新只提交/合并扫描任务，随即释放导航，后台自动查询进度，无需等在刷新按钮上。任务失败、中断或部分目录不可用保留原索引并显示说明，不提示全部成功。新增媒体目录由服务端分配 ID，演示提供方也会生成自己的本地 ID，界面不预先构造网络实体 ID。

`GET /api/v1/library-state` 是建库准备与扫描进度的权威来源：`ready`、`scanning`、任务 ID/状态/阶段、`progress` 的发现/处理文件数和字节数、失败/暂缓计数，以及各目录的准备状态、最近完成时间和当前扫描情况。扫描线程按约一秒节流持久保存进度；客户端建库/扫描时约两秒查询，闲置时约十秒查询。断网保留最后一次状态并标明进度暂未同步；连接替换、失效、销毁或恢复期间不接受旧查询结果。

首次连接到未准备的库时先锁定播放器，列表以“建库中”标明暂时数量。所有已映射目录完成扫描及身份核对后才就绪；`last_scan` 不在身份核对前提前写入。播放摘要在锁定时返回 `library_locked=true`、空窗口和零播放数量，原文件流返回 `409 library_preparing`。缩略图与目录/标签管理仍可读取。准备完成后自动读回完整轮次，避免早期几百条候选被当作全库；完整的恢复轮次不重排。普通增量扫描不重新锁定已准备的库，也不静默重排当前轮次。

视频库接近底部自动请求下一页，整行小型旋转指示器显示加载状态；同页不重复请求，失败保留卡片和位置，重试使用原偏移。新筛选取消过期请求。进度通知不会触发列表重载。播放初始化允许前台 30 秒、相邻准备 20 秒；仅对超时或临时来源/连接错误做一次释放旧播放器后的延迟重试，不对已切走页面启动播放，最终失败仍可手动重试或滑走。

0.1.2 将缩略图作为可再生成的可选缓存：有效元数据与内容校验通过后，即使取图超时仍可入库，`thumbnail_url=null` 显示现有占位图，不把缓存异常写入阻止播放的 `Video.error`。扫描任务分别保存 `failed` 和 `thumbnail_failed`，准备接口增加 `failure_reasons`、`warning_reasons` 汇总；客户端分别显示视频信息读取失败、具体原因和缩略图待补充，不从历史通用错误推测细分原因。未变化文件补图复用 hash 与元数据，仍核对签名与操作代次。详细问题见 [4K HEVC 修正](thumbnail-timeout-validation.md)。

### I6 真实备份与待确认恢复

`ServerBackups` 管理同一服务的导出、校验与恢复任务。少量命令标识、任务 ID 和文件摘要独立保存于 Android 加密存储，作用域同时包括地址及实例 ID；备份正文不放入凭据存储。上传和下载上限均为 32 MiB，传输和任务等待分别有两分钟边界。下载字节先与服务端任务中的 SHA-256 核对，再交给文件保存界面；取消保存不报告文件已保存。选择文件后校验正式服务格式、版本及服务端完整性结果，演示文件不能混入正式恢复。

映射表显示原目录、建议目标及视频/标签/回收站数量。确认前可取消，完整替换必须勾选确认。提交前先保存已确认命令；恢复响应或任务读取失败后，界面保留待确认提示。重开只恢复提示，点击查询后按已知任务 ID 或只读 `GET /api/v1/backup-requests/restore/{request_id}` 读取原结果，不重新提交恢复。不认识的旧命令也不补执行，需重新选择文件并确认。

处理及待确认期间禁用冲突写入，仍允许返回设置、只读导航、查询和重新连接；恢复面板处理期间不能用返回、拖动、背景或关闭按钮取消已提交任务。只有任务完成且权威状态读回后才报告成功，同时清理本机旧删除/撤销记录和过期缓存。失败和中断不误报完成，恢复前快照与历史操作不重放继续由服务端保障。外观偏好和设备状态不由 NAS 管理数据恢复覆盖。

## 实现与验证边界

演示存储使用 App 私有目录中的 JSON 文件，先写临时文件再替换，并保留上一份与恢复前快照；不是 NAS 数据库。Flutter 调试工程的 `--dart-define=DEMO_SCENARIO=...` 和设置中的开发工具提供可重复场景。注入 `LibraryRepository` 与 `BackupFiles` 是测试及后续适配的边界，不通过组件内部方法的调用次数验收。

本阶段真实验证的是 Android 播放器、打包媒体、Flutter 手势/页面和本地演示数据保存。媒体目录扫描、回收站移动、文件身份识别、备份数据库事务、认证和流媒体服务仍由后续服务端与联调任务完成。按标签调整文件夹不在第一阶段。


## 0.1.4 行为修正

文件结果查询只读一次状态，不进入全局 busy；不存在的旧任务清除本地回执但不重放。永久删除在后台进行，未变化的文件复用索引校验、按描述符及属性签名删除；变化或恢复中的文件继续核验。删除/撤销提示悬浮在视频顶部，不改变布局，本轮结束提示 3 秒消失。媒体目录新增同步外部变更及确认后清除失效元数据，详见 [验证与边界](purge-and-missing-validation.md)。

## 图包入口稳定定位（LF4）

声明 `pack_entry_anchors` 时，鉴权 `GET /api/v1/packs` 接受最多16个重复参数 `anchor_ids`，其余目录/标签交集/搜索/阅读状态/排序条件保持原查询。一次数据库读取确定总数、首个仍匹配候选的稳定排序索引和分页，响应增加可空 `anchor_index`；候选全部消失按传入offset收敛到有效末项。无匹配返回空页；目录不可用仍拒绝，不扩大范围。该读取不创建阅读会话、最近或进度。

客户端 `restorePackEntry` 要求能力与合法定位元数据，并使用独立图包读取取消范围。页控制器最多保留120项，前补/丢页由页面补偿位置；定位、刷新、前补、追加各有原意图重试，失败或当前代次意外取消保留旧窗口。显式离开/改查询/换连接使旧代次失效。跨页全选仍走独立完整ID接口，不受这个窗口上限影响。正式备份v2的全域恢复代次隔离另由LF7完成。

## 固定图包阅读（LF5）

Schema0009声明 `pack_reading_sessions`。`POST /api/v1/pack-sessions` 带request_id、scope（directory_id/search/tag_ids/read_state）、source、sort、order及可选anchor_pack_id；返回固定范围id/revision、candidate_count、available_count、cursor、finished、current、resume与previous/next。成员在服务端完整求值并固定，entries按原ordinal分页；不可用成员标明available=false，新增包或改标签不会加入/重筛范围。只有明确position更新或实际打开回退候选才改变存储位置。

`resume` 返回page/page_index、offset_ratio、completed、revision、content_version、recovery_reason和preferences。页清单/图像仍走LF2鉴权与版本读取。创建会话、摘要和分页读取不写进度、偏好或最近。只有首张实际显示后调用opened，带pack_id/page_id/content_version/expected_session_revision/expected_revision/request_id；成功回执返回新进度revision及session_revision，后续写入必须使用它们。若旧当前项不可用，opened同时提交回退位置并推进会话revision，原项恢复不会自动抢回当前阅读器。

`PATCH /packs/{id}/progress` 带session_id、page_id、content_version、expected_session_revision、expected_revision、offset_ratio（0–1）、completed、request_id；只允许当前会话已实际打开的当前包。清单、会话或进度冲突先读取新状态，不能盲目用旧页/新revision覆盖。`PATCH position` 带会话expected_revision、request_id及pack_id或finish二选一；手动前后包均在固定成员内，纵向末页不自动调用。

每包preferences使用独立expected_revision和当前会话归属，values完整包含mode(horizontal/vertical)、direction(ltr/rtl)、gap、fit(contain/width)。reading-defaults使用独立全局revision。首次实际打开时保存当时默认为本包偏好；后续默认改动不覆盖已读包。偏好操作本身不写最近。

`GET /pack-reading-requests/{kind}/{request_id}` 只读查询session/position/opened/progress/preferences/defaults回执；未知返回404，没有隐式提交或激活旧会话。已完成操作复用原request_id返回回执，内容不同则409。新的入口会话替换当前阅读归属；迟到旧会话写入拒绝，旧回执只读仍可查。客户端PackReadingSession在每个异步结果和实际首帧处检查归属；原生阅读UI已接入。

`recent?kind=pack` 只含实际opened并按包去重，视频仍为默认kind=video；packs及selection支持source=recent与sort=recent，并保留完整图包过滤。Schema0009保留旧pageId/比例/完成/revision，补当前清单版本与偏好revision；扫描删页选择最近可读页，记录page_removed，实际打开确认后清除说明。原页损坏读取时返回page_unreadable。完整备份v2与跨恢复代次隔离由LF7完成。

客户端读取句柄由 `LibraryRepository.createPackReader()` 创建，绑定连接/代次/阅读元数据代次。`ReaderCommand<T>` 保留原request_id和版本，submit单次发送、receipt只读，不自动重发未知结果；范围/页/队列及写回执严格校验身份、数量、版本和媒体地址。确认恢复发布新状态前销毁旧句柄；连接对象相同也不能跨恢复代次回写。`isCurrent` 提供轻量归属检查，原生页面已在首帧、后台flush和离页处使用它；完整后台/恢复组合仍需原生验收。
