# 私人视频库第一版规格

> 最新范围：取消独立归档分类；按标签一键调整物理文件夹移出第一阶段，映射规则留待后续。当前增加快速整理模式，用于限定范围、连续查看、打标签和删除撤销，不执行目录调整。详见后续事项与当前设计基线。

状态：需求基线、P2 HTML 原型与使用演示数据的 Flutter Android 客户端均已获用户确认。2026-10-16 完成客户端整体验收与 WSL2 Docker 开发环境检查，下一项为 S1 服务端实现。NAS 服务和真实联调尚未实现。项目由 GitHub 私有仓库管理，实际验证结果另行记录。

## Problem Statement

用户在 NAS 中收藏大量横版和竖版短视频，已有自己的文件夹组织方式。现有观看方式不便于随机重看收藏、用多个标签找回内容，也不便于连续快速删除不再想看的视频。面向电影与剧集的刮削流程不符合这些个人素材的管理需求。

用户仍会通过外部工具新增、改名和移动文件，希望 App 能接受这些变化；也希望在离开 App 后，仍然能通过 NAS 的物理目录找到视频。标签等管理成果需要持久保存并能备份恢复。

## Solution

提供部署在 NAS 的 Docker 服务和 Android 优先的跨平台 App，面向个人局域网使用。App 首次输入服务地址、端口和个人口令，之后直接进入浏览。

日常使用以随机连续播放为主，同时提供缩略图列表。用户可以通过多个平铺标签和视频属性筛选，并对结果继续随机观看。当前视频播放结束后循环，一轮向前浏览不重复，退出后继续原轮次。

快速整理模式先按目录、标签交集和视频属性缩小范围，再连续查看、快捷打标签和删除：未删除的视频自然保留；删除成功后立即播放下一条，可以撤销。视频先进入回收站，由用户确认后批量永久删除。

标签负责多维筛选，修改标签不改变物理位置。首次接入保留原文件结构，接受外部文件变化。提供多个媒体目录接入、逐层范围选择、扫描刷新、缺失记录保留，以及管理数据备份恢复。

验证先配置 Android 开发环境与模拟器，以模拟器中的完整用户流程验收 App；服务端 API 集成测试补充验证真实文件操作及异常恢复。

## Implementation Decisions

### 决策状态与现有基础

本规格的设计起点是只有需求、术语和规格等文档的空项目。之后按用户授权建立了 Flutter Android 环境验证脚手架与 B 风格 HTML 原型；它们不代表视频库业务已实现。旧归档分类决策已撤销，以当前需求、术语和设计基线为准。

上述用户行为是已确认需求。以下模块、数据模型、接口契约和边界处理为本规格提出的实现设计，不表示用户已经逐项选定技术栈。优先在第一轮可运行原型中验证；不能满足已确认需求时修改方案，不静默缩减范围。

### 部署与技术选择

- 客户端暂定 Flutter，先交付 Android 开发与模拟器验证；媒体兼容方案仍需真实样本验证。其他平台保留扩展方向，不承诺同时发布。
- 服务端采用一个可容器化的应用，内部划分职责；媒体扫描、缩略图生成和文件操作使用受控后台任务，不引入微服务。
- 使用一个持久化、支持事务和一致性备份的数据库保存管理数据。具体数据库、后端语言和播放器依赖待验证，本文不预设已选定。
- 媒体目录以用户明确指定的目录挂载；管理数据、回收站管理信息、可再生缩略图与原视频分清用途。容器重建不丢失管理数据。
- 通过同一个服务入口提供认证、业务 API、缩略图和播放流。App 不直接持有 NAS 文件共享凭据，也不直接操作物理路径。
- Android 开发环境和模拟器的安装、启动、App 安装运行以及模拟器访问开发服务，是实施阶段的首个可验收成果。

### 模块边界

| 模块 | 负责的行为与公开边界 |
| --- | --- |
| App 连接与浏览 | 保存连接、列表和筛选、播放控制、随机轮次位置、批量选择、整理与撤销交互。通过服务 API 完成管理操作。 |
| 媒体目录与扫描 | 维护媒体目录可用性和可选子目录层级，扫描稳定文件，提取媒体属性，识别外部变化；不调整正常收藏的物理目录。 |
| 视频目录与标签 | 稳定视频标识、视频状态、平铺标签及关联、交集与属性筛选。 |
| 随机浏览 | 保存轮次候选集合、顺序和当前位置，支持回看、重开继续、重新随机与失效项跳过。 |
| 播放与预览 | 授权访问媒体、支持按需读取与拖进度、提供缩略图，明确返回不可播放原因。 |
| 文件操作 | 统一执行删除、恢复和永久删除，管理操作记录、冲突、重试和中断恢复。 |
| 数据维护 | 管理数据备份、备份校验、恢复、版本迁移和服务状态。 |

模块是应用内职责，不是独立部署单元。App 中的页面组合不决定后端模块拆分。

### 数据模型

| 概念 | 需要保存的信息与不变量 |
| --- | --- |
| 媒体目录 | 稳定标识、用户配置的位置、扫描状态和上次成功扫描信息。目录不可用与空目录必须区分。 |
| 视频 | 稳定标识、当前位置、可用或缺失或回收站状态、媒体属性、首次发现时间、身份识别证据。路径不作为永久身份。 |
| 标签 | 稳定标识和名称；名称去除首尾空白，空名或与现有名称完全重复的输入需明确拒绝。 |
| 视频与标签关联 | 多对多关系，同一关联不重复。操作单个标签不会覆盖其他标签。 |
| 随机轮次 | 筛选条件快照、候选视频标识及顺序、当前位置。关联稳定视频标识，不绑定易变路径。 |
| 文件操作记录 | 操作标识、请求标识、原位置、目标位置、预期文件身份、执行结果和恢复信息。 |
| 回收站记录 | 视频标识、原位置、回收位置和删除操作。保留标签关联，便于恢复。 |
| 备份描述 | 数据格式版本、必要完整性信息、目录映射和管理数据，不包含原视频副本。 |

第一版没有已整理、待决定或明确保留等逐视频状态；缺失与回收站是可用性或文件位置状态。播放不改变保留含义。

### 扫描与外部变化

- 用户配置媒体目录后定期扫描，并可发起手动刷新。相同目录的扫描合并或排队，不并发相互覆盖。
- 回收站、应用管理数据和应用自己创建的中间文件不作为普通视频重新入库。重叠媒体目录不能造成同一物理位置被重复接入。
- 对仍在写入的文件延迟处理，读取失败留下原因并可重试；不因一次探测失败丢弃已有标签。
- 每次完整扫描先判断目录可用性；只有成功完成该目录的扫描后，才依据未发现结果标记单个视频缺失。整个目录不可用时保留原有记录，播放侧显示不可访问。
- 外部移动需要有身份证据。优先收集文件属性与内容指纹；快速指纹只用于候选匹配，必要时校验完整内容。相同内容存在多个副本或证据不足时，不猜测合并标签。
- 不同位置的重复副本按独立文件记录处理，不自动去重或共享标签。同路径被替换成不同内容时，不把旧标签自动赋给新视频，旧记录按缺失保留。
- 在接入范围内重新找到且可以确认是同一文件时更新位置并保留标签。移出接入范围只能记为缺失，不能声称已经发现新位置。
- 外部移动后接受当前路径，不自动搬回、不推导额外分类。目录选择使用实际扫描到的层级。

### 标签、列表与随机浏览

- 标签筛选采用交集，并与视频属性条件组合。未选标签表示不施加标签约束；缺失、已回收和不可访问内容不进入可播放候选。
- 批量添加标签按关联集合追加，重复请求不重复创建关联；批量移除只移除明确选择的标签，改名或删除标签不改变文件。
- 列表采用分页并返回稳定视频标识，筛选结果可以用于创建随机轮次。空结果明确显示为空，不退回全库随机播放。
- 每轮保存一次候选顺序；跨 App 重开继续位置。回看不算向前重复，视频内部循环也不算轮次重复。
- 轮次创建后新增内容留到下一轮；切换筛选或主动重新随机时创建新轮次。轮次播放前重新校验视频可用性和当前筛选条件，失效项跳过。
- 本轮耗尽时显示完成并提供开始新轮次，不在用户无感知下偷偷重复。最后一条视频仍可按既定循环规则播放。
- 暂停、倍速与拖进度作用于当前播放；轮次位置的恢复不等于恢复每条视频的时间进度。
- 视频按纵向整页跟手切换，短拖回弹，落定后更新轮次位置；保存失败退回原条目。点画面暂停/继续，不显示中央播放按钮；播放中长按临时 2 倍速，松手、取消或进入后台时恢复原速度，横屏一致。
- 名称与半透明快捷标签叠在画面底部；进度默认隐藏，横向拖动画面或底部区域时出现，松手提交并闲置 3 秒收起。横屏点画面显示/隐藏控件，左上退出箭头无背景并随控件隐藏；横向拖动快进/后退，左半区竖向调窗口亮度，右半区竖向调媒体音量，退出或进入后台恢复亮度。
- 更多与设置均提供暗黑模式切换，入口状态一致，外观偏好在客户端本机保存，不进入 NAS 管理数据备份。

### 文件操作、冲突和恢复

- 所有物理文件写操作经同一个模块执行；扫描需要识别操作中间状态，避免把一次移动识别成删除加新视频。
- 同名目标存在时不覆盖，返回冲突并允许选择其他目标或重试。回收站恢复遇到原位置被占用也按同样规则处理。
- 删除表示物理移入应用管理的回收位置，成功后才报告已删除。UI 可以立即显示处理中，但失败时必须恢复可见条目并解释原因。
- App 在删除成功后切下一条并保存对应操作标识，撤销精确恢复该次操作。连续删除的上一次以成功完成的操作为准，重试不能产生重复移动。
- 回收站优先使用与源文件同一文件系统的受控位置以支持移动；跨文件系统操作必须按复制、校验、确认后移除来源的流程处理，失败时不能丢失唯一完整副本。
- 数据库事务与文件系统操作不能视为同一原子事务。持久化操作意图，记录阶段，启动时核对实际文件状态并恢复未完成操作；公开接口返回明确的处理中、成功、失败或冲突。
- 永久删除必须绑定明确的回收站条目及用户确认，逐项返回结果。文件删除与管理记录清理失败要可恢复，不能显示假成功。
- 原路径、目标路径和内容身份都在执行时验证；只允许访问已配置范围，拒绝越界路径和可逃逸的链接。备份恢复也不能隐式触发文件移动。

### 公开接口契约

不在本规格中锁定具体 URL 或实现文件布局；以下为客户端与服务端共同遵循的行为契约。

| 接口能力 | 请求内容 | 可观察结果 |
| --- | --- | --- |
| 连接验证 | 服务地址和个人口令 | 建立可撤销的访问凭据；错误口令明确拒绝。 |
| 媒体目录和扫描 | 媒体目录配置、手动刷新请求 | 扫描任务标识、运行状态、发现数量和目录异常。 |
| 视频查询 | 标签交集、属性条件和分页信息 | 视频摘要、稳定标识、缩略图及可用性；不会返回凭据。 |
| 标签管理 | 标签变更或视频集合上的关联变更 | 最新标签与关联；无歧义的批量结果。 |
| 随机轮次 | 筛选条件、轮次标识与位置更新 | 持久化顺序、当前位置、可用条目及轮次结束状态。 |
| 媒体访问 | 视频标识、授权凭据和读取范围 | 可拖进度的媒体内容或明确错误；不能借文件路径绕过授权。 |
| 删除、撤销、恢复、永久删除 | 稳定视频或操作标识、请求标识、必要确认 | 可重试且不会重复执行的操作状态及逐项结果。 |
| 备份和恢复 | 导出请求，或备份与恢复确认 | 校验结果、备份版本及任务结果；失败保留现有可用数据。 |

写操作使用请求标识实现幂等。相互冲突的同视频操作串行处理；媒体不存在、目录不可用、目标冲突、权限不足和格式不支持分别返回可解释结果。认证覆盖业务 API、缩略图、播放和备份；口令不放在播放地址、日志或普通备份中。

### 备份与恢复

- 提供手动导出和导入；自动备份频率与轮换不作为本版必要条件，留作后续设置。
- 导出一致的管理数据快照，包含标签、视频关联、媒体目录映射、回收站索引、随机轮次和必要操作记录。缩略图等可再生缓存不必备份。
- 备份说明明确：恢复的是管理数据，不会让已永久删除的视频重新出现，也不会回滚磁盘上已经完成的移动。
- 第一版按完整恢复设计，不尝试合并两套标签库。恢复前校验版本与完整性，提示将替换现有管理数据，并先保留现有数据快照。
- 恢复期间暂停扫描和文件写操作。恢复后先重新核对目录、文件和历史操作记录，不重放旧备份中的删除指令；核对完成后才恢复写操作。
- 恢复到新环境时允许重新指定目录映射，无法匹配的原文件保留为缺失。访问口令单独重新配置，避免备份传播认证信息。

### 媒体兼容与性能验证

- 先尝试原文件播放，不承诺仅凭扩展名就能播放。用真实收藏样本确认容器格式、视频编码、音频编码、旋转信息、分辨率与拖进度行为。
- 播放不支持时显示可识别原因并允许继续浏览，不擅自转码或修改原文件。是否增加服务端兼容处理，由样本结果决定，是选型验证事项，不是已确认排除项。
- 控制缩略图、扫描、内容校验和预加载的并发，避免初次接入占满 NAS；昂贵工作不阻塞快速删除等交互请求。
- 在确定样本规模、NAS 与网络条件后记录首帧、切换、筛选和删除完成延迟及资源占用，再设定可重复测量的验收阈值；本规格不虚构已经达到的性能指标。

## Testing Decisions

### 测试入口与用户选择

用户明确要求先配好 Android 开发环境，并优先在模拟器中测试。主验收入口是模拟器上的 App 用户流程，贯穿真实开发服务、测试数据库和隔离媒体目录。模拟器流程用公开 UI 行为进行断言，不依赖内部组件名称或方法调用次数。

服务端公开 API 是补充集成测试边界，专门验证高风险文件行为和失败恢复；内部模块不分别建立一套 mock 驱动的镜像测试。只有无法从这两个高层边界可靠触发的故障，才添加最小的故障注入手段。

本规格起草时项目没有现成测试或可复用的代码范例。当前 Flutter 脚手架使用 flutter_test 和 integration_test 验证开发环境；真实业务测试继续遵循上述高层边界，后端测试工具随后端选型确定。

### 模拟器环境的完成标准

1. 确认 Windows 虚拟化与模拟器运行条件，安装或定位 JDK、Android SDK、平台工具、模拟器和可用系统镜像。
2. 创建并启动可重复使用的 Android 虚拟设备，确认设备工具可发现设备。
3. 根据最终框架配置开发工具；若选 Flutter，再验证其 Android 工具链和最小 App 构建、安装、启动。
4. 确认模拟器能访问开发服务，且请求确实到达测试媒体目录对应的服务实例。
5. 使用隔离测试视频完成首次连接、首次播放和一次旋转；环境重启后能够重复运行。

以上均为待实施的任务，不代表已经完成安装。模拟器不能证明真实手机硬件解码、NAS I/O 或家中 Wi-Fi 性能，交付前仍需一次目标环境兼容检查。

### 模拟器端到端验收

- 首次登录、错误口令、连接记忆、服务不可达与恢复。
- 多目录扫描后的缩略图列表、空库、空筛选结果和刷新发现新文件。
- 横版与竖版视频、暂停、拖进度、倍速、全屏、播完循环、滑动切换以及仅当前视频发声。
- 随机一轮无重复、回看、重开继续、重新随机、切换筛选和轮次结束。
- 单条与批量标签操作、标签改名及删除、多标签交集和属性筛选。
- 快速整理的目录/标签/属性组合筛选、连续打标签和删除、返回日常浏览；不改变未删除收藏的物理位置。
- 连续删除后自动切换、撤销正确条目和轮次位置、最后一条删除、回收站恢复和永久删除确认。
- 管理数据备份、恢复确认、恢复后标签和目录映射可见。

### API 与真实文件集成验证

- 测试使用可丢弃的媒体目录和数据库，断言 API 返回、目录内容与文件字节校验结果；不得在用户收藏上跑破坏性测试。
- 初次扫描不移动文件；新文件仍在写入时不错误入库；目录不可用不批量标记删除，扫描中断不错误清理记录。
- 外部改名、同一目录移动、跨目录移动、重复内容副本和同路径替换，验证标签不误绑。
- 删除、恢复中的同名冲突、权限不足、空间不足、源文件变化、请求重试与服务重启；验证不覆盖、不丢唯一副本、不重复执行。
- 扫描与文件操作同时发生时保持可解释的状态，不能把回收站文件重新作为新视频发现。
- 备份完整性和版本校验、恢复失败回滚、目录重新映射；旧备份的历史操作不能再次执行永久删除。
- 容器重建后管理数据仍在；新实例恢复备份后可以重新关联仍存在的视频。
- 未认证媒体和备份访问被拒绝；越界路径、链接逃逸、篡改的恢复目标和替换文件不能触发非预期文件写操作。

测试关注使用者能观察到的结果。不得用“调用了某函数”“写了几次数据库”替代行为验收；不为简单字段赋值重复编写实现镜像测试。

## Further Notes

### 实施顺序与完成条件

1. **HTML 原型确认**：同功能、同数据的视觉对比后，按用户选定 B 风格完成可操作原型，用户整体试用确认。
2. **Flutter 客户端演示版**：沿用已配置的 Android 环境，用统一数据接口和演示提供方完成所有界面、播放、手势及状态，在模拟器整体确认；此阶段不把模拟文件操作视为真实业务完成。
3. **服务端**：按已确认客户端契约实现认证、扫描、查询、媒体流、播放顺序、标签、可靠文件操作和备份，使用公开 API 与真实隔离目录验收。
4. **分功能联调**：逐项替换为网络提供方，验证真实连接、播放、标签筛选、快速整理、删除撤销、外部文件变化与备份恢复；每项均有对应客户端和服务端任务作为阻塞项。
5. **NAS 与 Android 交付**：容器重建、模拟器完整回归、真实 NAS 和目标 Android 媒体兼容检查，以及部署和恢复说明。真实样本与性能证据不能用 HTML 原型或环境脚手架替代。

各阶段属于同一第一版范围，备份恢复和外部文件变化仍须交付。按标签调整文件夹已明确延后，不阻塞本版。当前不估算工期，以实际样本和工具链验证结果再安排。

### 原型反馈对范围与契约的补充

用户在 HTML 原型中追加确认：支持随机与顺序播放，顶栏的播放模式按钮不承担整理模式切换；顺序暂按目录和文件名排列。候选还应支持媒体目录内的目录层级范围，包含子目录，与标签交集和属性条件共同生效。客户端使用服务提供的目录身份逐层选择，服务端只列举配置挂载范围内的目录，不能借此浏览任意服务器路径。切换目录、标签条件或播放模式开始新轮次；普通重开继续轮次和位置。

界面采用紧凑的当前页名称、位置/数量和文件夹/播放模式/更多三个按钮。视频下方标签为可高亮的快捷筛选入口；进度位于视频内，管理操作按需进入更多菜单，横版有快速横向全屏入口。原型的具体画面与交互以当前设计基线为准，HTML 的演示文件操作不构成 NAS 文件可靠性验收。

### 初始环境调查与后续变更

- 规格起草时的初始检查在命令搜索路径中未发现 Flutter、Dart、ADB、Android Emulator、SDK Manager、Java 或 Docker；这只描述当时的命令环境，不代表当前安装状态。
- NAS 连接、实际媒体目录、硬件配置和样本尚未提供；尚未访问 NAS 或分析实际视频。
