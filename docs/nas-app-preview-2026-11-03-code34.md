# 第34版：图包删除按视频方式处理

App：`0.2.0-preview.28+34`。服务仍为`0.2.0-preview.9`，本次无需更新或重启。对应[#188](https://github.com/ShiJiJS/video_viewer/issues/188)。

媒体库图包移入回收站直接执行，给出短提示和撤销，撤销也不打开提交进度弹窗。图包回收站选择后点永久删除，服务器后台删除对应文件夹，App自动查询完成结果并刷新列表和数量；不展示“待核对”“操作提交”“保存的删除选择”，不创建新的保存选择记录。重新打开App会自动处理旧版本留下的已完成删除请求。原请求去重及丢失响应后的只读查询继续保留在内部。

问题原因是第33版只记下了已受理的目录删除，没有自动跟踪到结束和清理本机未完成记录。已完成的实际文件删除因此被界面误报为仍需核对。本次NAS只读检查显示，用户自行发起的622个图包永久删除已全部成功，失败0；没有再次发送删除或用真实收藏测试。

正常APK：`video-viewer-0.2.0-preview.28-arm64.apk`；原签名同号旧视频界面回退APK：`video-viewer-0.1.4-rollback.28-arm64.apk`。覆盖安装保留数据，不卸载、不清数据。原型仍独立隔离、不随App打包；私人回收站记录及正式备份继续保留。

`flutter analyze`无问题，20个相关客户端测试文件共168项全部通过，覆盖启动自动处理旧请求、不重复发送、暂时断网后恢复查询、多选移除和撤销无弹窗、回收站数量自动刷新及旧服务兼容。签名构建及NAS交付校验另行补齐。未做实体手机测试。其他暂停的持续开发与旧验收不恢复。
