# LF6 客户端操作与普通卡片回收

本轮为已选定原型的继续实施，沿用 P2、Paper/SheetFrame 和现有卡片比例。用户任务是从图包卡片移除整包，并在误操作时恢复；从封面阅读与“更多”管理分工保持。不是新设计方向，也不修改冻结原型。

## 当前交互

- 封面仍进入阅读；更多菜单提供阅读、整包标签和（服务支持时）整包回收。普通回收按原型确认，显示包名、图片数量和保留源文件/标签/进度的后果。
- 确认后提交一次。成功后刷新同一查询与原位锚点，提供绑定该操作的撤销；失败不报成功。收到未知结果可关闭面板继续浏览，本机记录保留。
- 原卡片可能因服务端已成功而消失，因此列表保留“待核对图包操作”的独立入口；再次点同一包时也先采用原请求并查询。多个未确认操作可以逐项处理，不锁住其它图包。
- 查询只GET，404不丢掉记录、不自动POST。仅未取得任务身份时提供显式重新提交原请求；已知任务不会再POST。较新操作的撤销不受旧按钮影响，最终因果判断仍由服务端完成。
- 确认面板复用240ms浮层转场，处理状态使用既有进度指示，结果使用既有SnackBar进入/退出；状态不叠新导航。普通路径的确认是冻结产品契约，优先于技能中对可撤销动作的一般建议。

## PackFiles 模块

不可变 PackFileCommand 只包含逻辑整包 trash/restore/undo/retry；嵌套ID列表和阅读归属也不可变。请求键与原负载固定，展示包名只存本机，不发给后端。Task解析验证操作类型、结果总数、成功/失败/部分状态、唯一成员及请求成员一致；格式不完整不能当成功或清除待核对记录。中断和没有完成结果的失败任务仍需查询或显式重试。

PackFileJournal 用独立 `video_viewer.pack_commands.v1` SecureFileCommandStore，按 endpoint + server_id 分区，和旧视频操作记录分开。全部写盘串行，POST之前先落盘；写盘失败不发出POST。仅在调用方处理完成结果后 acknowledge。坏记录不自动覆盖或清空；不保存口令、令牌或媒体字节。未确认命令按包/回收条目互斥，重复同键在途请求合并、同键异内容拒绝；连接范围之间互不覆盖。

每个网关固定服务连接、连接代次和阅读/管理数据代次，旧连接结果不得应用到新连接。重开只加载本机意图，交互查询原请求，不自动提交。恢复代次与完整管理备份v2仍由LF7整合；当前不能以此宣称所有管理恢复场景已完成。

显式失败任务重试有独立只读 `/api/v1/pack-retry-requests/{request_id}`，返回原operation任务，不将它当作新的图包删除任务。服务端回执带当次 `server_time`；撤销时长由服务端提交期限与回执时间之差计算，再减去本机接收后的经过时间，最多8秒，手机与NAS系统时钟偏差不影响初始可用窗口。最终超时仍以服务端为准。

## 验证及剩余工作

HTTP接口/本机记录、确认面板和应用卡片路径分别验证；组件截图载入仓库PaperSerif与模拟器NotoSansCJK，测试默认Ahem方块图不作证据。支持320普通、360双倍字号和390普通，按真实字形检查换行与按钮。日志与当前实现校验另见LF6实施记录。

普通卡片和阅读器快速整理现均已接线，新增阅读路径见下文。按类型回收站/跨页恢复已接线，见[回收站契约](LF6-TRASH-CLIENT-DESIGN.md)；永久删除清单、整份批次计划后台续作、实际安全存储重开和DEL/REC完整验收仍需继续。已有原生标签名称路径随新的菜单返回方式调整，验证记录不得沿用旧截图来声称本实现原生通过。

## 阅读器整理接线（继续实施）

图包媒体库/标签结果的工具栏、卡片菜单和阅读器更多菜单均提供显式快速整理。进入时固定原查询和排序，候选范围由服务端创建，包含当前分页尚未加载的成员。快速整理沿用原型：标题副行显示模式，完成只退出整理；保留页码滑杆，底部用整包标签/回收两个按钮替代普通阅读工具，上一包/来源/下一包继续使用原范围。普通字号保持P2紧凑排布；大字号将来源与前后导航分行，避免末尾“返回来源”挤压。

PackReadingSession 负责进度与文件操作之间的时序。先冻结新的可见标记并flush当前实际画面，确认opened与进度版本后才保存并提交整包请求；待确认时同时禁止图片手势与页码/设置/队列写入。成功才读取同一session的下一成员，核对transition的session/revision/pack后安装。尾项直接返回来源，不将finished summary中可能保留的先前候选显示成下一包。成功回执后的元数据读取失败也保留原请求，查询只GET，不会重复推进。

普通阅读删除使用 `reading.advance=false`，确认后返回来源；服务端只撤销旧lease并保存返回守卫，不前进原游标。旧快速整理默认行为和幂等负载保持兼容，显式false使用新的 `pack_reader_cleanup` 能力门控。

阅读器内撤销先flush已显示的下一包，再冻结；原operation的reading_restored决定是否恢复原包/页码/比例/偏好。内容恢复但会话守卫失效时只刷新内容，不接管新的阅读位置。来源页面的撤销由MediaWorkspace按原library/tags/recent切换到图包入口，再只GET原session恢复阅读，不重新创建筛选范围。当前另一个阅读路由在前台时不抢占。

本机reader_context记录原查询、顺序、来源、quick、session以及列表偏移/锚点/邻项；不包含媒体字节，也不发给后端。该行为元数据参与本机同nonce签名，坏来源记录拒绝使用；老记录无此字段仍可恢复。离开待确认阅读器后，来源列表的独立待核对入口保留原请求；撤销请求同样保存原上下文。连接变化使旧结果失效。


### 阅读滑杆语义与异步保存

Flutter 3.47.7在弹层阻塞Slider并跨帧保存偏好时，可能保留内部OverlayPortal的旧语义父节点（上游问题[flutter/flutter#193706](https://github.com/flutter/flutter/issues/193706)）。本App按滑杆可交互状态设置ValueKey，让禁用/启用时重建Slider内部状态；没有移除断言、关闭语义或修改SDK。两尺寸带延迟保存的组件检查先复现同一断言，再通过；保留实际滑动断言及原生纵向设置流程。SDK临时诊断仅扩展assert消息，之后按原哈希恢复，详见回收站证据。
