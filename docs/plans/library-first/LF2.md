# LF2：图包目录与授权图片服务

对应 [#27](https://github.com/ShiJiJS/video_viewer/issues/27) / [PR #36](https://github.com/ShiJiJS/video_viewer/pull/36)，实现提交 `9aff732`，基于 LF1 / [PR #35](https://github.com/ShiJiJS/video_viewer/pull/35)。本阶段提供真实图包数据和读取能力；原生媒体库、阅读器、阅读会话及整理操作继续由 LF3–LF7 接入。

## 已实施

- 配置为 `pack` 的根直属文件夹作为图包，包内递归；页按相对路径各段自然排序。支持 JPEG、PNG、WebP 静态图片，保留坏页占位及原因；空包、全坏包和目录访问失败可查询，不混入可阅读列表。散落在根下的图片及其他附件记录扫描提示，不改动源文件。
- 扫描复用现有单任务调度，视频先完成准备，图包扫描继续后台运行。冷库没有待匹配旧身份时，已完整检查的包先发布，不必等最后一个大包；类型的 `ready` 仍表示完整首扫结束。部分目录失败保留旧记录，不把未见内容判为缺失；离线、停用和未映射分别处理。
- 包/页身份不靠名称推断。目录设备、inode 与创建时间可用时一起核对；缺少创建时间时需要完整签名或现存页证据。唯一完整内容清单可恢复跨目录移动身份，重复副本保留歧义；停用、离线、回收的缓存只用于排除歧义，不能捐出标签身份。受保护子树的旧页不充当当前身份依据。
- 同包增删页、唯一改名保留 ID、标签与进度；移除当前进度页时回退相邻有效页并提高 revision。页清单或目录策略变化提高 `content_version`。未变化的扫描复用哈希和探测结果，缩略图缺失可重建。
- 图包查询提供真实总数、分页、目录子树、标题/相对目录搜索、包标签 AND、阅读状态和排序。分页页清单包含尺寸、格式、哈希、错误、版本及同源读取地址。查询不创建阅读会话，不写最近记录。计数和返回条目在同一 SQLite 读取快照中生成。
- 封面、缩略图和原图使用已有 token 鉴权。读取再次验证根启停/类型/映射/最内层归属、目录身份和源文件签名；逐层拒绝符号链接及路径替换。支持 GET/HEAD/Range，取消后归还描述符和并发槽，原图流式发送。
- 图片探测在可终止子进程中运行，限制 8000 万像素、1200 MiB 地址空间、15 秒 CPU（16 秒硬限）及配置的墙钟超时（默认 20 秒）；失败不会拖垮 HTTP 进程。缩略图最长 512×768，按 EXIF 方向生成，原图字节不变；缩略图写入失败仍保留可读原图。
- 目录接口新增可选分页，默认调用继续返回全部直属项以兼容旧客户端。停用、图包及未映射子根形成隔离边界，即使子目录无读取权限，也不能让外层视频扫描失败。

## 迁移与接口

`0005 → 0006` 仅新增目录身份证据 JSON；冻结的 0004 旧库仍经真实升级逐行核对旧表旧列，另验证带图包标签、进度、偏好与最近记录的 0005 升级不变。升级快照/异常恢复继续沿用 LF1。`/info` 公布 `schema_version: 0006` 和 `image_packs`，不提前宣告阅读器或整理能力。

接口细节见 [CONTRACTS.md](CONTRACTS.md)。页的 `ordinal` 是稳定排序依据；隐藏子树后可有间隙，客户端页码应根据返回顺序与分页 offset 计算。读取旧版本返回 `409 pack_changed`，应重新取得清单，不能把旧页号套在新清单上。LF5 客户端图片缓存还需结合连接身份和页哈希；LF7 恢复后需使旧缓存及请求代次失效。

备份 v1 的临时门禁仍有效：存在图包数据或非默认目录状态时返回 `backup_upgrade_required`，LF7 的 v2 完整备份负责接替。本阶段没有把图包状态遗漏后伪装成成功备份。

## 验证与边界

验证结果、环境和源文件哈希分别保存在 [结果记录](https://github.com/ShiJiJS/video_viewer/blob/c9c6363ab1ca3bb7d72c96499432a289de33f187/docs/plans/library-first/evidence/lf2-results.json) 与 [源文件清单](https://github.com/ShiJiJS/video_viewer/blob/c9c6363ab1ca3bb7d72c96499432a289de33f187/docs/plans/library-first/evidence/lf2-source-sha256.json)。服务端使用冻结 Docker 镜像，无实时源目录挂载；全部源变更/取消/损坏测试使用临时生成的可丢弃数据。

- 服务端全量测试覆盖旧视频/迁移/回收/备份和新增图包行为，包括目录 inode 重用、重复副本、扫描中变更、中断恢复、冷扫逐包可读、权限失败、读取快照、授权与路径替换。
- LF0 标准四包夹具逐页通过公开 HTTP 校验：508 张有效原图 SHA-256、508 张缩略图、500 页自然排序、4K/6K/8K 尺寸和损坏 JPEG 的明确失败；扫描与读取后所有源文件哈希不变。生成器固定为 `video-viewer-lf0-synthetic-v1`，验证器只接受自建临时目录。
- 真实 HTTP 的约 50 MB PNG 和 128 MiB 视频分别验证单槽背压、三次取消、随后 Range 重开及有界 RSS/描述符。测试只在前一次流尾部的 ASGI 资源尚未释放时限时重试 503；持有未读流时仍严格要求第二条流返回 503，泄漏不能靠无限重试掩盖。
- Android I1 两阶段复跑旧视频连接、分页/目录、服务重启、断线恢复、App 进程重启后凭据和深层目录恢复。使用 Mac host GPU、关闭 Vulkan；只重置 8761 隔离实例，普通 8760 服务不变。

Ruff lint 通过；9 个原有未修改文件仍不符合 Ruff 格式基线，单独记录，不宣称格式全绿。当前数字是 Docker ARM64 合成数据与模拟器的验证，未作为真实 NAS/手机性能结论。原生图包页面、横纵阅读、整包删除以及逐项原型视觉验收尚未完成。

原型仍单独位于 `design/reference/`，tag `design-lf-2026-10-23` 固定，本阶段没有修改。未改真实 NAS 文件，未发布升级 APK。合并继续按 LF0 → LF1 → LF2 的依赖顺序。
