## 问题与处理

上轮原 Restore-partial 在未重扫前已实际读取成功，准备另一图包时扫描却使其变成旧missing + 新available。原目录没有创建时间，目录属性因自身永久删除变化；剩余图片归位后的ctime又与页记录不同。扫描以完整图片签名确认身份，因此匹配失败；后备内容比对还包含已永久删除的页记录，与实际剩余页的摘要不相同。原标签、进度和最近没有被删除，但留在旧ID上，App看不到它们。

新的扫描确认只增加一种有日志依据的连续性：同一目录设备/文件身份，创建时间存在时必须不冲突；仍在原相对路径，剩余图片的设备/文件身份、大小、mtime、完整SHA相同，并有当前未历史化的成功归位日志及已恢复记录。图片观察由已有扫描器在稳定文件上读取/核验；不按路径强认身份，不放宽普通目录或图片替换的规则。读图与扫描共用归位日志条件，读图接口的只读哈希/缓存行为不变。

已经产生的旧missing+新available，也可在下一次明确扫描找回原ID。仅当原ID有上述唯一证据，且新ID没有任何管理或操作引用，才移除无管理数据的新记录、使用原页/原标签/原进度继续更新。检查所有指向图包的数据库外键，未来新增关联默认也会阻止自动处理；事务内重新核对状态、代次和进行中的操作。若新ID已有标签、进度、偏好、最近、会话或操作记录，两边都保留，本次扫描报告身份冲突，不静默选择或丢数据。
