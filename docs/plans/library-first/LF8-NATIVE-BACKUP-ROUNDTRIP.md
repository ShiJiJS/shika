# LF8 下一步：系统文件与完整管理备份同次往返

依赖草稿PR #87，继续#24／#33／#32的备份验收，不改变独立原型布局。当前已开始实施，原生结果待实际执行后记录，不预先宣称以下整路完成。

## 已有能力与真实缺口

PR #53已实现Android系统文件选择／保存桥接、64KiB复制、协商上限和SHA校验；独立DocumentsUI三轮40MiB保存／选入、取消／超限已有[旧阶段证据](evidence/lf7-archive-files/README.md)。同阶段真实HTTP／Repository／安全日志／私有文件也完成三轮完整备份恢复，但系统文件边界使用私有适配器。后续PR #54补强停，#71补原型页面。不能再将系统选择或分块代码笼统标为未编写；也不能把这些分段结果拼成整路真实系统文件往返通过。

生产backup_v2能力仍关闭。当前最直接缺口是从真实App设置页出发，系统导出到手机文档、重新选择同一份文档、HTTP上传校验、目录确认、完整替换、核对恢复结果在同一次流程完成，随后再做大文件整路和故障组合。

## 下一次实施

1. 沿用现有ArchiveBackupPage／NativeBackupArchiveFiles与独立8762夹具，新增真实系统文件模式的驱动，保留既有私有文件测试边界，不mock原生通道或伪造系统选择结果。
2. 经四入口App设置导出，由实际DocumentsUI保存新文档；记录这次新文件的大小和SHA，不能误选模拟器上以前同名文件。重新选择同一文档上传，核对导入结果与实际页内统计。
3. 保留目录映射／分页、默认未勾选的完整替换确认，只明确确认一次；核对恢复前新增的两类标签被替换、媒体源字节不变、免口令新代次、原恢复任务和恢复前快照可查询。系统保存取消／选择取消必须保留原请求状态，不自动重发。
4. 保存固定源码、DocumentsUI与App窗口、HTTP精确请求数、原安全日志、文档／媒体SHA及显示恢复，先完成小文件同次往返，再以大管理数据文件核对协商上限及App整路有界传输。独立40MiB旧测试不重复算作新整路结论。

后续正式开放完整备份须依据实际通过的App／公开能力／服务说明同步处理，不能为了进入页面直接打开生产能力。目标手机／云文档提供器／NAS与原签名升级等待配合时按用户授权暂跳过，并保留未验收状态。默认凭据、正式8760、NAS源文件、SDK和原型不改，不在此计划中发布APK。

实施入口：现有server_archive_management_test保留默认私有文件模式，显式ARCHIVE_NATIVE_DOCUMENTS使用生产NativeBackupArchiveFiles，仅记录元数据、不替换平台通道。专用ARCHIVE_SERVER_PORT=8769、安全键archive_native_app与新容器／数据目录隔离已有8762夹具。新runner实际操作DocumentsUI，在保存框显式改成唯一文件名，保存后按Download目录本轮新增集合精确识别文件、读取字节核对大小／SHA，选取时严格匹配该新文件名；成功保留本轮导出的系统文档供复核，工作目录留同字节副本，核对其它文件名不变。App仍从四入口设置进入、核对27根分页与默认关闭确认、完成一次恢复及只读快照预览。当前生产代码和能力开关均未改。

初轮诊断：系统保存成功，host通过exec-out读取带空格名字时把shell引号传成了字面文件名，得到84字节cat错误而非备份；实际adb pull的19205字节与App源SHA完全相等。修为ADB文件传输后，第二轮保存及SHA通过，但Android文档提供器保留了前次已删文件的同名条目，严格选名发现两个候选而拒绝。现改为真实保存框唯一命名，不放宽成随便选第一项；两次未完成材料单独保留，不计整路成功。
