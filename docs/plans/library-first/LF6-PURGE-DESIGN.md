# LF6 精确图片清单与永久删除

沿用冻结原型的设置→回收站→永久删除，最终必须实现双确认、逐页结果与中断核对。整包逻辑回收与永久删除是不同命令；前者已接App，本记录继续永久删除。本次先落地后台清单准备，不把预览清单当成执行授权，也不据此关闭DEL-05。

## 已实现：后台准备精确清单

`PackPurgePlans`持有不可变请求、后台准备、持久化清单与只读回执；`PurgeManifest`隐藏文件描述符、递归目录证据与逐图片哈希。页面后续只领任务、读结果和确认ID/摘要，不持有可任意修改的NAS删除路径。准备过程没有mkdir、rename、unlink或rmtree。

| 接口 | 当前行为 |
| --- | --- |
| POST `/api/v1/pack-purge-plans` | request_id + 1–1000个trash_ids；全部类型/存在/状态合法才建任务；202后后台读取与核对 |
| GET `/api/v1/pack-purge-requests/{request_id}` | 只读原受理回执，不创建、不重新准备、不延长期限；同键不同选择409 |
| GET `/api/v1/pack-purge-plans/{id}` | 任务状态/逐包错误、图片数/字节/保留项数、每包与整份清单SHA、服务端时间/期限 |
| GET `/api/v1/pack-purge-plans/{id}/files?trash_id=…&offset=…&limit=…` | 逐包精确图片清单分页，最多200；计划/包ID不对应404，未准备好409 |

仅声明`pack_purge_preview`，不声明永久删除能力；目前没有图包永久删除执行路由。任务名为`pack_purge_preview`，当前App尚未调用这些新接口。准备在独立单worker执行，文件读取/哈希不持有SQLite写锁，普通查询与无冲突写入继续工作。提交与工作器按包保存/处理明细，最终管理核对流式读取；任务列表和进度只查独立的包名、路径、图片数量/字节与状态列，不载入所有包的source/manifest JSON。

源快照保存pack/trash身份、根/挂载/授权策略、generation/content_version、目录设备/inode/出生证据、每张索引图片的pageId/相对与绝对路径/签名/大小/已有SHA。逐级以O_NOFOLLOW打开目录，逐图片以父目录fd+文件名打开，核对同一普通文件的读取前后签名并计算SHA；与已有索引SHA不一致则拒绝。目录被替换、已索引页缺失、路径越界、未索引新增图片、普通范围内链接/FIFO等特殊文件均拒绝准备完成。

非图片附件记录为保留项；独立根、停用子范围与扫描排除目录记录为保留scope，不深入读取或借清单扩大授权。空目录记录身份供后续受限清理。目录每层读取前后检查，图片哈希完成后再检查整棵树的成员/签名和根/包身份；管理数据与目录授权在短发布事务内再次校验。准备中恢复图包或更改目录策略使该条目失败。

每包成功清单独立持久化。部分包失败时可以查看原因与已准备的包，但整份计划无可确认摘要、ready=false，不让成功前缀冒充整份确认。单包目录树最多20万项、深度128层；过大时明确要求缩小处理范围，不截断成成功清单。准备完成后有效期15分钟，由服务端计时；过期仍可读原回执，不自动续期。重建服务只重做尚未完成的只读准备，清掉上一进程未完成的中间清单，已完成清单不重算或重置期限。historical记录可读但不ready，也不自动重做。

## 持久化与迁移

增量schema0010增加`pack_purge_plans`与`pack_purge_entries`，不改旧视频、图包、标签、阅读与文件操作字段。计划关联Task，每包一行源快照/精确清单/摘要/错误；不把所有包清单写进一个不断重写的大JSON；汇总列在同一发布事务从已验证manifest生成，失败或重建时一起清零。不把可重做的准备任务放入逻辑文件操作队列，也不预留媒体文件来阻塞正常恢复。

既有迁移器在升级前生成可恢复SQLite快照；测试从0009的实际合成图包扫描、逻辑回收、图片/附件和请求记录出发，逐表核对升级前后原值。0010只在隔离测试目录运行，本机正式8760/真实NAS尚未迁移。正式备份v2、管理恢复时标记旧计划historical及新数据代次仍需LF7接线。

## 下一步：绑定清单的实际执行（尚未实现）

1. App从回收站所选项领取准备任务，保持原选择；展示准确包数、图片数/字节、删除图片与保留附件规则、不可撤销和备份不能恢复源文件，提供分页文件清单。勾选明确确认后才能提交第二次确认。
2. 新执行请求绑定plan_id、digest、request_id和明确确认值。核对未过期、非historical、全部条目可用且未被其它操作占用；确认前后的管理数据、根授权/目录身份、文件版本和目录成员必须重新验证，不能复用逻辑回收时的旧manifest作为物理授权。原请求幂等，未知回执只读查询。
3. 在逐页持久化执行日志里固定源签名/哈希与受控暂存位置。复用既有descriptor/no-overwrite文件转移机制的实际认领、核对与恢复语义；仅删除已确认且仍是所认领身份的图片。执行阶段跨进程可核对，重试只处理未完成项；冲突/新增/替换停止该包并报告，不递归删除图包目录。
4. 保留所有附件和新出现文件，只对清单内身份一致且实际为空的目录做rmdir；删除失败与文件字节删除后数据库提交前中断须分别覆盖。只有图片步骤与最终核对都完成才把该回收项标为purged；部分完成继续可查询，不能作为完整恢复成功。
5. 接回收站双确认、逐项任务结果和统一任务入口；真实Android/可丢弃目录故障验证后，才声明永久删除能力。随后完成整份批量计划后台续作和LF7统一任务/备份整合。
