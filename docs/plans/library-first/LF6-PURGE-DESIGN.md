# LF6 精确图片清单与永久删除

沿用冻结原型的设置→回收站→永久删除。整包逻辑回收与永久删除是不同命令；后台清单准备、逐页执行后端和 App 的清单核对/明确确认/部分结果现已接入。统一任务、整份批次续作与整体验收仍待完成，不据此关闭 DEL-05。App契约见 [LF6-PURGE-CLIENT-DESIGN.md](LF6-PURGE-CLIENT-DESIGN.md)。

## 已实现：后台准备精确清单

`PackPurgePlans`持有不可变请求、后台准备、持久化清单与只读回执；`PurgeManifest`隐藏文件描述符、递归目录证据与逐图片哈希。页面后续只领任务、读结果和确认ID/摘要，不持有可任意修改的NAS删除路径。准备过程没有mkdir、rename、unlink或rmtree。

| 接口 | 当前行为 |
| --- | --- |
| POST `/api/v1/pack-purge-plans` | request_id + 1–1000个trash_ids；全部类型/存在/状态合法才建任务；202后后台读取与核对 |
| GET `/api/v1/pack-purge-requests/{request_id}` | 只读原受理回执，不创建、不重新准备、不延长期限；同键不同选择409 |
| GET `/api/v1/pack-purge-plans/{id}` | 任务状态/逐包错误、图片数/字节/保留项数、每包与整份清单SHA、服务端时间/期限 |
| GET `/api/v1/pack-purge-plans/{id}/files?trash_id=…&offset=…&limit=…` | 逐包精确图片清单分页，最多200；计划/包ID不对应404，未准备好409 |

服务端现向 App 声明 `pack_purge_preview` 和 `pack_permanent_delete`，App 同时核对两项能力；缺少能力时不显示永久删除入口。准备任务名为 `pack_purge_preview`。准备在独立单worker执行，文件读取/哈希不持有SQLite写锁，普通查询与无冲突写入继续工作。提交与工作器按包保存/处理明细，最终管理核对流式读取；任务列表和进度只查独立的包名、路径、图片数量/字节与状态列，不载入所有包的source/manifest JSON。

源快照保存pack/trash身份、根/挂载/授权策略、generation/content_version、目录设备/inode/出生证据、每张索引图片的pageId/相对与绝对路径/签名/大小/已有SHA。逐级以O_NOFOLLOW打开目录，逐图片以父目录fd+文件名打开，核对同一普通文件的读取前后签名并计算SHA；与已有索引SHA不一致则拒绝。目录被替换、已索引页缺失、路径越界、未索引新增图片、普通范围内链接/FIFO等特殊文件均拒绝准备完成。

非图片附件记录为保留项；独立根、停用子范围与扫描排除目录记录为保留scope，不深入读取或借清单扩大授权。空目录记录身份供后续受限清理。目录每层读取前后检查，图片哈希完成后再检查整棵树的成员/签名和根/包身份；管理数据与目录授权在短发布事务内再次校验。准备中恢复图包或更改目录策略使该条目失败。

每包成功清单独立持久化。部分包失败时可以查看原因与已准备的包，但整份计划无可确认摘要、ready=false，不让成功前缀冒充整份确认。单包目录树最多20万项、深度128层；过大时明确要求缩小处理范围，不截断成成功清单。准备完成后有效期15分钟，由服务端计时；过期仍可读原回执，不自动续期。状态、摘要与任务结果通过同一SQL读取，避免并发完成时拼出“已完成+旧摘要”的矛盾结果。重建服务只重做尚未完成的只读准备，清掉上一进程未完成的中间清单，已完成清单不重算或重置期限。historical记录可读但不ready，也不自动重做。

## 持久化与迁移

增量schema0010增加`pack_purge_plans`与`pack_purge_entries`，不改旧视频、图包、标签、阅读与文件操作字段。计划关联Task，每包一行源快照/精确清单/摘要/错误；不把所有包清单写进一个不断重写的大JSON；汇总列在同一发布事务从已验证manifest生成，失败或重建时一起清零。不把可重做的准备任务放入逻辑文件操作队列，也不预留媒体文件来阻塞正常恢复。

既有迁移器在升级前生成可恢复SQLite快照；测试从0009的实际合成图包扫描、逻辑回收、图片/附件和请求记录出发，逐表核对升级前后原值。0010只在隔离测试目录运行，本机正式8760/真实NAS尚未迁移。正式备份v2、管理恢复时标记旧计划historical及新数据代次仍需LF7接线。

## 已实现：绑定清单的实际执行后端

| 接口 | 行为 |
| --- | --- |
| POST `/api/v1/pack-trash/permanent` | request_id/plan_id/digest/confirmed=true；严格布尔确认，拒绝false、字符串、数字或缺项 |
| GET `/api/v1/pack-file-requests/{request_id}` | 原受理回执，只读不入队；同键原负载返回原任务，同键不同操作409 |
| GET `/api/v1/pack-operations/{id}/pages` | 分页返回图片/目录的相对路径、阶段、结果与原因，最多200 |
| POST `/api/v1/pack-operations/{id}/retry` | 复用原任务，保留已完成步骤，仅处理未完成项；不生成新删除范围 |

计划有效期只约束新确认受理，已经受理的命令不因排队超过15分钟取消。每份计划只能绑定一个执行操作；其它键不能再次消费，预览回执给出operation_id并不再ready。受理事务核对状态/摘要和管理归属，并使所选内容所属旧逻辑回收的8秒撤销失效；无关图包的最新撤销保持有效。工作器再次核对冻结清单、目录身份/授权、源文件签名和树成员。单一图包文件工作器与现有逻辑操作共用排队/互斥，文件读取、哈希、移动和删除不持有数据库写锁。普通查询和其它无冲突元数据操作继续可用。

执行日志保存在schema0011的`pack_purge_executions`和`pack_purge_steps`；每包仍使用原PackFileStep作互斥和结果单位，每张图片与待清理目录有独立持久化阶段。图片page_id作为历史文本保留，不以外键阻止扫描器清理已经删除的页记录。PackTrashItem增加purged_pages，旧记录默认0；旧字段逐列保持。

图片先用不覆盖的原子rename认领到接入根内的受控私有暂存位置，再重新核对实际inode、完整SHA和读取前后签名；即使原签名相同也不跳过认领后的哈希。写下purging后才按本次认领的完整签名unlink/fsync。源文件或暂存身份变化不删除替换项；能安全归还时不覆盖地退回原位置，原位置已有新文件或暂存身份不明时保留冲突并标记needs_attention。

目录只处理清单中身份一致、当时实际为空的目录：不覆盖地认领到私有暂存位置，再核对身份和空状态，仅rmdir/fsync，绝不递归删除。包含附件/受保护范围的目录保留。清理期间出现新文件会停止并归还可归还的目录，新增内容保持；身份或目标冲突时不猜测归属、不覆盖。

树核对缓存各目录签名；成员变化时重新读名字集合，当前图片则在认领后完整哈希，附件/受保护项仍检查；大量附件/子目录下的真实NAS性能仍待LF8测量。已准备但尚未操作的图片不逐轮stat其不存在的暂存路径，避免按图片数平方增长的暂存探测；一次只装载当前包的日志/清单。所有目录重开时校验原身份，不仅依赖路径。

## 逐页归档、部分完成与恢复

文件unlink后、数据库归档前崩溃，保留purging日志；重启先核对原位置与暂存位置，再补归档，不能重复删除或增加计数。每页归档与页标记、pack.page_count/generation/content_version和purged_pages递增在同一事务；已提交的页不会因后续异常改写为失败。已永久删除页退出分页/封面/阅读恢复的可读清单，旧进度与偏好仍保留；重新扫描可清理旧页记录，历史执行日志不丢。

错误分开报告：已归档删除页数、待核对页数和未完成包数。未知结果不计作成功或部分成功；已有确认删除但整包未完成才标partial。原始文件已移除但归档未完成、或仍有身份冲突暂存内容时，保留needs_attention互斥，阻止恢复/扫描/目录改动掩盖未核对状态。GET只读展示；明确重试原任务继续核对与未完成步骤。

已知失败且全部认领文件已安全归还时释放互斥，用户可从回收站恢复剩余内容；已永久删除页不会因此回来。剩余计数来自当前索引，与旧原始清单分开。若所有旧页都已删除、又出现未索引新图，恢复后先显示不可读，再通过扫描重新索引。对于新增/替换/授权变化，必须重新核对或恢复后扫描，不以重试放宽原清单。

完整完成才把旧回收记录标purged、旧包标deleted并释放location_key；旧页/进度保留为历史。以后同路径出现新图片，扫描创建新身份，不自动继承已永久删除包的标签。其它包失败不阻止独立包完成，任务按包与逐页分别报告。
