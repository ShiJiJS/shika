# LF8：弹出菜单过渡

按[问题#110](https://github.com/ShiJiJS/video_viewer/issues/110)继续#24/#33的UI-06，基于已交付code15源码10f7c13b。原型保持独立可移除，当前preview.9两包不重建。本段统一现有菜单，不新增选项或改变业务动作。

实际Workspace“更多”在普通和减少动画下均报告300/300ms，运行中开启减少动画后仍停在0.2；专用公开SDK夹具设置AnimationStyle的240/160后，实际路由仍为240/240。3项实际App组件和1项SDK检查均失败，原日志与完整执行夹具保留。当前固定SDK的私有菜单路由没有读取reverseDuration，不能仅靠调用处配置完成退出与实时偏好要求，也不修改本机SDK。

七处入口接入PaperMenuButton：媒体库更多、两类排序、阅读器更多、播放器两处速度和旧服务首页更多。复用PopupMenuButton公开入口类型和原生PopupMenuEntry，路由及controller归本模块所有，进入240ms/退出160ms；每次方向开始重新读取系统偏好，实际原生偏好事件也能直接完成正在进行的方向。选择结果按原Navigator回执立即执行，退出动画不延迟业务。

按钮构造、Material菜单表面和布局沿用当前SDK规则，包含主题/形状/宽度阶梯、初值滚入、RTL、上下锚点、安全区与折叠区域。相关适配明确保留Flutter版权及BSD许可在apps/mobile/third_party/flutter-LICENSE；不访问或修改SDK私有状态。原生InkWell/IconButton、菜单条目与闭环焦点遍历保留，取消和选择分别回调一次；移除原按钮后仍能安全退出菜单，已移除按钮不执行迟到回调。

10项针对检查通过，包括实际Workspace普通/减少动画、进入和退出中切换、选择立即回调、Tab/Enter跳过禁用项、Escape取消、空/禁用菜单、移除锚点后旋转，以及一个测试内16组深浅/RTL/LTR/上下锚点/文字或图标按钮的完整RGBA与原菜单比较。原160ms断言把可见终点与Route.completed同一时刻等同，失败保留；现严格断言160ms绘制进度为0，再取下一ticker样本核对路由清理，不把清理帧时间称为可见退出或手机物理延迟。

初期自有路由直接混入WidgetsBindingObserver，和框架预测返回方法签名冲突，编译失败保留；现由独立观察器把偏好事件送给自有控制器，不覆盖原路由返回行为。一次从根目录误调用Flutter的启动失败未执行用例，也保留为运行器失败。以上均不计通过。

完整750客户端及analyze通过；本段仍需真实Android菜单与系统偏好核对，随后才能纳入新的普通安装包；当前code15不包含此修改。其它控件继续按具体构造调用核查：9处下拉选择、4处CheckboxListTile及1处Checkbox、1处展开项，以及其它自有显隐/尺寸过渡；重试/轮询/进度保存的业务计时分别遵循原契约。此清单是源码入口数，不是实际控件实例总数，也不据此宣称这些入口都存在相同缺陷。完整UI-06、其它正式验收、#78/#89/#100原因、目标手机/NAS/有声/云文件继续开放。
