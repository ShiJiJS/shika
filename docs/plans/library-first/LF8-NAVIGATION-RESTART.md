# LF8：完整来源导航与真实冷启动

基于PR #81，在当前整合分支继续NAV-01/02/03及相关LIB/REC组合。沿用LF4既有契约：冷启动默认媒体库、不自动播放；只把媒体库来源保存范围恢复到媒体库，标签来源留在标签中，最近来源不污染媒体库。运行中的各类型／来源草稿和选择互相隔离；不把跨进程持久保存所有未提交草稿当作既有要求。

专用8768夹具使用27段公开样本副本和27包公开PNG（各6页），两个标签命名空间保持不同ID。媒体库与标签结果各从第二页实际点击内容，视频／图包分别核对来源、完整成员、返回位置、搜索／筛选／排序和选择隔离；最近只来自实际打开，不借媒体库条件缩小。两类的完整来源都实际进入内容并返回，不以只切tab作为验证。最近深窗口另沿用其专段证据，不把本轮少量真实最近冒充长列表。

每轮在library／tags／recent其中一种最后视频范围后从设置页真正强停活跃Android进程，确认PID消失。新进程使用专属键的生产SecureCredentialStore及独立偏好文件，走生产App初始化；免口令进入媒体库，保留原活动范围和实际最近，不自动创建预览／阅读或新的打开记录。三轮分别覆盖三个最后来源，均记录强停前PID、新PID、接口、范围／进度及源SHA；同进程重建不算强停证据。

原生收集前冻结生产与驱动。发现产品问题先补回归并修复后再冻结，失败尝试与最终证据分开；大字／横屏或其它专项如果未执行就明确不作本段结论。用实际可丢弃目录，不操作正式8760、NAS、私人收藏或默认凭据键，不发布APK／改签名与版本；原型独立可移除且不变。整体验收和目标手机／NAS终验仍开放，需配合部分按授权暂跳过。
