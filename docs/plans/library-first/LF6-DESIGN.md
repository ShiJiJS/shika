# LF6 图包操作的实施契约

按已冻结的完整原型实施普通整包回收、显式快速整理、8秒撤销、按类型回收站、跨页选择和限定清单的永久删除。继续保留视频异步操作。原型在design/reference，不参与构建，也不为实现改动。

PackOperations模块持有幂等意图、逐包结果、任务恢复、回收记录与阅读转换。HTTP和客户端不自行拼接数据库状态。第一步接入逻辑trash/restore/undo和只读任务/回执；永久删除仍是本阶段必需工作，必须另加确认清单和实际文件核对，不能用逻辑回收接口冒充已经支持。

## 操作与持久化

- POST packs/trash、pack-trash/restore、pack-operations/{id}/undo接收request_id，返回持久化Task。相同键和内容返回原任务；同键改内容409，读回执不入队。未知结果只能查询，明确重试原请求或原失败任务。
- 身份列表1–1000，全部必须是正确类型且存在，否则整个请求404、不建任务。状态改变、已回收、竞争等按逐包结果报告；已成功步骤不会被重试重做。回收站完整选择最多五万，超过要求缩小查询，不返回伪完整前缀。
- 用LF1的PackFileOperation/Step/TrashItem表，JSON操作快照记录准备时的状态/版本和阅读归属。逻辑操作不读、哈希、创建、移动或删除媒体文件；保留location_key来防扫描重复导入，保留页/标签/进度/偏好/最近记录，最近和普通查询按状态隐藏。
- 持久化queued后单worker执行。提交成功和任务结果是不同状态。逻辑批次在事务里提交，进程在提交后丢响应/中断时，恢复只完成结果归档，不重新标记、重复推进阅读或重置撤销期限。historical操作不执行。
- 新受理的图包trash意图使旧图包撤销失效；重放旧request_id不能把它重新变成最新操作。撤销必须绑定原operation ID，8秒从原实际提交时间起算，只约束新撤销请求的受理；已受理的撤销可在重启后继续完成，不能因为排队时间而丢失。

## 阅读与撤销

快速整理只允许单包，并携带session_id、session_revision、pack_id、content_version、progress_revision。客户端先flush；后端验证当前实际opened归属与已确认版本。排队期间再次验证，旧阅读状态不能回收新的当前位置。普通媒体库回收不隐式切换阅读。

成功回收和原固定范围内向后推进在同一事务，跳过当前不可用项、不绕回前项；末尾标记结束并让界面返回来源。任务提供转换后的会话revision/下一包/结束结果。失败或未知结果不在客户端抢先跳走，不创造新范围。真正显示下一包首帧后，才按既有opened接口更新其最近。

保存原包、原位置、pageId/比例和偏好快照。撤销先恢复逻辑记录；只有原会话仍是当前、仍在该删除产生的位置/revision、原元数据没有被别人改写，才恢复阅读位置。否则恢复内容但不抢回另一个阅读范围或覆盖新进度。恢复进度和偏好采用保留的数据，不把旧快照强写回去；结果明确reading_restored。

## 并发和目录

PackFileStep pending沿用扫描预留；扫描读取之前与发布之前都检查回收/预留，避免先读后删的迟到发布复活图包。目录调整在待执行图包操作时拒绝。禁用/离线根不删除回收数据；恢复只改逻辑标记，未启用根仍受原查询/图片授权规则约束。管理恢复的写门禁继续生效；正式v2和跨模块恢复由LF7接线。

## 永久删除和界面（后续实施，不能据此关闭LF6）

永久删除必须先生成并确认精确已索引图片清单、版本和签名，再执行受控文件操作；新增/替换/歧义停止重新核对，非图片附件保留，只有空目录可清理。持久化逐页阶段、部分失败和中断后核对/重试，不能笼统递归删目录。

普通卡片确认整包影响；快速整理显式进入/退出，成功才前进，8秒撤销浮在界面上不改变布局。按类型回收站、跨页全选/分批恢复和永久删除双确认均需真实接口。界面、系统生命周期、未知回执、连续删除/撤销/末尾与视觉比例另按DEL-01–06和UI-02/04原生验收。
