# LF7 App 管理代次与原请求分册

## 行为契约

服务管理恢复后，App 必须先重新读取当前媒体库。旧页面、媒体请求、阅读器、任务页、默认设置网关、缺失清理和本机选择均不成为新管理库的提交来源。六类本机记录（视频、图包、整份恢复、缺失清理、永久删除选择、备份）保留原 request/task ID 和所属分册；历史查询不重新 POST，不结算当前分册，不因 404 擦掉未知结果。

`ServerApi.bindAuthority(info)` 只绑定一次。支持 `management_authority` 时每次携带固定 `X-Management-Epoch`，调用方不能覆盖。普通响应代次变化或服务端明确 `management_changed` 使该传输冻结并通知 Repository；新的传输从 info 捕获新代次。成功的旧写响应跨代次属于结果未知，不能伪装成明确 409 未执行。缺少/非法响应头同样保留未知记录；401仍沿用凭据失效逻辑。

备份原任务/原回执/原下载 GET 的窄路径白名单允许跨代次完成原恢复结算；只限无请求体 GET/HEAD，不能用于新写或新库页面。原恢复结算先落盘 settled，再交由 Repository 换连接，避免旧客户端在回调后清理新分册。迟到旧媒体401也须匹配令牌及代次，不能让已重连的新库退出。

Repository 发现变化后使旧连接和所有读取失效，保留加密会话，最多三次只读初始化；无需再次登录或保存口令。代次在初始化中再次变化才重试；人工重连的 generation 优先于尚未完成的自动重连。重连失败保留旧日志并给出重新连接入口，不循环提交命令。

## 持久化兼容

范围键为 JSON `[endpoint, server_id, management_epoch]`。已有图包多分册日志继续沿用；视频/备份旧单分册文本通过 `ScopedJournal` 兼容读取并升级为 `{version:2,scopes:{...}}`。写入适配器捕获固定范围，串行合并其他范围，不从可变化的 owner 读取所属范围。写盘先成功再发命令；即使存储实际写完后回执丢失，下次也须重读实际文本再合并。

旧服务无权威能力时初次单连接保留旧格式兼容。人工重新连接、从支持权威的服务回退、或已经有新式分册时，分配本机32位随机 localGeneration，启动继续复用；明确完成的旧式管理恢复也换本机分册，不能用清空旧视频日志代替。旧服务外部恢复仍不能自动检测，这是协议能力边界。

坏日志或范围不一致不覆盖、不提交；媒体只读与服务端任务仍可查看。多分册保存未引入无限大小承诺，现有本机选择上限仍沿用50,000项；日志大小和历史分册整理可继续审计。

## 任务中心

枚举同 endpoint/server 的原分册，并给历史本机行使用带原范围的稳定身份。历史选择保留27等原未提交数量，不能继续下一批；明确移除只影响该本机选择，不清除已提交命令。旧整份恢复/停止成功回执也保留原记录，不走普通结算；历史图包回执禁止acknowledge。原成功任务的详情及刷新通过只读包装始终保留历史标记，不重新进入当前操作入口。已有普通操作任务页面布局和字号比例沿用，仅增加必要历史文案。

本阶段只接仍可由当前服务原 GET 查到的回执；查不到保留原记录。尚未将独立历史图公开路由、恢复父任务的历史引用/孤立准备清理接入，所以不能据此声称任意旧图同 ID 查询已经完成。

## 验证与后续

服务端事务代次沿用 PR #50 的375项全集与两次真实 v1 SIGKILL；本阶段生产服务未改。App 单元/HTTP/组件检查和真实 Android 安全存储结果分别记录于 `evidence/lf7-client-authority/`，失败诊断与最终源码通过轮次分开。

原生使用公开合成媒体、专用安全存储测试键和隔离8761，实际 v1管理恢复轮换权威，验证运行中重新读取，以及强停后在App缺席期间恢复、新PID免口令读取原日志。它不是完整备份v2恢复/系统选择器证明。完整v2协调器、根映射/物理真相/前快照/原子替换、正式历史路由、App有界流式文件传输与系统选择器仍需继续。冻结原型独立可移除；本阶段不发布APK、不改SDK或正式NAS服务。
