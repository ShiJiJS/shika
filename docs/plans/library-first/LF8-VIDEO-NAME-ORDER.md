# LF8 视频中文名称顺序

冻结原型对视频标题使用localeCompare('zh-CN')；两个公开样本顺序为“风里的花园、水边的花”。旧服务的名称顺序为lower(name)/path/id，按编码比较时顺序相反。用户在媒体库、标签结果中选择范围后进入预览，列表和范围必须使用同一种完整顺序，不能只在App重排已缓存的一页。

## 协议和兼容

新增video_name_order能力。具有该能力时，App的VideoSort.name在目录、返回锚点、完整全选和创建固定播放范围中同时传sort=name及name_locale=zh-CN；path/newest/recent不带区域参数。缺能力时保持原请求。公共排序枚举继续是path/name/newest/recent，区域参数只接受zh-CN且只能用于name；旧请求和默认path行为保留。

服务在SQLite排序、LIMIT/OFFSET和row_number之前使用同一ICU zh_CN文件名键，再以原路径、稳定ID解决同名/规范化等价项。文件名为字面内容，不应用图包作者/编号解析，不改变name/path/ID、源文件或扫描结果。复用既有固定libicu72运行环境及线程独占collator，视频名和图包标题缓存各上限4096条，不持久化排序键。缺ICU不声明能力；显式区域请求返回503，不静默换成另一种排序。

固定范围内部以name_zh记录源顺序和source_ordinal；公共摘要返回sort=name及name_locale=zh-CN，旧App忽略额外字段后仍可解析已存在范围。此前直接增加公共枚举值的开发方案已弃用，避免旧客户端按枚举读取时崩溃。创建请求幂等哈希区分有无区域参数；恢复、随机后切回顺序、继续旧范围复用已存成员和序号，不因改名/新增而重排或扩大。无schema迁移；新服务先部署时，旧App名称请求仍沿用旧序。

## 预览退出生命周期

真实原生回归发现，返回来源时旧流程先释放播放器，页面仍可能在退场过程中重建VideoPlayer，触发“No active player with ID”。退出先同步标记closing、暂停可见意图并卸载原生画面，等本帧结束后关闭解码器，完成后才允许路由返回。重复退出仍被同一closing标记拒绝；断连与界面/系统返回复用该流程。保持原淡出时间与来源恢复。

## 验证边界

服务检查覆盖27项跨页的中文顺序、锚点、全选和固定范围，新增/改名后的固定序、随机后恢复、幂等、规范化同名、旧排序/最近加入/最近及缺ICU/非法参数。客户端HTTP检查核对四个调用面与重试、重连，旧服务不带区域参数；退出组件检查用已初始化的播放器观测原生视图在销毁前已卸载，界面和系统返回分别覆盖，旧源码应失败。

原生使用完整App、真实服务及公开2视频/4包/24PNG：冷库不创建范围，搜索一条后实际预览、回到原筛选；清除后打开完整范围，队列切顺序并跳到第二条，返回保持原名称顺序，最近只记录实际播放的两条。真实解码与静态卡片截图分开，不用缩略图冒充首帧。浏览器参考只在未保存snapshot中配置冷库，无修改冻结源码或持久状态。

Demo的离线字符比较不作为中文服务排序证明。完整最近列表形态、视频原文件名/时长显示、其它预览/阅读/管理状态及手势、500页4K/8K性能、目标手机/NAS与原签名覆盖升级继续保持未收口；本段不关闭LF8或总任务，不发布APK或操作正式8760/NAS。
