# 图包阅读默认使用纵向拼接，保留用户单独选择

跟踪：[137](https://github.com/ShiJiJS/video_viewer/issues/137)。

来自preview.16/code22首次NAS体验反馈，继续 #24/#30/#33。优先级：中；小改动，可优先随修复版交付。本轮仅规划，尚未实施。

当前核对：生产源码12d6ca67的`reading.py:26`、`reading_api.py:65`和客户端`pack_reading.dart:26`默认都是horizontal。本轮NAS容器内mode=ro读取确认未保存reader_defaults，因此正使用横向兜底；未修改运行设置。`preferences_in`已能区分图包自定义覆盖与继承默认。

目标：首次打开未单独设置阅读方式的图包，直接纵向拼接。它是阅读默认值调整，操作范围、标签、文件管理和阅读进度规则保持。

- [ ] 服务端实际默认值、接口缺省值、客户端/演示默认及设置页初值一致改为纵向，避免只改按钮显示。
- [ ] 这次现有NAS未保存全局默认，升级后继承新默认；实施前再核对是否已有用户显式保存的新选择，不猜测覆盖。
- [ ] 图包已单独保存的阅读方式继续优先；用户主动选过横向的保留。未覆盖的图包即使已有阅读进度，也继承全局默认，不重置页码/页内偏移。
- [ ] 不顺带改变方向、间隙、适配方式或当前阅读范围；保存/取消/重开和备份恢复的优先级一致。

验收：全新库/升级且未配置默认、已有全局设置、单图包覆盖、已有进度无覆盖四类；从媒体库/标签/最近进入；横纵切换/重开定位正确，默认设置取消零写。覆盖`test_reading.py`、默认设置和阅读组件相关检查；正常包读回服务端实际值。

交付边界：不通过批量改写所有图包的偏好来伪造默认，也不在本次规划直接PATCH真实NAS。
