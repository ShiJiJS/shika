# 修复新版返回操作可能进入旧浏览页的问题

跟踪：[140](https://github.com/ShiJiJS/video_viewer/issues/140)。

用户在preview.16/code22实际使用中反馈：偶尔按返回等操作会出现旧浏览页。继续 #24/#29/#33，关联历史返回/焦点票 #127，但不是同一问题。优先级：最高；先记录并复现真实路径。本轮仅规划。

已确认的源码事实：旧页没有完全删除，仍用于旧服务兼容。home.dart:1018起，新服务四入口使用MediaWorkspace，但非主入口管理页复用legacyBuild；1056起的PopScope含go('browse')，go函数没有新版目标校验；MediaWorkspace另有PopScope且会以Offstage保留。新版存在能显示legacyBuild/browse的代码路径。

尚未证明：这次手机偶发现象的唯一根因。不能直接声称某一行已复现或修好；需优先排查隐藏PopScope仍参与返回、多个处理器先后修改page、管理页/连接状态返回。

- [ ] 当前正常包记录系统返回/手势返回/页内返回的实际路由与处理顺序；覆盖媒体目录、任务、回收站、备份、连接设置，以及阅读/播放/全屏/标签结果/选择/菜单等组合。
- [ ] 新服务下只有媒体库/标签/最近/设置四个主入口，内容只从选定来源打开；管理子页返回设置，内容返回原来源并保留筛选/选择/锚点。
- [ ] 统一返回归属，隐藏/失活页面不消费当前返回；弹层、选择态、缩放态先在当前页面处理。一次返回不被多个回调连续跳转。
- [ ] 在新版导航边界禁止browse成为有效落点；库首页返回按Android规则退出/后台，不出现旧浏览页、不自动播放或创建旧播放范围。连接失败/重连/能力信息刷新不误降级到旧页。
- [ ] 兼容旧服务的旧界面与配套回退包单独保留并测试，不能为了挡住新版泄漏而顺手破坏原兼容承诺，也不能把旧页藏在仍能参与返回的新版页面栈下。

验收：真实普通包连续多轮返回并含Android手势/预测返回、冷启/后台重开、管理页与内容往返；核对界面及路由、无多余播放流/旧范围请求、原来源位置与阅读进度保留。旧服务兼容单列验证。故障路径和修复前证据保留，不能仅添加page字符串单元断言就关闭。
