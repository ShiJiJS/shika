# 纵向拼接阅读支持双指缩放和放大后移动

跟踪：[142](https://github.com/ShiJiJS/video_viewer/issues/142)。

用户确认希望纵向拼接时也能缩放。继续 #24/#30/#33。优先级：高；[默认纵向#137](https://github.com/ShiJiJS/video_viewer/issues/137)后这是主要阅读路径。初始规划保留如下，现已进入实现与检查。

当前核对：pack_reader_page.dart:923起传给_VerticalReader的没有resetZoom/onZoom；1843起仅ListView.builder和单击手势。缩放只存在于横向_ZoomPage（InteractiveViewer，1–4倍，双击2倍）。这是纵向分支实际缺失，不能用横向缩放的旧证据算已支持。

目标：直接在纵向连续阅读画面缩放和移动，保持前后图片连贯；不用先切到横向或跳进单图预览。

- [ ] 支持双指1–4倍缩放，以手指位置为中心；双击在2倍和原始比例之间切换。最小比例为正常宽度适配，缩回后仍能自然单指上下阅读。
- [ ] 放大后可横向查看细节，并可继续上下浏览相邻图片；拖动/双指/单击显隐控件的手势归属清楚，不误触翻包、整理或按钮。
- [ ] 返回先复位缩放，再按正常规则返回来源；复位、翻到指定页、切换模式/图包、旋转时保持正确页ID/页内锚点，不跳回首图或相邻包。原始阅读页码/偏移仍是续读依据。
- [ ] 捏合/复位本身不写成“读到下一页/读完”；主动滚动形成的新可见位置才按既有阅读规则保存。缩放比例作为本次会话状态，不默认写入永久进度或云端设置。
- [ ] 保持延迟解码和窗口边界（当前最多120条页元数据、6个图片provider与48MiB估计缓存）；不得把500张图拼成一张巨图或为缩放预加载全包。
- [ ] 图片失败重试/跳过、分页窗口前后扩展、8秒撤销恢复及内容版本变化不留下旧变换，不引入阅读写入的自动重发。

验收：混合横竖比例/长图/高分辨率/500页公开样本；1x/2x/4x、跨图片边界平移、双指后单指、复位/双击、深位置续读、真实旋转、窗口淘汰/补页、坏图和快速整理；使用真实Android双指操作及目标手机体验，核对页码/偏移、请求/缓存和误触。旧横向缩放及横向左右翻页回归单列。

入口：pack_reader_page纵向布局/缩放与返回状态、pack_reading_session锚点/窗口、reader_images解码缓存。实现前先明确缩放时的坐标和滚动映射，不通过禁用纵向滚动来规避手势冲突。
