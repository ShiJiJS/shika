# 简化图包操作文案，去掉“整包”措辞且保持行为不变

跟踪：[141](https://github.com/ShiJiJS/video_viewer/issues/141)。

用户明确要求操作说明更自然，例如“移入回收站”即可；操作对象和行为都不变。继续 #24/#31/#33。优先级：中，可随默认值调整一起交付。本轮仅规划。

当前核对：apps/mobile/lib及services/server/video_viewer共检索到28行带“整包”的可展示文本，涉及菜单、标题、提示、标签编辑、恢复/撤销和服务端错误，不能只替换一个菜单按钮。

预期文案示例：
- “整包移入回收站/整包移入回收站？”→“移入回收站/移入回收站？”
- “整包标签/保存整包标签”→“标签/保存标签”（需要区分类型的入口可用“图包标签”）。
- “整包已移入回收站”→“已移入回收站”；“撤销整包移除”→“撤销移除”；保留源文件、标签和阅读进度的说明用自然语言写清。

- [ ] 清理当前中文界面的菜单、按钮、确认、通知、错误、任务可见标题及辅助功能标签；服务端会直接显示的错误一并处理。
- [ ] 仍操作当前图包或已选图包，不新增单张图片管理/标签，不修改身份、请求体、任务/回执或文件范围，不改变普通确认、快速整理、8秒撤销、回收站/恢复及永久删除边界。
- [ ] 永久删除继续明确“永久”及影响对象，保留必要确认。简化措辞不删掉不可恢复、源文件是否保留等关键信息。
- [ ] 只因文案变化而更新对应语义/选择器/预期；技术类名、协议字段和历史诊断证据不做无意义全库替换。旧备份/既存历史文字不为本票重写或重放任务。

验收：正常模式/快速整理、媒体库菜单/阅读菜单/批量标签、回收站/撤销/结果待确认/错误页逐处核对文案与可访问性；关键动作请求对象与修前相同，取消零写。仅文案本身不另造镜像测试，复用相关业务检查确认行为没变。
