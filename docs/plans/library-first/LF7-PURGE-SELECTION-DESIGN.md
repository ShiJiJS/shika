# 永久删除：保存整份选择，逐批明确确认

用户选中大量回收站图包后，核对一批、离开、回来继续，不应再凭记忆重新全选；每批删除仍以当次核对的精确图片清单为准。沿用冻结 P2 的 Paper 字体、颜色、设置入口及完整管理页，不修改参考原型。

## 选择与删除权限

新增 `PackPurgeSelections`，只保存/读取/移除本机选择，没有 HTTP 或文件删除接口。`purge_selections_v1` 与文件命令、整份恢复共用生产安全日志及串行写队列，按 endpoint+serverId 隔离；旧 version 1 日志和未知字段保留。保存完整排序去重的1–50000个图包回收ID，最多32份选择；不保存媒体字节或口令。

保存选择不代表确认删除。只有用户在本批精确清单中勾选声明并确认，才产生包含原清单/摘要/图片数/最多1000个目标的 `PackFileCommand`。额外的 `purge_selection_id` 只在本机记录中关联整份选择，不进入服务端删除负载。原命令及其占用的本批目标在一次写盘中提交，写盘失败不能发送 POST。

剩余选择 = 原快照减去已经明确确认且未被明确拒绝的批次目标。未知响应的本批仍单独保留原命令，不能重新算成未提交内容；未开始的其它目标保留，不自动提交。新批必须正好匹配当前剩余快照的前1000个，旧页面或重复确认不能消耗新的剩余范围。已受理操作只绑定原任务ID，结算文件命令后仍保留整份选择和批次结果入口。

明确未受理的4xx（沿用原协议，408/429除外）把该批标为未受理，并恢复到未提交选择；再次处理须重新核对清单，不能重用已拒绝的本机批次。超时/503/未知/404保留原命令，查询不自动重发。其它命令的原资源互斥仍生效，未确认选择本身不授予删除权限或锁死正常恢复。

移除保存的选择只删除本机这份选择，不停止服务端任务、不删除图片、不清除待核对命令。移除前比较完整版本，旧页面不能移除后来新增批次。相同剩余选择复用原记录，重叠选择要求先从原入口继续或移除，避免出现多份无法区分的剩余清单。

## 入口与状态

回收站原“永久删除”先保存整份选择，再沿用原核对面板。取消面板后仍可从“保存的删除选择”打开；操作任务也展示本机选择，明确标为每批仍需核对，而非已经受理的文件任务。打开选择页只有本机读取，不准备清单、不提交删除。

选择页显示原数量、未提交数量、已确认批次和“核对下一批”，提供原操作结果入口。下一批重新使用精确清单面板，确认框默认关闭。移除选择有简短确认。历史选择显示原因并隐藏继续操作；本机管理恢复完成后保存选择一并标为历史，旧网关失效。其它设备管理恢复的权威数据代次、v2备份及完整父/子/成员历史化仍由后续管理备份阶段落实，不能据本机标记宣称完成。

沿用现有页面过渡、240ms面板动画、勾选反馈和实际读取进度。等待用户核对面板期间不保留底层持续加载条。普通字号保持现有比例；多页回收站的分页栏使用可换行排列，双倍字号不裁掉上下页按钮。主 Agent 走查，未做本阶段独立视觉评审。

## 验证边界

协议/本机记录检查覆盖1027快照、原子写盘、断线重建、未知GET404、4xx未受理、旧确认/旧移除、历史/连接隔离、损坏记录和未知字段保留。组件检查实际走1027选择→取消→离页找回→明确删除1000→剩余27→新清单默认未确认，并覆盖390普通、360双倍字号及操作任务入口。

真实 Android 流程另行检查取消后保存/重开入口、精确清单、响应丢失、部分删除和原任务重试，使用隔离8761合成文件。该路径与1027组件测试分别计证，不把组件存储重建当作 Android 进程强停，不把单包原生流程当作1000包物理性能。
