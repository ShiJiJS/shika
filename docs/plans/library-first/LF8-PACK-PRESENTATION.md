# LF8 图包标题、作者与完整范围排序

沿用冻结原型的标题16dp、作者12dp、标签11dp与两列封面比例，不修改参考目录。图包文件夹名、路径和稳定ID保留原义，显示字段不参与身份、写命令或扫描匹配。

## 可选显示信息

服务端从完整文件夹名派生 `title`、可空 `author` 与保留前导零的 `number`，列表、详情和阅读会话复用同一摘要。只识别明确的 `作者 NO.编号 - 标题`（亦接受大小写、全角点、不同破折号与可选作者括号）；编号为1至8个ASCII数字，作者上限100字符。单纯括号、日期、分辨率、数字前缀或破折号不足以识别作者。空作者/标题、含换行、格式未知均回退完整原名，作者与编号为空。既不重命名源文件，也不对未知来源编造作者。

App模型将原名与显示标题分开。列表主行显示标题，次行有作者时显示作者，否则保留可读张数；封面右下角仍显示图片张数，左上阅读角标按原型显示“在读 · 页码”或“已读”；未知页码只显示在读，不猜数字，多选时隐藏阅读角标以免遮挡选择。续读、操作页标题、阅读器、范围列表及最近列表使用显示标题。阅读头部次行显示作者与编号，无资料则保留页数。详情保留完整原目录、总页数/可读数与整包标签。旧服务缺字段、空字段或类型不正确时正常回退原名与既有信息，不阻断列表。

标题和作者都是原目录名的连续部分，沿用服务端原名/相对目录搜索可匹配这两项；不生成猜测的作者别名。搜索框改为冻结参考中的“搜索图包、作者、目录”。

## 服务端统一排序与兼容

新能力 `pack_presentation` 表示环境支持 `sort=title`。App的“名称”在此能力存在时，对列表、锚点、完整全选与创建阅读范围统一发送 `title`；旧服务仍发送 `name`。原来的 `name` 参数、缺省值和旧固定会话顺序保留，不改变旧调用含义。`newest` 与 `recent` 也保留原语义。阅读数据校验同时接受既有name与新的title会话，但创建回执必须与实际请求的排序一致。

`title` 在SQLite内用同一 `vv_pack_title_key(name)` 排序表达式，然后才做LIMIT/OFFSET、窗口锚点和成员快照；相同标题用稳定ID兜底。不会在App中只重排缓存首屏。显示字段始终是可变的当前摘要，已有会话的成员和ordinal不因改名或新增包重新排序。

中文顺序使用ICU `zh_CN` 的默认拼音排序，对齐原型 `localeCompare('zh-CN')`，不采用Unicode码点或单纯英文转小写。已在实际浏览器核对公开四包为“加藤惠 · 和服、灵梦 · 新年快乐、夏日祭、原野上的浪漫”；版本变更可能影响罕见文字的相对次序，需要重跑相应比较。ICU键只缓存在进程中（最多4096个名称），不持久化，不引入schema迁移或重扫。每个工作线程独立持有并释放collator；按实际UTF-16单元数处理emoji、组合字符与空文本。

Docker显式固定 `libicu72=72.1-3+deb12u1`；当前测试镜像已包含相同库版本，Python通过小型C接口读取排序键，不新增Python构建绑定。裸开发环境缺少ICU时不广告此能力，旧查询仍可用；直接请求不支持的标题排序返回明确503。标准Docker环境提供完整功能。

参考：[ICU排序](https://unicode-org.github.io/icu/userguide/collation/)、[C接口](https://unicode-org.github.io/icu-docs/apidoc/released/icu4c/ucol_8h.html)、[固定Debian运行库](https://packages.debian.org/bookworm/libicu72)。

## 验证范围与余项

服务检查包括保守解析/原名回退、身份路径不变、标题/作者搜索、28包跨页、中文同标题兜底、锚点/全选/创建范围一致、范围创建后改名/新增不重排、缺依赖能力回退、线程及Unicode；另回归库存、两类隔离、阅读、扫描、视频目录和备份。客户端检查两代能力的完整请求链、既有固定会话、无效显示字段回退，以及正常/双倍字号长作者卡片与操作入口。

原生使用已有AVD和每轮新建8768的公开2视频/4包/24PNG，验证实际卡片、作者/标题搜索、阅读标题/编号、原目录详情、原筛选返回、最近加入的完整4包范围与最近来源。实际打开会写opened/进度/最近，不能把本流程称为全程只读；搜索前后的只读区间另作断言。正式截图与验证结果在对应阶段证据中登记，未通过的轮次不得计入。
