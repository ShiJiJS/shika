# LF7 v2 管理恢复的真实 App 强停契约

本阶段承接 PR #53 的实际 App/HTTP/私有文件流程，补充 BAK-03 和 SET-05 的真实进程边界。只增加集成测试、隔离夹具和宿主脚本，App 与服务端生产源码均不改变；不据此开放 `backup_v2` 或关闭整个 LF7。

## 持久身份与中断位置

先通过生产安全存储和网关导出/校验一份 v2 文件；随后真实受理一个图包回收任务和一个恢复任务，保留原回执，并保存一份未提交的永久删除选择。导出之后新增的图包标签用于辨认完整替换。

真实 `ArchiveRestorePage` 加载 27 个根，跨 24 条分页检查并明确勾选原本关闭的完整替换确认。生产网关必须先持久化 v2 恢复请求，才发出唯一恢复 POST。隔离夹具在真实服务端故障钩子的 `snapshot_written`、`after_replace_before_commit` 或 `restore_committed` 暂停，并扣留受理响应，保证 App 没收到任务 ID。App 再次读取生产安全日志，确认原请求已落盘且任务 ID 尚未知。

宿主必须读到实际活跃 PID，执行 `am force-stop` 并确认 PID 消失，才释放服务端检查点。服务端完成期间持续确认 App 缺席，原请求映射到同一恢复任务，权威代次发生变化。首段 runner 的非零退出是有意中断，不能作为测试通过；第二段必须完整退出 0。

新进程使用同一专用 SecureStorage 键及原文件，免口令自动重连新代次。原恢复、导出、校验、两个真实图包命令及未提交选择共六条旧记录均保留原分册。原恢复请求只 GET 核对，两个图包任务必须返回受理时的原 ID/种类、历史标记和原 graph 的成员结果，不能读当前投影替代历史。原未提交选择不能继续删除，安全日志除既定的选择历史标记之外保持原内容。

## 实际页面与系统保存

从完整 App 的设置进入操作任务和历史筛选，打开原恢复任务，再点击下载原恢复前快照。宿主必须确认前台窗口是实际 Android DocumentsUI，截图后返回取消；App 恢复操作按钮，不能显示保存成功或结算原记录。再通过 App 自定义返回入口打开旧选择，确认没有继续永久删除入口。最后再次验证原私有备份长度/SHA、六条记录与源媒体字节。

重开阶段独立截取请求轨迹，除了既有自动扫描 POST，其余请求必须都是 GET；整轮只允许一次登录和一次管理恢复提交。所有历史图包成员查询必须携带原 graph ID。

## 隔离与证据

夹具只在 `VV_ARCHIVE_APP_FIXTURE=enabled`、固定隔离数据路径/挂载/合成口令的已有启动保护内运行；控制端点另需专用测试头。暂停与扣留均有 120 秒超时，宿主 finally 释放并恢复原视口。只使用已运行的 owned 8762 和 emulator-5554，明确 `--no-uninstall`，不重启 AVD、不清 App、不更换 SDK，不操作正式 8760 或 NAS。

固定源提交的三个检查点各跑一整轮，小屏双倍字号和普通视口分开报告。保存两个 runner 日志、旧/新 PID、停止前/缺席完成状态、重开前后请求轨迹、前后媒体摘要、实际 App/系统窗口截图与源码摘要。开发失败和开发成功轮次均放独立 diagnostics，不纳入固定源码通过数。

这只证明 App 在三个服务事务位置被强停后的恢复与只读核对；不是服务端断电/整机崩溃，不替代 PR #52 的服务进程 SIGKILL。此处文件由真实导出产生，未声称三轮均为 40MiB，也未测 Android RSS。完整历史专用永久删除清单/页明细、其它命令/来源的强停组合、历史图片失败、全原型暗色/横屏/手势与目标设备/NAS及签名发布继续。
