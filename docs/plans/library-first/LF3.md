# LF3：视频固定范围（实施中）

对应 [#28](https://github.com/ShiJiJS/video_viewer/issues/28) / [草稿 PR #37](https://github.com/ShiJiJS/video_viewer/pull/37)，基于 LF2 / [PR #36](https://github.com/ShiJiJS/video_viewer/pull/36)。服务基础提交 `08fb641`，客户端/二级预览页 `d2f4631`，队列版本读取修正 `98d47d0`，暂停控件与队列定位 `ea43f9f`，原型控制条与背景对齐 `1af451e`，长列表定位 `436554c`，重叠刷新保护 `0902ade`。LF3 仍在实施：固定范围、二级原生预览和来源位置恢复已接入；完整 I2 故障/生命周期矩阵及进程重开两阶段已首次通过，仍待 LF4 的来源接线与最终关键路径复跑。

## 服务端已实现

- `POST /rounds` 显式指定 `membership=fixed`，同时接收 search、目录、标签交集、方向/时长/类型、source、sort、anchor 与 request_id。候选由服务端全范围查询生成，和已加载的第一页无关。查询与创建使用相同的名称/相对目录搜索及排序。
- 固定会话只排除目前不可用的成员，不再重新套用原标签/目录/属性过滤；编辑或删除标签、新增文件、扫描刷新不重建会话。旧调用默认 `legacy`，保持旧客户端原有协议。
- 切换随机/顺序走独立的 `PATCH /rounds/{id}/order`；只重排存储成员，保留当前视频。顺序基于进入时的原始排序，不跟随后来变化的最近顺序。`restart=true` 从原范围重新开始，也不吸纳新内容。创建、重排和位置更新均有幂等或 revision 校验。
- `GET /playback?create=false` 在尚未开始时返回 `404 round_not_started`，允许新界面只读连接状态；原调用默认保留自动创建旧轮次的兼容行为。最终新客户端须使用只读模式。
- 最近视频只在 `POST /rounds/{id}/opened` 核对实际当前视频后去重更新；请求可幂等重试。列表、队列和封面预取不写历史。`GET /recent?kind=video` 分页读取；`source=recent` 创建范围只使用最近成员。图包最近接口留给 LF5。
- 视频撤销在固定会话中保存视频 ID，重排后按 ID 恢复；删除原过滤标签也不阻止找回原视频。旧回执按原 cursor 继续兼容。
- `0006 → 0007` 增加轮次 membership/source/sort 和成员 source_ordinal；旧轮次默认 legacy，旧候选不扩大。`0007 → 0008` 独立增加 sequence_revision，位置更新不改变队列版本，重排/重来才改变；已有 0007 状态逐表逐列保留。v1 备份投影仍为精确 0004 列，有固定会话时明确要求 LF7 的 v2，避免遗漏新语义。
- 队列分页带 `v=sequence_revision`，服务端在读取快照内核对；失配返回 `409 round_order_changed`。客户端刷新当前队列后拒绝旧页，不能把新顺序页放进旧位置缓存。

## 客户端与原生路径已接入

- `VideoEntryScope` 独立保存查询、搜索、来源和排序；`VideoBrowseContext` 另存返回位置。图包上下文仍独立。真实服务与 Demo 都支持查询完整入口、固定范围、重排/重来、实际打开记录；Demo 还持久化基准顺序、当前顺序和最近记录，重开不按最新标签重筛。
- 新服务连接使用只读 playback 获取，不自动创建轮次；固定预览需要 fixed_video_sessions / versioned_video_queue / video_entry_anchors 能力。旧服务继续原视频协议，新固定入口明确要求升级。旧本地缓存查询也核对根启停/类型/嵌套边界，搜索不匹配主机挂载前缀。
- 支持新能力的服务及 Demo 默认进入媒体库；库内搜索、筛选与活动轮次分离。点卡片、预览此范围、快速整理均进入独立 route，来源页保留在下面。预览没有底部主导航。四入口外壳及视频/图包分类仍由 LF4 完成，现有外壳的旧浏览入口尚未删除。
- 新预览页按固定原型保留 52dp 顶栏、46dp 范围栏、完整画面、范围队列、视频标签、按需快速整理和底部前后切换。暂停后显示明确的播放按钮/进度/速度，横向全屏与原手势复用现有播放器。离开前关闭解码器；未完成的初始化等待可取消，退出后不保留超时计时器。
- 队列使用随机访问分页，最多保留四页元数据；排序后重新定位当前项。位置、显式队列选择、模式变更和完成命令在浏览会话内串行；队列版本与位置 revision 分离，迟到位置回执不能覆盖新顺序。
- 阅读实际可见的视频才确认 opened，队列和播放器相邻准备不写历史。快速整理沿用原视频异步文件命令、准确操作 ID 撤销和 8 秒浮层；未知结果不显示成功，浮层不挤压画面。
- 页面进出 240/160ms，面板 240ms，快速整理展开 160ms；系统减少动态效果时这些新过渡直接到位。尺寸与交互说明见 [预览设计记录](LF3-DESIGN.md)。
- 重开连接时只读恢复上次实际进入过的查询、搜索、来源与排序，停留在媒体库，不创建新范围、播放器或最近记录；用户修改新的入口草稿不覆盖保存的活动会话。连接失效时二级预览关闭并释放播放器，露出登录页。
- 默认播放顺序已与活动会话分离，只作用于下一次进入预览。首次沿用已有顺序作为初始默认；当前范围的随机/顺序切换不覆盖它，修改默认值也不重建活动范围。LF3 暂用串行保存的本机偏好，读回与保存失败保留旧值均有回归；LF7 仍须按规划接入服务端默认及 v2 备份。

## 原生播放与生命周期修正

实际横屏回归发现旋转的短暂 inactive 会被误当成后台，导致暂停并丢失时间线。现在保留旋转前的播放/暂停意图及同一解码器；只有真实 hidden/paused 才释放网络播放器，回前台继续暂停。控件中的设备提示消失时，也使用稳定 Key 保留倍速菜单状态，避免选择 1.5× 被重建吞掉。

另一条真实流程发现，在队列面板内切换到新视频，面板关闭后未恢复播放。新选中项现在在面板关闭后开始，原来暂停的当前项仍保持暂停；开启/关闭相邻准备两种路径都有可复现的回归。

`5d1c496` 的独立原生全屏用例已通过，覆盖同一解码器、旋转前后的播放意图、实际亮度/音量、1.5× 与长按 2×、真实 Android Home/返回、后台释放及横屏返回。宿主通过 ADB 触发系统状态，完整记录 inactive → hidden → paused → hidden → inactive → resumed，不再直接注入不合法状态顺序。该记录作为早期独立检查点保留；完整 I2 两阶段已在 `22ff159` 通过，包含上述修正及外部失效提示修复，见 [播放回归检查点](evidence/lf3-playback-results.json)。

外部移除导致旧视频页面被销毁时，恢复说明由预览 route 保存，不再随旧解码器一起消失；只接受同一活动范围内的结果，连接失效仍返回登录页。
