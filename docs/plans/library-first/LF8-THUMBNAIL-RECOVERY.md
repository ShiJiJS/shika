# LF8 总览缩略图恢复与取消（#83）

基于 PR #82 的整合分支，原型仍独立放在 design/reference/library-first，未改变总览尺寸、布局和“重试”按钮。

复查旧请求，两个503之后确实各有200，但发生于 nav-device-back 阶段；不能由截图断言旧版完全没有自动重试。旧实现已有400／800ms两次退避。本段要证明成功解码与取消的边界，并修复缩略图共享网络客户端不能取消在途响应的问题。组件旧版基线 recover/bounded/close-timer/manual/unauthorized 5项通过，close-request 因关闭后socket仍未断开失败。其它开发命令／驱动诊断另存，不计通过数。

实现：每个远程缩略图单元格／尝试独立拥有HTTP客户端，关闭总览时立即强制关闭其连接；关闭动画开始即取消工作，不等卸载。换页、版本、图包、地址或请求头改变时取消旧请求并清除旧图；手动重试取消待执行的自动计时器并重新获得两次退避预算。正常主阅读仍使用原有图片提供器，关闭覆盖层不重建主阅读图片。401继续原有鉴权回调，不自动重试。临时网络／503／429／超时最多自动重试两次，持续失败保留手动入口。

验证范围：新增10项真实本地HTTP组件检查，连同既有阅读布局、错误页和传输重试共21项；静态分析／格式／Ruff。计划在8768独占公开样本夹具实际验证6张缩略图各注入首次503后自动解码（生产端并发忙碌也占原两次预算）、持续失败停在3次请求、手动恢复6张、真实Android返回取消6个未结束响应、重开成功；比对固定范围、当前页码／模式和服务详情、非GET请求。专用控制只存在于测试工厂且受夹具键和环境开关限制。源文件前后SHA、原生图及窗口／请求／源码记录按既有runner保存。

首轮原生注入每张两次503后，生产第三次另有真实并发忙碌503，两张达到上限；未计成功。保持原上限，改为首次注入503并让生产忙碌占其余预算，组件另有连续两次503恢复检查。第二轮六张实际已各在2或3次请求内恢复，但旧驱动仍要求全部3次，断言超时；只修正驱动为2–3次并且六张真实解码，不修改App或放宽两次重试上限。原生验证进行中，尚不据组件检查宣布#83或PKG-03全部完成。正式8760、NAS、默认凭据、签名和APK发布不在本段操作范围。目标手机、大字／横屏及其它LF8未决项保留各自验收边界。
