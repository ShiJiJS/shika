# LF4：双类型媒体库与四入口（实施中）

对应 [#29](https://github.com/ShiJiJS/video_viewer/issues/29)，基于 LF3 / [草稿 PR #37](https://github.com/ShiJiJS/video_viewer/pull/37)。完整四入口与页面尚未交付；当前首先接入真实图包目录数据，避免界面继续依赖视频缓存或原型数据。

## 已接入的读取与写入边界

`LibraryPack` 是整包摘要，保留真实页数、可读页数、版本、独立标签、进度与鉴权封面；不会把单张图片变成媒体库项目。`CatalogPage` 的 total、offset、limit 均来自服务端，不以已加载条数充当总数。

真实 adapter 分离为 `server_pack_catalog.dart`，继续共用连接凭据、恢复门禁与凭据失效处理，和视频共享同一 repository 生命周期。它实现：

- `loadPacks`：标题/相对目录搜索、图包目录 ID、标签交集、阅读状态、排序及分页；目录不可用直接反馈，不回退全库。
- `loadPackTags`、`editPackTag`、`setPackTags`：独立命名空间、名称搜索与服务端计数、创建/改名/删除、批量追加及单项替换；临时丢失写回执时，显式重试复用原 request_id。
- `loadPackDirectories`：始终带 kind=pack，根与子目录按真实接口分页，不复用视频目录缓存。
- 图包、图包标签、目录各自持有可取消读取；取消视频列表不取消图包。切换连接、凭据失效、销毁会使旧结果无效并取消请求。鉴权封面只允许同源地址，保留内容版本，并以连接会话区分缓存。

`PackQueryController` 负责分页、旧数据保留、原偏移重试、迟到结果隔离及换连接清空。最近图包依赖 LF5 尚未落地的实际打开记录；目前明确拒绝这个来源，不能在“最近”下悄悄返回全部图包。这个临时边界不等于 REC-01 完成。

## 验证

`c26522a` 全量 **119 项客户端测试通过**，静态检查通过。新增 6 项 HTTP adapter 测试及 5 项分页状态测试，覆盖完整筛选、服务端总数、页数/进度、鉴权/跨域拒绝、目录不可用、同名视频/图包标签隔离、追加/替换、丢回执重试、跨类型取消、迟到结果及连接切换。

测试的 HTTP 服务是可控协议夹具，用于验证客户端传输和状态；不是完整 FastAPI 或原生页面的验收。既有服务端图包能力和原生视频检查点分别见 LF2/LF3，不能把它们当成 LF4 原生界面已完成。

## 下一步的页面接线

1. 四个主入口固定为媒体库、标签、最近、设置；旧服务保留已有视频兼容路径。视频预览保持二级 route，管理页继续使用现有连接/目录/回收/备份能力。
2. 媒体库、标签和最近各自保存类型；每种类型/来源独立保存查询、排序、批选、滚动位置。标签先选 AND 条件再看结果，结果和媒体库草稿分离。
3. 先完成真实服务的图包卡片与视频/图包切换，再接标签 CRUD、分页筛选、来源返回；阅读、最近图包实际写入及整包整理分别接 LF5/LF6，不能提供假成功。
4. 按固定原型的 P2 尺寸实现代表性原生页面，390×844 对照，补窄屏、横屏、大字体、暗色及键盘。初载、空、失败、旧数据保留和原位重试分别验收。

原型仍在独立的 `design/reference/`，tag `design-lf-2026-10-23` 锁定；业务代码不依赖这个目录。当前未改原型、真实 NAS 媒体或发布 APK。
