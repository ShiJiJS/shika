对应 [#29](https://github.com/ShiJiJS/video_viewer/issues/29) / [草稿 PR #38](https://github.com/ShiJiJS/video_viewer/pull/38)，基于 LF3 / [草稿 PR #37](https://github.com/ShiJiJS/video_viewer/pull/37)。已从数据接线推进到真实四入口、视频/图包列表和独立标签页。阶段仍未完成：视频标签分页和完整跨页批选已补齐，图包名称已接入真实读取，剩余来源/深列表返回组合要继续补齐，图包阅读/最近由 LF5 接入。

## 已接入的读取与写入边界

`LibraryPack` 是整包摘要，保留真实页数、可读页数、版本、独立标签、进度与鉴权封面；不会把单张图片变成媒体库项目。`CatalogPage` 的 total、offset、limit 均来自服务端，不以已加载条数充当总数。

真实 adapter 分离为 `server_pack_catalog.dart`，继续共用连接凭据、恢复门禁与凭据失效处理，和视频共享同一 repository 生命周期。它实现：

- `loadPacks`：标题/相对目录搜索、图包目录 ID、标签交集、阅读状态、排序及分页；目录不可用直接反馈，不回退全库。
- `loadPackTags`、`editPackTag`、`setPackTags`：独立命名空间、名称搜索与服务端计数、创建/改名/删除、批量追加及单项替换；临时丢失写回执时，显式重试复用原 request_id。
- `loadPackDirectories`：始终带 kind=pack，根与子目录按真实接口分页，不复用视频目录缓存。
- 图包、图包标签、目录各自持有可取消读取；取消视频列表不取消图包。切换连接、凭据失效、销毁会使旧结果无效并取消请求。鉴权封面只允许同源地址，保留内容版本，并以连接会话区分缓存。

`PackQueryController` 负责分页、旧数据保留、原偏移重试、迟到结果隔离及换连接清空。最近图包依赖 LF5 尚未落地的实际打开记录；目前明确拒绝这个来源，不能在“最近”下悄悄返回全部图包。这个临时边界不等于 REC-01 完成。

## 已接入的原生工作区

`MediaWorkspace` 固定媒体库、标签、最近、设置四入口，视频预览是二级 route。媒体库/标签/最近分别保存当前类型，六种类型/来源列表各自保留查询、排序、选择和滚动容器。类型切换在帧后启动新读取，旧页取消不会误伤新页。

标签页显示当前类型标题、选择目的、独立搜索与标签计数；底部明确显示选中标签数和服务端交集总数，视频分别提供“查看结果”和“预览这 N 个视频”。直接预览也先建立对应来源结果，再进入固定范围，返回落在标签结果中，不改写媒体库草稿。最近视频只读实际打开记录，不继承库或标签的筛选。

新启动时，媒体库只恢复媒体库来源的上次范围，标签来源的保存范围保留在标签中；这取代 LF3 临时把最后一个来源填入媒体库的做法。保存的预览元数据仍不自动播放。

图包页使用真实整包模型、鉴权封面、页数、阅读状态和独立标签接口；支持搜索、目录、阅读状态/标签交集、排序、分页和整包标签编辑。当前点卡片展示真实详情，不假装已经具备阅读器；LF5 将替换为固定范围阅读。旧设置与连接、目录、回收、备份恢复继续保留，管理页面覆盖在保留的工作区之上，旧服务继续兼容路径。

比例沿用冻结 P2，并适配系统大字体与真实 SafeArea。视频封面保留原比例，暗色聚焦搜索保留主题轮廓；标签标题/汇总/通栏按钮已按独立评审修正。大字体增加文字区和工具栏高度，键盘弹出时暂收标签操作区以保留搜索空间。繁忙封面最多自动重试两次，每次清理失败图像缓存，最终失败仍可手动重试；离开页面取消延时，401 不循环重试。

## 标签分页与完整跨页批选

`e92a0ef` 将视频标签改为独立的名称搜索/分页读取，不依赖连接时的旧 snapshot；第50项后的真实标签、服务端总数和计数均可读。视频/图包标签各有可取消读取，旧搜索和旧连接的结果不能回写。分页失败保留列表与选择，固定错误入口按原偏移重试；发现总数变化、重复ID或错误偏移时，重试改从0刷新，避免拼接有缺口的标签。真实Android完整路径连续三轮通过，见 [标签分页证据](evidence/lf4-tag-catalog/README.md)。

`5953d16` 为视频和图包接入“全选匹配项”，一次读取当前筛选范围的完整ID快照，而非逐页抓取。独立选择控制器保留原选择，支持取消、失败后重试及单项排除；改查询/来源、手动选择或换连接会使迟到的全选失效。切换类型仍保留各自已选ID。底部三个操作区可随系统字号换行。

服务端新增鉴权 `GET /api/v1/videos/selection` 与 `/api/v1/packs/selection`，声明 `catalog_selection` 能力，沿用现有查询条件和类型边界；在一个数据库读取中取得完整ID，不创建预览、最近或阅读记录。视频包含library/tags/recent来源、排序与全部过滤；图包包含目录、搜索、独立标签交集、阅读状态和排序。响应为kind/ids/total，客户端拒绝错误类型、重复或不完整数量。超过五万项明确要求缩小筛选范围，不返回部分ID冒充全选；旧服务保留手工选择并提示升级。

批量标签写入按稳定ID顺序每1000项一批，继续使用原有写回执；丢失回执可显式重试。每批重新检查连接归属及恢复门禁，换连接不会将剩余批次发给新服务。部分或不确定结果保留选择，显示已确认进度。批选只剩一项仍按追加处理，保留原标签；卡片单项编辑仍是替换。未新增数据库迁移。

当前全量 **146项客户端测试**、静态检查通过，**56项服务端相关回归**与Ruff通过；包括完整筛选/最近、无观看副作用、跨1000项、丢回执、换连接、迟到全选、手动排除、失败保留与大字体下一项追加。提交后的真实Android完整路径连续三轮通过（360×740系统字号2一次、390×844两次）：24项已加载时全选27项、排除1项、追加26项，两类媒体原标签保留且选择互不串用。日志、截图及每轮APK哈希见 [完整跨页批选证据](evidence/lf4-selection/README.md)。

## 图包标签名称与编辑读回

`5d0d49d` 为图包摘要增加独立 `tag_names`，卡片按已有视频卡片的11dp单行样式显示名称；不为每张卡片再读全部标签页。摘要中的ID和名称来自同一读取，宣告 `pack_tag_names` 能力时客户端拒绝不完整名称。

新增鉴权 `GET /api/v1/pack-tags/resolve?tag_ids=…`，按精确ID返回独立图包名称及 `missing_ids`；每次最多256个，客户端需要时分批，保持同一连接与取消归属。视频标签ID只会被报告为缺失，不串用同名视频标签。名称读取与标签列表分页各有可取消范围，换连接、恢复或销毁使旧读取失效。

编辑和筛选弹窗直接解析原有选择，首50项以外也能显示名称。名称失败保留选择并可重试，未确认或已被删除的选择不能直接保存；用户取消已移除的标签后可继续。较早的名称响应不能覆盖后来搜索读到的新名称，换连接会清除旧名称并要求重新打开。列表翻页失败保留所选名称并按原offset重试。长中文标签在窄屏大字号下最多显示两行，卡片仍沿用原比例与单行截断。

保存后，已打开的图包详情保留这次成功编辑的标签ID与名称；再次编辑不会重新带回旧选择。真实卡片由服务端重新读回，改名/删除随原有通知刷新。旧服务未声明名称能力时，卡片保留计数；弹窗仍可通过已读取标签页确认名称，未确认项不会静默保存。没有新增数据库迁移、全局名称缓存或跨媒体共用标签。

当前 **157项客户端测试**与静态检查通过，本次图包/类型/完整选择相关 **41项服务端回归**和Ruff通过；之前56项选择相关证据继续单独保留。`5821667` 上真实Android完整路径连续三轮通过（390两次、360系统字号2一次）：卡片名称、首50项外名称失败/重试、保存后重开、改名/删除与视频命名空间隔离均实际走通；每轮日志、截图与APK哈希见 [图包名称证据](evidence/lf4-pack-names/README.md)。一次旧协议测试仍精确要求此前能力列表，已把两个新增能力补入预期完整集合，重跑41项通过；未放宽成子集检查。
