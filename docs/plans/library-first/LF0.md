# LF0：可运行骨架与可移除参考基线

对应 [#25](https://github.com/ShiJiJS/video_viewer/issues/25)，总任务 [#24](https://github.com/ShiJiJS/video_viewer/issues/24)。本次只完成 LF0，LF1–LF8 继续开放。

## 已实施

- **参考原型独立保存**：`design/reference/REFERENCE_ONLY.json` 和主页标记说明仅作设计验收、不随 App 发布，LF8 通过后可整目录删除。旧私人素材版留在本机忽略目录，上传版有 24 张合成页、公开演示视频的共享读取路径、独立 runtime/vendor/生成器/测试/截图；正式构建不依赖参考目录。
- **AppShell** 接管 Scaffold、安全区和底栏，保留当前入口和 nav-* Key。新四入口的视觉/导航迁移在 LF4，避免把 LF0 骨架和完整产品交付混为一谈。
- **VideoBrowseContext** 与 **LibraryQueryController** 已接入现有视频库。分页、取消、迟到响应、错误/重试在查询模块内处理；读取不创建播放轮次。旧播放、逻辑回收与备份仍经原有接口运行。
- **可分享夹具**：四个合成图包、508 张有效 PNG（含 500 页长包、4K/8K、大图横竖与嵌套自然顺序），外加损坏图片、空目录、附件；生成器拒绝覆盖非空目录。旧库 SQL 固定 schema 0004、4 个视频身份、标签、轮次/位置、逻辑/历史物理回收和未确认命令；不含凭据/真实媒体。
- **契约与验收**：[模块契约](CONTRACTS.md)、[视觉/性能测量方法](MEASUREMENT.md) 及 45 项 [验收 ID](ACCEPTANCE.md)。当前原型基线 hash 见参考目录，原素材版 `baseline.json` 仅作历史映射。

## 验证与发现

- 改造前：Flutter analyze 通过，68 项客户端测试通过；服务端 98 项业务测试通过。服务端完整脚本因既有 12 个 Ruff 格式文件仍返回非零，保留此基线，不批量重排业务代码。
- 改造后：Flutter analyze 与 73 项客户端测试通过，新增 5 项覆盖迟到响应不覆盖、读取不改播放、分页失败保留及重试偏移、离页取消、查询身份与滚动分离。
- Android 原生 + 8761 隔离实例：连续滑动、阻塞位置回执、连续逻辑回收、提示超时、跨页 25 条全选恢复、后台永久删除、缺失清理/待确认查询通过；操作前后测试源文件路径与 SHA-256 一致。
- 参考原型：12 组主流程、5 组整理、8 组设置，各连续 3 轮通过，含各自失败回退；隔离后统一为有序 runtime bundle，避免缓存刷新时只初始化部分扩展。合成素材截图另行保存，不上传私人原图截图。
- 新增冻结 0004 迁移不变量测试已在 Linux Docker 通过；Mac 本机不提供现有文件执行器依赖的 renameat2，这不是新数据迁移失败。

本轮补跑旧 I6 发现两处测试环境假设：OrbStack 在宿主 rename 管理目录后保留旧 bind mount，现保留挂载目录 inode，只移出其内部管理文件到可恢复快照，再重建隔离容器；原用例随机锚点可能位于队尾，却硬取位置 1，现显式建立顺序轮次来确定所验证的非零位置。二者都不改变正式 App / NAS 行为。完整 I6 三阶段已通过，包含恢复中断后的只读核对、全新实例显式映射及再次重开；结果见 `evidence/results.json`，失败日志保留本机 `.dev/logs/`。
