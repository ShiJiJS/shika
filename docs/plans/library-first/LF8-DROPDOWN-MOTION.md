# LF8：下拉选择过渡

[草稿PR #113](https://github.com/ShiJiJS/video_viewer/pull/113)按[问题 #112](https://github.com/ShiJiJS/video_viewer/issues/112)继续#24/#33的UI-06，承接菜单[草稿PR #111](https://github.com/ShiJiJS/video_viewer/pull/111)。本段保留现有下拉表单和列表布局；原型继续独立、可移除，不增加原型运行依赖，不重建现有code15两包。

实际阅读偏好的“默认翻页方向”使用固定Flutter3.47.7的DropdownButtonFormField，普通/减少动画都报告300/300ms，打开60ms再开启减少动画的第一帧仍为0.2。三项实际表单组件反例均失败；其中系统标记由组件测试提供，不当作真实Android证明。固定SDK的下拉路由只使用300ms，未提供可覆盖进退场与实时偏好的公开参数。

采用一个App内模块 `paper_dropdown.dart`，提供 `PaperDropdownButton` / `PaperDropdownButtonFormField` 两个现有使用形式。按钮/输入装饰/表单状态、菜单绘制、所选项对齐、滚动限制与条目焦点沿用当前SDK实现，保留Flutter BSD版权和 `apps/mobile/third_party/flutter-LICENSE`。实际选项仍是原生DropdownMenuItem、焦点/InkWell/输入装饰和表单机制；不访问SDK私有状态、不改或升级SDK。替换9处构造入口，范围涵盖视频筛选、图包状态、阅读器与默认阅读设置、目录类型、清理记录和维护任务筛选；调用处的选项、值、保存/请求和布局参数保留。

自有路由进入240ms/退出160ms，减少动画为0，每次方向开始重新读取偏好；独立系统观察器能完成进行中的进退场。保留菜单的分段展开，退出改为完整160ms渐隐。原SDK在路由结果回调中移除菜单，单设时长不能保留退出；现在结果立即更新选项，路由独立完成绘制退出。按钮持有全部未完成路由，销毁/旋转/禁用时主动清理；旧路由的布局回调不更新新菜单的条目尺寸。null选项与取消仍分别处理。焦点滚动普通100ms，减少动画直接跳到目标，运行中开启也完成目标并停止后续移动。

15项针对检查包括实际表单普通/减少/运行中开启、选择即时一次且退出中点仍可见、退出中切换、打开后再启用偏好、null与点击外部/Escape取消、40项长菜单的选择位置/键盘跳过禁用项、焦点滚动运行中切换、表单校验/保存/重置/初始值变化、禁用/空/失效状态及移除锚点/旋转。一个检查内另有16组深浅/RTL-LTR/上下锚点/普通与表单的完整RGBA新旧对照。既有阅读/设置检查只更新控件类型查找，保留全部业务断言。

调试中的失败分别保留：初始写入命令用了错误工作目录及zsh保留变量，没有启动Flutter；一次私有初始化形参调用名导致编译失败，不计用例通过；一次在已释放路由上查询Navigator的测试改为在didPop记录时长，第一帧动画为0的断言保留。焦点滚动的首两次键盘尝试没有观察到进行中的动画，不能当作实时切换证明；后一次请求未挂载的惰性条目同样失败。最终使用已挂载项的公开Focus请求，先严格确认滚动进行中，再核对开启减少动画后到目标、不再移动。键盘上下/Enter是另外两项通过检查，不把Focus请求称为实际按键。所有失败均与最终结果分开保留。
