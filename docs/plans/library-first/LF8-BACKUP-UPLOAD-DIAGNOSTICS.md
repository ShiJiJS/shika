# LF8：上传失败原因与原请求找回

基于[公开入口PR #90](https://github.com/ShiJiJS/video_viewer/pull/90)，继续[问题#89](https://github.com/ShiJiJS/video_viewer/issues/89)和#24／#33／#32。原失败只有“暂时无法连接服务”，底层IOException被归一化后丢失，服务trace没有导入POST；不能凭此认定完全没发出数据，或认定空闲连接就是原因。

本段保留失败时的Dart操作阶段和原始IOException，仅在内存中的ApiFailure持有；用户提示、请求次数、写命令重试策略、协议与连接参数不变。阶段表示异常出现在哪个await操作，不证明服务已经／尚未接受请求。程序不自动输出或上传这些信息，头部／口令／文件内容不写诊断日志。

显式--diagnose的隔离App驱动在导入失败时记录类型、阶段和异常message（不调用带URI／文件路径的toString），同时保留真实错误页面及安全日志，然后按失败退出；不把诊断失败变为通过，不增加POST。正常驱动保持原检查清单；测试仓库只观察原inspectArchive调用，转发同一个异常。

验证分层：真实拒绝连接保存原请求后，同进程重建ServerBackups／HTTP客户端，删除本地输入，再对相同原请求GET两次；服务明确404，日志及请求键保留，POST为0。此项使用MemoryBackupWorkStore，不能当作SecureStorage或进程强停证明。已有“上传已受理但丢回执”的相反组合继续回归；两者都不自动上传第二次。

随后固定源码、无其它回归并发，顺序运行真实Android系统文件／取消／完整恢复并记录每次终态；若出现原错误，先检查同次错误原因、原安全日志、错误页面和HTTP记录，不换版本后把其它通过材料算作修复。未复现时#89继续开放，不以成功轮次代替原因或修复证明。目标设备／云文档／NAS与原签名升级不由本段替代，原型仍独立可移除。
