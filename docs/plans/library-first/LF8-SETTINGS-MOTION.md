实际App原主题默认200ms，Material3开关300ms；二者在系统运行中开启“减少动画”后都不能立即完成已有动画。另发现共用标签底色会在主题变色后再走140ms，自定义Paper颜色只看brightness，导致过渡中途突然跳色。修改前主题5项、开关2项及单独的实际背景检查失败日志均保留。

现在主题与设置开关使用自有140ms过渡。开启减少动画时，已有过渡在下一次构建直接到目标；手指正在拖动开关时仍跟随手指，取消不保存。应用主题包装保持相同Element结构，页面、草稿、焦点和滚动位置保留。Paper颜色作为ThemeExtension跟随同一主题进度，输入底色同步；标签主题变色直接跟随父层，正常选择动画继续保留。

开关仅替换行内指针/绘制部分，整行键盘、焦点、无障碍语义和原紧凑48×40布局保留。滑块、轨道和描边随同一进度绘制，保存由原父层负责；异步保存未完成或失败时不虚构已保存值。取消、禁用、移除行不提交偏好，RTL/LTR方向保留。静止时深浅/开关/禁用/方向16组像素与原Material3开关完全相同；标签另16组静态对照继续通过。

完整740客户端检查及analyze通过。真实Android系统三项动画比例读回、PlatformDispatcher和MediaQuery一致，无注入；实际VideoViewerApp设置页的深浅切换及准备相邻视频各普通/减少动画三轮，共24次切换、24次内存偏好通知及12段完整解码录屏通过。普通模式采到滑块和主题中间值；减少动画在值变更后的首个观测帧已到目标，控件与导航Element保留。这里是实际App接内存Demo仓库的profile观察，不连接媒体服务，不把内存通知称为文件保存或服务写入，也不把Flutter帧时间称为手机物理显示延迟。
