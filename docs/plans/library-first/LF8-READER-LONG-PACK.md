# LF8：长图包与大图的 Android 原生演练

对应 READ-01/02/03/04/05/06、UI-02 与 #24/#33，基于 PR #75。上一阶段证明服务扫描及移除参考目录后的构建，这一段继续补 Android 阅读链路。

使用现有 LF0 公开合成生成器：500页长包、4000×6000与6000×4000及8000×8000大图，另保留自然排序、坏图与附件。只操作新建、受标记保护的本机目录和独立8769实例，不扫描或写入NAS及正式8760。

从媒体库真实入口打开长包，经阅读设置切换纵向，实际触控滚动到第500页；记录窗口跨40页分页、120页元数据上限、ReaderImages六项/48MiB估算预算和实际Flutter图片缓存/待解码数量。横纵切换保留当前页，手动换到大图包并实际解码4K/8K，再返回长包继续阅读。使用公开API和只读SQL核对进度/页ID及固定范围，不只按缓存数量判定完成。源文件操作前后SHA一致。

宿主在保持的检查点采集前台截图、真实dumpsys meminfo与窗口焦点；定期采样进程内存，保留Android日志和交互录屏。测试内记录实际解码帧尺寸、框架缓存峰值及帧时序；模拟器硬件、渲染模式与构建类型明确列出，不能当作目标手机/NAS的p50/p95或性能门槛。

先完整运行一次定位问题；如果需要修复生产行为，按新冻结提交重跑。关键链路按最终同一实现重复三轮，失败与QEMU宿主故障另行保存，不拼接成成功。没有通过的组合不关闭验收ID。原型树1cbf605继续独立保留，APK不发布，开发签名不作为覆盖升级证明。
