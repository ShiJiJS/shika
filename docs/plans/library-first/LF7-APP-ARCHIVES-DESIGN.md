# LF7 App 管理文件与原图历史

北极星：把两类媒体的整理结果保存成文件，需要时先核对目录，再完整恢复；断线或离页能找回原任务。沿用冻结 Paper 原型的备份入口、内容层级和确认逻辑，原型树不改。

## 入口与产出

设置 → 备份与恢复，展示两套标签、关联、媒体目录、回收、预览轮次、图包进度和阅读偏好的边界。导出先得到服务端原任务，经私有文件的大小与 SHA 核对后进入 Android 系统保存；取消保存保留原任务。重复打开下载同一文件，只有保存成功才结算导出并清理对应私有副本。

选择文件 → 服务端校验 → 独立的可滚动目录核对页。统计分开显示视频/视频标签和图包/图片/图包标签；目录按24项分页，跨页保留编辑，全部根载入后才能勾选默认关闭的替换确认。留空明确表示不启用。失败保留草稿和页位置。完整恢复的媒体字节、口令、本机外观边界沿用原型。最多256根时使用完整页面承载长表单，避免在小底部面板里编辑上百目录。

“恢复前的快照”直接出现在同一备份页，读取上次已完成恢复的本机快照；点击只是校验已有快照并进入同一目录核对页。服务端有界复制原文件，无须先下载再上传。不存在、缺失或变化不重新生成，不直接恢复。任务详情保留原导出与恢复前快照的下载入口。

从备份页开始计数：导出需要1次App点击和系统位置确认；导入需1次选择、系统选文件、核对目录、1次显式勾选和1次恢复。27根增加一次翻页，不要求记住上一页输入；校验失败不进入确认。已知快照入口省去下载/保存/重新选择三步，保留同一恢复确认。

## 文件边界

新 `BackupDocument` 只包含所属服务/代次、私有文件ID、长度和SHA；安全日志保存标量及句柄，不保存NDJSON、完整String或Uint8List。HTTP下载按块落私有临时文件，大小/SHA吻合后发布；上传先校验，再按块发送。取消、超时、文件变动和迟到代次响应会清理本次私有输出。未知写入不会自动重发POST。

锁定的 file_picker 保存接口需要完整 bytes，选取实现也会先复制缓存，不能用其接口宣称有界复制。本实现使用 Android SAF 桥接，64KiB复制并同步文件，选取过程中执行协商上限；MethodChannel仅传标量。只读用户本次选择的content URI，只写本次系统创建的文档，应用内路径须位于files/cache下。[Android文档](https://developer.android.com/training/data-storage/shared/documents-files)说明创建文档会生成新文件；本实现失败清理只针对本次创建的URI和私有临时文件。

服务返回实际 `management_backups.max_bytes`，允许4KiB至256MiB；默认仍32MiB。App不预设64MiB可用。私有副本消失时只GET原导出任务，不重新导出。系统保存取消或写入未知不结算原任务；服务替换/切换后旧文件不能进入新连接的恢复。

## 协议与历史

新文件流程使用v2，旧v1工作日志保持协议与原ID。重新打开只查询旧请求；用户明确重新选文件后才创建v2校验。旧协议的原预览只读，并提示重新选原文件，不自动把未知v1意图转发到v2。

历史回执按原epoch，详情与成员按原graph_id；校验父任务和成员图一致。未知代次/原请求没有落到当前库的兜底。仍在本机保留的原备份控制账本是权威执行结果，允许查询它已完成的原恢复；旧媒体命令仍严格只读。历史文件下载必须明确图或代次、匹配原任务类型/状态/大小/SHA；异机缺少原文件时不声称可再造原字节。

恢复前先持久保存确认内容及原键；恢复完成按既有管理代次接管新连接，不再询问口令。实际原生联调发现并修复了短暂连接切换时备份页重读能力上限的异常：页面保留本次打开时的协商值并禁用过期操作。

## 视觉、动效与验收边界

沿用Paper纸白、墨绿/橄榄、Serif标题、20dp页面边距和既有原生按钮/输入框，不引入新风格。状态区域140ms尺寸变化并尊重降低动态；页面过渡、勾选与按钮反馈使用既有Material/Paper行为。目录分页保留草稿，主滚动只有一个。标题、长路径和说明自然换行，390普通与360双倍字号均取实际Android截图。

`backup_v2`生产能力保持关闭。隔离8762夹具仅在测试进程明确添加能力，使用独立数据/媒体目录，不能据测试入口宣称正式服务已开放。系统SAF和真实服务UI分开核验：前者不mock原生选择器，后者使用真实HTTP、Repository、安全日志和私有磁盘，但保存/选取边界使用私有文件适配器。两者组合不替代目标手机、云文档提供器、真实v2强停组合与最终LF8验收。文件和历史专项仍需继续，所有LF0–LF8目标及issue保持开放。
