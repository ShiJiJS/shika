# 原型到原生 App 验收表

基线与架构见 [PLAN.md](PLAN.md)，原型摘要见 [baseline.json](baseline.json)。下表完整原生路径仍待实施/验收，当前 HTML 测试通过不能勾选原生项目。LF1 的类型/标签/迁移与 LF2 的图包扫描、分页及授权读取已完成服务端验证，见 [LF1](LF1.md)、[LF2](LF2.md)；这是 TAG-01/02、LIB-02/03、PKG-01–03、SET-04、UP-01 的服务层证据，不替代原生交互及真实目标设备验收。

每项证据包括：实现提交、Demo/真实服务模式、数据夹具版本、步骤及结果、必要截图或录屏、失败/重开检查。功能与截图分别验收；任务关闭必须引用下列 ID。禁止仅按函数调用次数或已加载缓存数量判断业务完成。

## 分层执行与交付

1. LF0：复跑旧库/视频/任务基线，固定非私人测试素材、确定截图状态。
2. 各功能：公开行为接口测试 + 服务端迁移/幂等/故障恢复测试；保留旧视频回归。
3. 原生 Android + 8761 隔离实例：以上入口到服务的全链路，冷启动/重开、断网与迟到回执；关键路径连续 3 轮，以发现状态污染。
4. 同数据 HTML / Flutter 并排截图；触控和动作另附录屏，截图评审不冒充运行验收。
5. NAS + 实际手机：可丢弃样本目录做文件变更/删除验证；真实收藏仅做已授权的浏览性能观察。记录首屏/首帧/翻页、p50/p95 延迟、内存、NAS CPU/IO/流量、样本规模与网络条件。性能阈值在 LF0/LF2 建测量基线后定，缺实测不得标完成。
6. 完成时提交 `RESULTS.md`，每个 ID 有状态/证据/偏差；未解决项目继续开 issue。全部通过后才关闭总任务，不因安装包能启动就宣称与原型一致。
