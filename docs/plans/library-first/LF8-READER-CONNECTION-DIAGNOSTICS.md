# 图包命令失败诊断（#100）

普通preview.3的第三次继续阅读出现连接失败，但QEMU、服务health和容器内SQL仍响应。原session请求查询404，明确重试一次后同request_id创建一个session并恢复。既有证据只有界面安全提示，不能判断在打开连接、发送、等待响应或读取响应时失败；它与原备份上传#89没有同根因证明。

当前先补诊断边界。ServerApi原有ApiFailure已携带底层IOException和等待阶段，但PackReadingSession将它压成字符串。阅读会话现在保留最近一次仍属当前连接/代次的命令异常：命令种类、原请求ID、是否只读回执查询及原ApiFailure。记录仅在该会话内存中保留一条，销毁清除；后续404或成功不抹掉它，下一次实际异常才替换。没有自动上传、额外写盘、UI技术信息或重试行为改变。

组件检查覆盖真实已关闭连接的失败、原IOException/阶段保留、查询失败不准重发；已有503→原回执404→明确同请求重试检查同时核对记录未丢失。关闭一个已连接服务后的首次请求可能在openUrl或等待响应头时发现旧连接已断，初始检查误把它固定当成opening，现按真实TCP关闭时序核对两种可能；这不是原#100已复现或已定位的结论。

独立profile诊断入口 `integration_test/server_reader_connection_test.dart` 使用自有AVD5558、独立8775普通服务和小型公开夹具；原正常APK9/升级AVD5556不覆盖。它反复从媒体库续读、Android返回、两套标签和设置，在进入前改变有限等待时长。若命令失败，先采集该次原异常/阶段，再只读查询原回执，停止且不重发写操作；终端报告和失败截图/请求窗口分开保存。诊断上报只存在于该专用入口，普通main不调用。

本阶段不调整ServerApi连接池、请求正文或写命令重试策略，不把相似提示或受控断线当作原故障。若有实际复现，再依据捕获的阶段和原因修复，并补前后对照；没有复现则#100继续开放。原型1cbf605保持独立可移除，服务生产树/镜像和SDK不变；真实手机/NAS需配合部分按授权暂跳过。

## 当前原生结果与宿主音频线索

冻结App/诊断入口edb4a235，677项客户端检查、17项相关检查通过。首次带音频的host GPU轮完成11次后QEMU87639退出，驱动退出1、没有终端profile报告，不能计12次通过；没有捕获到#100的阅读命令异常。确认进程及ADB均消失后才重启，不因观察超时重启。

复查87639、53619、41697和90728四份宿主报告，均有CoreAudio初始化等待（包括HALB_IOThread/AudioDeviceStart/coreaudio_enable_impl）和主循环/其它vCPU等待qemu_mutex_lock_iothread。此共同栈是宿主音频阻塞的线索，不是App OOM证据，也不能把原视频绿边或所有退出定为同根因。

随后只给同一AVD增加 `-no-audio`，App/SDK、服务容器、数据和媒体不重置；直接复用SHA `80dafb1b6756cbd6f680abe187f9f8931d36bb973e75f985128e3fcfcb119536` 的同一profile APK，12次完整操作和终端报告正常收尾。它支持阅读诊断的临时配置，不等于持续稳定已解决；音频关闭时不能验收有声播放。原#100在这12次中没有复现，保持开放。

启动器提供显式 `VV_EMULATOR_AUDIO=off`，默认on；10项隔离CLI检查通过，实际复用带no-audio的同一PID成功，要求on时返回3且不重启。说明见[Mac开发环境](../../macos-development.md)。本段没有改动原正常preview.3/rollback.3包或F5默认配置；新诊断改动尚未生成下一版正常配套包。
