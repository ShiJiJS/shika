# 纵向拼接缩放

跟踪[#142](https://github.com/ShiJiJS/video_viewer/issues/142)，基于分目录进度页面#148。当前生产源码d8acf140。最初d78afeaf实现缩放，60a0ae09只调整测试脚本等待设置面板的方式；普通code24发现入口竖屏锁仍阻止真实旋转，因此d8acf140为阅读器单独允许设备旋转，离开恢复媒体库竖屏。完整原生组合仍待完成，票保持开放。

用户任务是在当前连续阅读中看清细节，再自然地接着向下看。选定方向沿用现有阅读器：从媒体库打开图包后直接双指缩放，不切横向、不进入单图弹窗、不新增顶层入口。原本要经阅读设置切到横向才能缩放；现在同一画面内完成。图片是主角，现有顶部/底部控件与操作区维持原尺寸和Paper样式，冻结原型不改。

连续列表按本次会话的1–4倍比例布局每张图片，左右移动限制在图片边界，纵向仍由真实ScrollPosition处理拖动和惯性，可以连续跨图。没有把整个视口放大，也没有创建全包巨图。双击已显示的图片切换2倍/原比例；失败图片的重试、跳过和末尾操作不参与双击识别，避免等待双击判定或误触缩放。

捏合开始以手指下的稳定页ID和页内位置作为锚点；改变比例后把该内容放回移动后的手指位置。横移也以同一焦点计算。两指增减时重新建立手势基准，放开其中一指后可以直接继续上下/左右移动。最小宽度适配不小于原比例；图片间距和末尾操作区不放大。

缩放和自动重排不调用阅读位置写入。只有主动纵向拖动/后续惯性才按现有规则记录当前页、页内位置和末尾状态。放大比例不写服务端偏好或续读标记。返回先复位，再沿既有返回规则离开；复位保留当前视觉位置。切模式、跳页、换包和整理后的代次变化清除旧变换；阅读器存续期间允许设备旋转，离开恢复应用原来的竖屏约定。旋转按视觉页ID/页内位置重新排布并复位比例，避免以旧列表像素偏移跳到首图。

窗口扩展/裁剪按稳定页ID恢复位置；恢复在窗口边缘时仍会只读加载相邻清单，这与保存阅读进度分开。元数据最多120条，ReaderImages仍限制6个provider/48MiB估计预算及原解码尺寸上限。捏合不加载整个图包；图片失败继续沿用原读取/重试/跳过协议，不自动重发阅读写入。

直接操作随手指即时响应，松手后的移动使用原生滚动惯性；双击和返回复位沿用横向阅读器的即时切换，阅读设置和其它控件继续使用已有Paper转场与按压反馈，没有为这次功能另造动效系统或提示文字。

检查分别覆盖上限/下限、双击、横向移动和纵向续读、单指转双指再转回单指、返回复位、退出重开读回、深位置旋转、跳页/横纵模式切换、500条页清单的窗口加载与淘汰、缓存上限、窗口边缘续读，以及末图缩放不误记完成。实际资产解码和合成元数据分别说明，不能把组件里的500条清单当作真实500张高分辨率图片或NAS性能。

回归包含原横向翻页/RTL/缩放、默认纵向与旧横向偏好、坏图跳过、整理和8秒撤销的既有用例。尚需普通Android包上的真实双指/旋转、500张实际公开样本、坏图/缓存/整理连续操作和目标手机体验，并与分目录页面一起验证新旧服务。当前没有将本候选部署到NAS。

实现阶段自检未进行独立视觉评审。普通code24已有原签名覆盖、分目录页面、双击/返回、真实双槽输入捏合、横向平移及纵向跨图片的公开夹具画面和业务比对；不能把当时未成功发生的旋转命令算成旋转通过。当前源码完整832项、相关37项三轮与分析通过；修正后的code25已完成24→25覆盖、同页/偏移续读、真实双槽捏合/横移、2400×1080横屏→1080×2400竖屏、返回/冷启动及A单独重扫的基础操作；完整组合仍待补齐。NAS交付仍为code22，本地候选不等于已分发到NAS或真实手机。
