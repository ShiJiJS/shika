# LF8：真实旧服务数据升级与停机回退

基于[预览包 PR #92](https://github.com/ShiJiJS/video_viewer/pull/92)，继续UP-01/02。使用已固定cf992025的正常release APK6及runtime镜像，实际旧8760服务镜像ID作为旧版；所有容器、数据副本与AVD均独立，不部署真实NAS。

先复用上一阶段已停止的schema0004独立旧服务数据副本。使用旧服务公开接口准备非空视频／原标签及关联／播放范围／逻辑回收站／文件请求回执；撤销准备凭据后，保留原App安全存储的登录凭据。正常App读取旧服务，停止App及服务，再完整备份独立data目录和配置；记录全目录哈希，不把只复制活动SQLite主文件当作可回退备份。

同一独立端口和data目录切换到预览runtime镜像，由正常启动执行0004→0014迁移。验证自动迁移前快照、完整旧列投影、旧视频／标签／ID／播放范围／回执，以及旧凭据首次绑定管理代次后仍可用。启动扫描等允许改变的字段需明确记录，不笼统声称整库不变。正常APK冷启应进入新媒体库、不自动播放，能读取旧视频、独立图包入口和回收站；通过UI创建升级后标签作为回退标记。

回退前停止App和新服务，保留升级后数据用于诊断，将完整升级前data快照恢复到原独立路径，再启动原旧镜像。禁止用旧服务直接打开0014数据库。验证恢复目录与备份字节一致、实际旧服务可读、原token无需登录、旧视频／标签／回收站／原回执保留，升级后测试标签消失。计划重复三轮同一公开样本的升级／回退，不将重复样本等同不同数据库或真实手机/NAS验收。

仅在自己的新阶段副本内执行回退替换；上一阶段原始证据数据不改。文件摘要、实际PID、请求路径窗口、原生截图／语义、镜像身份、各阶段schema和清理记录一起保存。目标手机／NAS、App高版本号回退包、500页4K/8K与#89/#78等开放项继续；本段成功也不关闭#24/#33。
