## 实现与实际流程

视频／图包独立回收站沿用 Paper 全高度页头、20dp 边距、名称／完整路径层级、左侧勾选、逐行恢复和“已选→恢复所选→永久删除”。短列表动作紧随内容，长列表有可见收尾，键盘或极短高度时进入正文滚动；保持实际系统字号和安全区。真实 24 项分页、搜索、刷新、读取失败保留、原请求核对与任务详情继续可达。

每个最终轮次只重置专用 8761 公开夹具：27 包、81 张实际图片；通过生产阅读器写入首包阅读位置／偏好，并建立标签与独立视频范围。准备完成后请求记录清零。实际视频回收独立；图包读取 503、重试、搜索零结果、真实 IME、跨页全选27排除1、第二页、暗色、确认取消均走实际 App。确认26整份恢复后故意丢回执，只 GET 原请求一次；返回列表清除对应26个选择，再逐行恢复剩余1个。逐行取消仍无写入。81张源图片的精确路径/SHA在15个检查点相同，原首包阅读位置／偏好／标签、当前完整视频响应和视频回收总数由原生断言核对。

原请求核实前保留真实选择，界面显示“保留选择26”和明确待核对说明，阻止所选内容的重叠恢复／永久删除；未通过清空请求或取消跨页选择消除显示差异。原请求回读后只释放该请求成员，稍后选择的其它内容保留。逐行恢复标题为“恢复1个图包”，与批量“恢复已选26个图包”区分。后台恢复仍沿用既有原请求、固定成员与受理协议。

`checks/` 的47项相关客户端检查连续三轮通过，另含analyze、Dart格式和Ruff；范围是回收站、选择、原请求与保留的永久删除组件，不是客户端或服务端全集。服务生产源码与#69相同。`verify.py`只读核对15×3窗口/原始图、两次恢复POST(503/202)、精确26+1不相交成员、唯一原GET与请求哈希、SQL完成计数、81源SHA、固定源码与显示恢复，并核对manifest全部输入。

`reference/` 是真实浏览器390×844参考及源SHA。`review/`保留首轮冻结2问题/1提升清单及各次复核，普通／大字／横屏与补图的可见项已静态闭合；不以静态图证明协议、手势或动画。原生取证无HTML lint，不声称完整动作录屏。主题、源名、搜索、分页和真实状态有必要差异，不为贴合合成条目删功能。

`supplement/landscape/`是同生产88a45ec的独立补图轮：由原主流程前缀及单列tail生成临时测试，走到26包恢复丢回执，在unknown实际滚到动作区，核对保留选择、说明及两项禁用动作完整边界。11张上下文图仅计最后1张页尾补图，不覆盖或重计原45点。补轮只有一次明确26恢复POST(503)，零原请求GET／重发，81图片SHA与完整视频响应保持，显示恢复；源生成器、tail、生成测试与各自SHA全部归档。原生断言另检查实际按钮回调为空，静态评审只认证外观。

## 基线与失败边界

`baseline/`保留调整前b520486的9点首阶段截图及原日志：该首阶段通过TRASH_BASELINE_VERIFIED；旧runner误启动第二阶段、未重置夹具，预期27实际0，整体runner失败。因此它仅是调整前的9点静态基线，不能算成功完整运行。第二次APK编译期间生产已开始修改，但失败于准备阶段、没有覆盖首阶段PNG；初次source.json固定首阶段字节。后续runner修为单阶段。

`diagnostics/`分别保留原生初轮的真实旧选择未释放问题／空态脚本断言错误、修正后普通中间成功样本、大字键盘焦点丢失与惰性分页脚本错误，以及末项恢复后过早查找刷新按钮的等待问题。前者已按原请求成员释放选择；焦点问题由稳定ListView视口类型修复；原生等待分页改为先等读取完成再滚到真实页码。失败不累加到最终检查点。旧组件FakeAsync准备队列问题只在测试夹具中修正，未为通过测试改变生产异步语义。

本阶段使用MemoryCredentialStore，不新增安全存储或真实进程强停证明；未执行真实永久删除，不替代原精确图片清单协议及既有独立证据。完整备份/任务管理、永久删除复核与部分失败、其它视频/阅读异常和手势、500页4K/8K、目标手机/NAS及原签名覆盖升级继续在台账开放；需配合部分按授权暂跳过。backup_v2仍关闭，未发布APK或修改正式8760/NAS/SDK。
