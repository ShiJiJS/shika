# 目录类型、启停与图包缺失管理证据

基于 [Draft PR #47](https://github.com/ShiJiJS/video_viewer/pull/47) / [设计契约](../../LF7-ROOTS-MISSING-DESIGN.md)。正式轮次由 `source-sha256.json` 固定源码，结果见 `verification.json`；运行 `python3 docs/plans/library-first/evidence/lf7-roots-missing/verify.py` 独立复核全部检查点、真实请求、数据库统计与源文件哈希。最终运行结果记录在下方，诊断不计入成功轮次。

## 实际路径与不变量

隔离8761服务、API36 Android模拟器，每轮实际通过App设置表单新建图包目录、停用和启用，然后发起新的扫描任务，入库27包81张公开花卉图片。实际读过一个包以冻结偏好、写进度和最近，并关联一个独立图包标签。编辑目录尝试改成视频类型时服务端拒绝，表单保留名称、路径及选择。

夹具只移除本轮生成的25个图包文件夹，重扫后得到25个缺失包，页面24+1分页。目录停用时，取消清理不提交；确认后的任务保留全部25项及标签/进度。重新启用后夹具恢复其中一包的一张图片，不重扫：第二次确认清理只能清24个失效元数据，重新出现的一包保留。原文件执行器没有介入，源字节没有因清理被删除、移动或改写。

第二次清理真实受理后将响应替换为503，App保留生产安全日志中的原request_id。销毁/重建App和Repository，用专用测试键从真实Android安全存储恢复连接与日志；重新进入只展示原请求，明确点击查询才发一次GET，不重复POST。任务中心核对25项、24清除/1保留及24+1分页，并展示“内容已重新出现，请同步后核对”的具体原因。旧包墓碑与固定会话成员保留，标签关联、进度、偏好和最近清除；实际原视频预览范围完整JSON保持不变。

每轮9个原生截图及匹配的请求/图片SHA/数据库统计，独立核对包括：前三个检查点81图片不变；夹具移除25包后保留6张原图片；恢复一张后7张文件持续不变；两次POST202/503只对应两个原父任务；重开没有自动GET/POST，明确核对只GET第二个原ID；没有新视频范围、回收或永久删除写命令。1003成员范围的检查为服务端生成元数据的有界任务/分页验证，不冒充1003个物理图包的NAS性能。

## 安全回归与失败来源

补充扫描后同路径目录替换的回归：最初的红色探针证明，只在执行时比较两次当前目录身份会误清旧记录。修复后，清理必须匹配最近成功扫描在同一事务保存的本机根目录身份；受理前/后替换、缺失/损坏/时间不匹配的扫描证据均保留，明确重扫后才可清理。缓存不导出到管理备份。服务端还覆盖离线/停用/未扫描/返回/符号链接、固定范围及后续新缺失排除、逐成员服务重建继续和历史任务不运行。

`diagnostics/`保留早期路径/HTTP覆盖/定位等测试失败、旧迁移末版本断言0012需更新0013的311通过/1失败回归，以及原生失败。大字号实际发现键盘挡住提交，表单在类型/启停选择时收起键盘；随后原生定位还需在键盘inset变化后滚动到按钮中心，保留失败截图。扫描等待改为核对新任务ID，避免读到前次ready。任务详情的“全部”列表惰性构建分页尾部，测试须滚到真实下一页后再核对25项；没有删除业务断言。

宿主图形模拟器确曾因图形缓冲错误退出139，ADB断开；该轮不通过。改用软件渲染后继续，禁止崩溃报告上传，未改SDK。正式源码固定前的一轮在按钮中心尚未滚入裁剪区时失败；期间另补保留原因的文案映射，源码守卫也正确拒绝把这轮算作最终源码。各次中断与preflight保留，不混入正式三轮。

并发回归时，27包/81页的原生扫描未在原测试40秒内结束；之后读取同一任务确已completed、27包81页且无失败，保存于`diagnostics/contended-scan-timeout/scan-after-timeout.json`。只对原生“等待新扫描完成”设置120秒上限，其它等待仍40秒；必须核对新任务ID、完成状态和实际27包，未取消断言。正式轮次在其它完整回归结束后串行运行。

随后一次在准备夹具时出现“Software caused connection abort”，清理视口的ADB也超时。宿主8761健康，但两次设备TCP探测无响应、后续ADB子进程超时；QEMU进程仍存活，不能据此称为进程崩溃。再次尝试尚在加载时，主Agent主动终止专用测试模拟器以恢复网络，因而该次设备断开/非零退出是恢复动作造成，另存`native-network-recovery-interrupted/`，不混算功能失败或成功。随后冷启动同一AVD，软件渲染、无原生窗口且不发送崩溃报告，SDK及App源码未因此修改。

TCP空响应探针的stdin/EOF行为未独立验证，不能单凭它认定NAT故障；`network-check.json`明确这个诊断限制。恢复动作依据实际App连接异常和ADB退出清理超时，而非据探针声称已查明网络根因。冷启动后以真实Android流程重新验证连通性。

冷启动轮仍实际出现Pixel Launcher/System UI的ANR弹窗，截图直接显示遮挡；该轮同时因目录保存连接错误失败，归档在`diagnostics/launcher-anr/`。主Agent确认当前系统ANR窗口后停止专用AVD的Launcher，并在实际可访问树中定位System UI弹窗的“Close app”按钮，关闭该无响应系统进程以重启；随后前台恢复Launcher。操作与焦点另存`controlled-recovery.json`。没有禁用ANR提示，也没有据Flutter控件能点击就算屏幕可用。新宿主守卫对本阶段每个截图保存`-window.txt`，当前焦点必须属于App，系统弹窗或其它应用遮挡直接使宿主验收失败。

## 运行结果

客户端全量369项、analyze及变更文件Ruff通过；新增服务端15项针对检查通过。服务端全量运行1010.83秒，316项通过、1项旧视频范围检查在扫描62个视频时触发30秒夹具超时（当时53个已导入、零媒体错误）。同一源码和原断言的失败用例随后单独运行，13.54秒通过，未改其测试或超时。全量与独立复跑日志分别保存；这里不把两次结果写成“一次全量317通过”。保留1条既有Starlette弃用警告。先前无根身份修复的312项全量结果不代替当前结果。

固定源码59f78b6正式三轮全部退出0：360双倍字号308.89秒、390普通138.03秒、390普通197.17秒。独立`verify.py`已通过，核对27个检查点的请求、文件、数据库统计、App前台窗口和源码SHA；结果见`proof.json`。每轮均保留25项、清24项/返回1项、2次明确清理POST与1次原回执GET，原视频范围保持。各轮APK的构建SHA分别保存，不要求不确定性构建产物字节相同；运行源码和服务端契约固定。

模拟器最终恢复1080×2400、420dpi、字号1，SDK工作区干净、冻结原型树与design-lf-2026-10-23一致。`evidence-sha256.json`索引除自身外全部证据；`runner-used.py`保留当次宿主编排脚本和当次绝对工作区路径，复跑命令亦见`verification.json`。

## 继续范围

本次App/Repository重建在同一Android进程内，不是强停进程；服务端成员恢复测试也是正常关闭/重建，不是SIGKILL。其它命令/来源及强停组合仍需后续证明。软件渲染模拟器不代表目标手机或NAS性能。SET-04其它目录/视频首扫组合、全部深浅色横屏与手势、历史图片错误根因仍待LF8。

主Agent查看了本阶段实际普通/双倍字号截图，长管理页、短编辑、错误保留与分页位置可核对；没有开展独立视觉评审或全原型像素验收。保留两项具体复查：新建目录尚未扫描时仍沿用“目录暂不可用”字样，应在LF8统一未扫描/离线提示；任务详情的SelectableText编号在部分普通/大字号截图中缺字或裁剪，需区分实际渲染与采集时序并修正。任务身份本身由原回执/数据库/接口校验，不据这几张截图宣称该文本视觉已通过。
