## 逐项故障与恢复范围

- 正常确认只删精确图片，附件保持；空图包目录移除，含附件目录保留。结果分页分开呈现图片/目录阶段。新内容重新出现旧路径，扫描创建新ID且不继承旧标签。
- 清单后新增图片/附件、替换同内容不同inode文件、修改签名、替换包/子目录和链接均在未删图片时停止；认领期间改内容、改附件、新增文件也保留变化内容。暂存位置被替换、原位置被新文件占用时不覆盖或误删，保留待处理。
- 原位置冲突用例保留两份内容并保持needs_attention；测试随后明确移除外部新增冲突文件，再重试原任务。服务没有自行删除或覆盖冲突文件，不能据此宣称所有冲突均自动解决。
- 中途权限失败时归还可安全归还的文件，已删除页单独归档并退出可读清单；测试验证剩余图片能恢复及重新扫描。执行器未删除标签/阅读偏好等记录；非空阅读状态的完整原生恢复留给App接线验证。扫描不被历史page_id外键阻塞。
- 字节已移除但归档未完成时，报告待核对页而非成功/部分成功；保留互斥，禁止恢复或扫描掩盖未核对状态。明确重试原任务补归档，再处理未完成项，计数不重复。已提交页不因后续异常被改写成失败。
- 一个包变化不阻止独立包完成；严格确认拒绝false、字符串、数字和缺字段；过期/错误摘要拒绝受理，已受理命令不因排队过期取消。单计划只消费一次，已受理请求在管理门禁期间仍可只读查询，不排新任务。
- 物理读取/认领期间仍能读取信息/回执及创建无冲突标签，证明文件IO不占全局数据库写锁。受理后重新核对目录启停和历史状态。
- 永久删除受理使它所属旧逻辑回收的8秒撤销失效；其它无关图包最新撤销继续有效。同键回放只返回原任务，不再次改变撤销因果顺序。`undo-compatibility.log`为两项收尾加19项既有逻辑操作，共21项通过。

## 合作式中断与实际SIGKILL分别验证

10个合作式中断/关闭重建阶段包括claiming、claimed、verified、purging、unlink后归档前、图片归档后，以及目录claiming/claimed/removing/rmdir后。它们使用InterruptedError和实际SQLite冷重建，不称作进程强杀。

`process-and-regression.log`在当前dd2dcf3又单独跑过9项：以下两条真实TCP/HTTP路径各3次，另含快照并发和两项撤销兼容。每次使用独立临时管理库/媒体树、随机本地端口、独立uvicorn进程，确认Popen.kill后退出码为-9，再启动生产create_app，使用原token与GET原request回执恢复。

| SIGKILL位置 | 三次结果 | 核对 |
| --- | --- | --- |
| 图片已unlink/fsync、数据库尚未归档 | 均完成 | 原操作ID，pages_deleted=pages_total=2，附件仍在 |
| 空图包根目录已rmdir/fsync、目录步骤尚未归档 | 均完成 | 原操作ID，两页计数不重复，图包目录仍已移除 |

恢复先查询原回执；完成后另显式重发原负载只为测试幂等，仍返回同一任务，不把这一POST当作客户端自动重放。当前App还没有调用该物理接口，不能据本测试宣称Android命令日志/强杀重开已验收。

## 已保留的失败诊断

`diagnostics/interruption-before.log`为中间开发状态：InterruptedError被其OSError父类分支接住，10个中断用例误报失败，后来拆分异常路径；另1个旧迁移测试需要按旧列投影核对新增列。这是开发诊断，不是最终源码通过证据。

初次260项全量有259项通过、1项失败，见`diagnostics/server-before-snapshot.log`及该次源码SHA。失败实际发生在清单准备查询，不是测试名所指的目录恢复：SQLite独立SELECT读到旧plan.digest和新Task.completed。`snapshot-before.log`随后用同步屏障稳定复现同一矛盾结果；修正为同一SQL读状态/摘要后，确定性回归及最终264项均通过。红灯日志是中间状态，不冒充当前源码；最终来源以根目录manifest为准。
