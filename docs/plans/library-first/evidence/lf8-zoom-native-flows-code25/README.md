- **复位与续读：** 长距离往返后控件仍可见，Back先复位并留在282/500；35张业务表、设置键摘要及凭据摘要完全保持，没有额外写请求。强停后新PID启动先到媒体库，重新从库中打开仍读回相同页ID/偏移/未完成状态。重开先取offset280/40，再在窗口边缘只读补240/40；重开本身的revision/打开时间变化单独记录。
- **长宽图和手指交接：** 新增5张仅供开发的网格图，包含600×6000长图、6000×600宽图、竖图、横图和8000×8000方图。根据实际getevent设备信息向virtio多点设备的两个输入槽发送真实Android手势。长图捏合后只显示部分放大的网格；单指→双指→松开一指后继续移动，网格能跟随剩余手指上下移动；缩小后恢复完整宽度。只有主动纵向拖动改变pack_progress/request_records，捏合与缩小分别保持全部35表和设置摘要。

## 请求、内存和检查边界

requests.jsonl来自本机只转发至本机服务的观察代理，不记录请求体、认证头或图片内容。Dart的chunked请求最初被观察脚本漏转发而产生422，已修正分块读取；原诊断留存，已知错误口令的401仅用来确认分块JSON确实到达服务，不计入App操作。最终trace共708项：685个200、5个201、7个202、8个无播放范围时的/playback 404、2个封面503及上述1个探测401。两个封面路径稍后分别读回200，详情见http-summary.json；错误响应体未采集，不臆断503具体原因，不宣称所有请求都成功。

每次清单40条和旧窗口重新读取有原生请求证据。精确120条元数据、6个provider/48MiB估计缓存、1–4倍上限来自原代码及组件断言；本轮没有在普通APK中注入内部计数器，不能把dumpsys的整个进程PSS等同于图片缓存预算。memory/保留实际检查点原始输出。这些低复杂度合成PNG及8K尺寸检查，不代表500张高分辨率照片的性能、真实NAS速度或手机内存表现。

table-comparisons.json按每张表固定前后行数与摘要，原始全表快照仅保留在私有.dev。读取均在唯一所属容器内通过SQLite mode=ro进行，没有在宿主打开活动数据库或导出WAL。主Agent已查看保留的长页、网格、坏图、撤销、返回和覆盖画面；现有Paper控件尺寸保持，没有独立视觉评审。冻结原型树1cbf605保持。
