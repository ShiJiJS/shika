## 实现与组件

24个总览单元格原本可同时打开24连接。在实际HTTP容量夹具中，两个新增基线均失败：取消场景150ms已有14请求；健康接收端最多同时处理3个时，峰值24、63次请求仍未全部解码。原始日志见diagnostics/before-capacity.log。本段仅生产reader_thumbnail_image.dart增加共享3许可的下载队列，每项仍独立拥有客户端；等待时不创建socket，关闭／换页移除排队项，已开始的中止连接，成功／错误／取消均释放许可。默认服务media_streams=4，给主图留出一个位置；未据此宣称所有自定义服务上限均无忙碌。400／800ms两次重试预算未增加。

新增两项组件实际验证24张全解码且无容量拒绝、3下载＋21排队取消后无后续请求；连同既有缩略图身份／手动／鉴权、传输、阅读错误与布局共24项通过。分析／格式／Ruff通过。控件、三列比例、选中样式和原型树1cbf605未改；原型继续独立可移除。

## 三轮30页图包

normal-1至3分别来自开发输出pagination-native-3／4／5。目标包30张由6份公开合成SVG光栅循环生成独立文件，另外3包各6张、2公开视频，共50源文件，逐轮前后SHA一致。序号与ID唯一，不能用重复图案代替成员身份断言。每轮都在实际生产App与服务中：

- 打开第3页再进总览，第一页24个独立单元格已挂载；3个响应仅发PNG前16字节并保持，其余21项排队。
- 实际滚动到页尾点击“下一页”，清单GET offset=24保持未完成；此时3个旧响应全部取消，21项没有到服务端，旧格active全部false。释放清单后，25–30六张实际解码；上一页返回后1–24全部实际解码，健康阶段缩略图均200。
- 再点下一页并保持清单未完成，真实Android返回仅关面板；服务端清单取消事件成立。重开显示原1–24，当前仍第3页／横向模式／原固定范围，API完整图包详情相同，无新增非GET。
- 之后进第二页，明确点第30页才新增一次PATCH进度（同范围、正确page_id、completed=true），服务API读回第30页；主阅读画面已目测实际合成图06、30/30，再返回媒体库。

## 六图故障回归

six-cell-regression为同生产树的新驱动8点：六张注入首个503后均自动恢复；持续503每页恰3次，等待后无额外请求；逐张手动恢复。pending时3个下载＋3个排队，真实Android返回后3流全部取消且排队项无GET，重开六张成功。范围／当前页／模式／API详情相同、总览无新写入，26公开源文件SHA不变。此前#84的“6在途”是其旧无限并发实现的真实记录，这里明确不沿用该旧预期。
