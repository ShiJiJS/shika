# 当前视频预览：原生手势与生命周期

对应[实施范围](../../LF8-PREVIEW-LIFECYCLE.md)，基于PR #76，提交至[Draft PR #77](https://github.com/ShiJiJS/video_viewer/pull/77)。本段为当前媒体库→二级预览完整链路补证；生产App、组件测试和服务业务树与605badb一致，未改布局或SDK。驱动加入控制器身份和每次切片的真实控制器状态，宿主补ADB系统操作、旋转分段录屏，以及录屏回收失败后仍继续环境/容器清理。最终采集源码98507ea。

使用独立127.0.0.1:8768和受守卫约束的合成目录；只在专用preview-lifecycle夹具变体启用第三个视频（复制现有公开横屏样本字节，不新增私人素材）。其它原型场景仍2视频/4包。每轮3视频/4包/24PNG，共27个源文件；准备后前后SHA相同。测试从真实媒体库入口进入，实际范围面板明确选顺序并点库中第一项，尊重生产的服务端默认与当前锚点规则，不靠改默认令断言成立。固定3成员/序号经API与只读SQL分别核对。

每轮检查：暂停和真实进度轨道拖动，选择1.5倍；真实旋转进入横屏全屏，同一控制器身份、暂停位置和基础速度不变。恢复播放后左右手势改变实际窗口亮度/媒体音量，按住临时2倍；宿主发送Android Home，App在合法inactive→hidden→paused后释放全部网络播放器，前台重建并继续暂停/恢复1.5倍及窗口亮度。宿主系统返回先退出全屏，原预览/范围保留；普通预览再执行一次Home/前台。六次1600逻辑px/s fling依次到1/2/1/0/1/0，逐次记录当前可见VideoPlayer、三个真实控制器及音量/播放状态，并分别记录UI播放请求与原生状态，并确认暂停意图下不播放；中间项必须恰好当前及前后共3项，至多当前一项playing且volume>0。设置真实开关关闭相邻准备，再从媒体库进入新固定范围，实际上下切片时只保留1个控制器；两次离页全部释放，最近记录仍3个实际看过的视频。

抽查实际原生画面发现：关闭宿主视频解码后，横屏视频右侧有明显绿条。相同App生产树、同源视频字节在早期宿主解码截图没有该条；原图与对照保留，不裁剪或改素材掩盖。当前仅能定位到不同解码路径的关联，不能据此证明SDK、插件或App的具体根因。此项由[渲染问题 #78](https://github.com/ShiJiJS/video_viewer/issues/78)继续处理；即使行为三轮通过，UI-02画面完整性仍未通过。

证据包括每轮15个保持的前台截图/窗口/内存点、Dart原始日志、ADB操作回执、逐次切片状态、候选API、SQL投影、HTTP请求、媒体SHA和旋转分段录屏。控制器identity为运行内Dart对象身份；后台释放另有明确空集合检查与新身份，不将数量调用替代实际解码/播放。音量/静音按实际原生控制器和AudioManager读回核对，不声称做了扬声器声学测量。七次fling在每次稳定后继续，不声称覆盖重叠初始化或迟到回执竞态。

最终使用同一API36 ARM64 AVD（video_viewer_api_36）、390×844/DPR3/字号1，实际横屏2532×1170物理像素。模拟器software GPU/headless，并按本机SDK advancedFeatures.ini公开的HardwareDecoder功能关闭宿主视频解码；启动参数与属性在各组environment.json，SDK功能定义和Flutter版本在checks。App没有Skia等渲染覆盖。该环境不同于中间宿主视频解码尝试；软件解码/debug和小型公开视频不代表目标手机/NAS性能、硬件解码器容量或真实视频格式兼容矩阵。

screenrecord按实际横纵尺寸分段；切换期间可存在缩放/留黑与段间缺口，不声称无缝录制。ffprobe检查编码/尺寸/帧数，并以保留输入时间基的ffmpeg全帧解码，结果由checks/recordings-decoded.json及复核脚本校验。dumpsys meminfo保留原文，仅作检查点观察，不给出过程绝对峰值或性能通过结论。第3轮初播放截图点记录到一次UI请求播放而原生isPlaying=false的瞬时样本；前置ready与之后的实际播放/切片已通过，样本原因未确定。请求播放与瞬时原生状态不作恒等，暂停意图下必须不播放；该样本在verification中显露，未删原始状态。

本段未新增设计方向/独立视觉评审，不把真实旋转与录屏当作所有字体/主题/像素对照已完成。
