# LF8 独立视觉评审

评审类型：存量已有界面润色，只对齐冻结原型、Paper 与 LF4 设计记录，不打分，不提出新风格。已阅读 reviewer-manual.md 和 LF4-DESIGN.md；实际查看八组 compare 图，以及 home、video-tags、settings 的 overlay 图，并核对 metrics.json 的视口与文字坐标。未读业务源码，未改代码，未执行原生操作。

## 速查清单

- [本轮修正 1] 设置偏好区：开关明显大于参考，“准备相邻视频”说明由一行变两行，使下方条目继续下沉 → 恢复参考的可见控件比例和文本密度，保留足够触控区，底部阅读偏好达到参考可见程度。
- [本轮修正 2] 标签确认区：视频标签底部区起点比参考提前约 35dp，图包标签提前约 10dp，视频两行信息之间尤其松散 → 两类标签确认区的层级、行间距与参考对齐，按钮与底导航保持现有稳定位置。
- [本轮核验 3] 暗色截图：dark-native 的开关已开而整屏仍浅色，dark-bottom-native 才为深色 → 等待主题稳定后重采同一滚动位置；若真实操作中持续不一致，再修主题应用，不能用当前静态证据判定已通过。
- [本轮小项] 标签搜索框比参考更绿、选中标签整行新增灰底，且主按钮绿色略有偏差 → 对照冻结 Paper token 确认是否属于已有组件的批准差异；不是批准差异的则统一。
- [迁移后续] 图包继续阅读摘要缺失、媒体类型计数缺失、图包作者与名称未分离、管理设置能力的完整性 → 登记完整原型验收，不应被本轮几何接近所掩盖。

## 本轮最影响完成度的布局问题

### 1. 设置偏好区的控件比例与说明密度尚未对齐

证据：settings、settings-bottom、dark-bottom 的右侧开关约 51×32dp，参考约 40×24dp；“准备相邻视频”的原生说明尾部“用”独占第二行。它下方的播放顺序和阅读偏好较参考下移约 9–11dp。settings 首屏中阅读偏好的说明因此比参考更难露出；底部截图中可以看到完整条目，未见被永久遮住的证据。

影响：偏好区显得比上半部分松，控制件抢占文字空间。普通字号也出现短尾换行，削弱已确认原型的紧凑比例。

验收：390 宽、textScale=1 时，普通副说明不出现单字尾行，开关可见轨道与参考接近，保留原生可操作热区；设置底部无需额外滚动即可达到参考相近的内容露出。不能靠缩小系统文字或压缩大字体适配达成。

可删减文字：相邻视频说明可去掉不影响决策的冗余词，使“前后各一条”和“关闭可减少网络及解码占用”的信息在参考空间内说清；“保存在服务端”是实现位置，若用户不需据此判断同步行为，可移至播放顺序详情。这是文案减法建议，不要求删除有效设置。

### 2. 视频标签确认区的内部留白偏大

证据：video-tags 参考的底部分隔线约 y=648，原生约 y=613；第一行“同时包含”明显上移，而预览按钮只比参考上移约 3dp。metrics 扣除 49dp 系统区后，原生第一行文字框始于 y=634，匹配数文字框始于 y=680.5，两行相距约 46.5dp；参考两行更紧密。pack-tags 的同一区分隔线约 y=638，对比参考 y=648，差距较小。

影响：视频页的匹配数量与选择条件关系被拉松，确认区更早侵占列表；视频与图包的共享确认行为也呈现两种密度。当前没有遮挡或读不清，但离参考布局有可见偏差。

验收：使用相同滚动与选择状态并排截图时，两类确认区的首行、匹配数、按钮垂直关系与参考一致；可见行不因额外空隙损失，且“清除选择”“查看结果”和主按钮的真实点击范围仍足够。截图不能证明热区大小，需另做触控检查。

### 3. 暗色状态的现有证据不完整

证据：dark-compare 左侧参考深色，右侧原生从顶栏、内容到导航均为浅色，但“暗黑模式”开关滑块已处于打开方向；dark-bottom-compare 的原生则已是深色。像素核对也确认了整屏底色差异，非叠图透明度导致。

影响：无法从本组材料确认开关状态与界面主题同步完成。可能是采到了切换中间帧，也可能有应用延迟；静态图不能区分。

验收：真实操作切换后等待稳定，分别重采浅色和深色的顶部、底部。开关与主题一致，顶栏、背景、分隔线、文字、底导航一起进入对应主题。若已有运行验证证明仅为截图时机问题，重采证据即可，不应为了这张图盲改主题逻辑。

## 共享组件的其他观察

- home 顶栏、搜索框和范围工具条没有明显纵向漂移；两列首封面都从约 y=207 开始，宽度和 211dp 高度符合设计记录。顶栏标题、页面左右锚线和底导航整体稳定。导航没有额外选中短横线，符合 LF4。
- 标签搜索框原生填色为更明显的浅绿，参考接近白；原生选中行还有参考未出现的整行灰底。搜索文字清晰，不构成可读性阻断，但属于可见组件差异。背景本身仅相差约 1 个 RGB 分量，无需将这种微差当作主要问题。
- 共享按钮绿色的实测参考约 RGB(88,102,73)，原生约 (83,102,74)。不建议重新选色，只需确认使用冻结 Paper 中的正确角色 token。顶栏更多、底导航设置图标的造型也不同，但从这些截图看不影响理解，不建议为个人图标偏好扩大本轮范围。
- 设置主标签相对多数非开关条目的 x=55dp，开关条目的 x=60dp，有约 5dp 差异。可在本轮密度修正时顺带对齐文字锚线，不要另引入一套条目样式。

## 应登记到完整迁移验收的产品差距

1. packs 参考在搜索与工具条之间有“继续阅读”摘要，原生直接进入数量与网格，因此首行封面从参考约 y=292 提前到 y=207。不是共享搜索/工具条本身高度错误。应由后续完整图包流程验收确认此入口与进度是否接入；目前不能称图包首屏已完整还原。
2. 媒体库视频/图包类型栏原型包含计数，原生只有类型名。若完整原型仍要求快速判断两类库存，应补齐；不要与标签页本来没有计数的类型栏混为一谈。
3. 图包原生标题被“示例作者 NO.xxx”前缀占满，真正作品名大多省略，次要行显示“6 张可读”而非独立作者。交接已注明命名未统一，因此本轮不把它算作几何退步；但实际用户需要辨认作品，完整验收必须覆盖长名称、作者分离和省略策略。文件后缀、示例 5 秒/真实 6 秒、排序和标签选择对象不同，均未被计作实现缺陷。
4. 设置入口可见：服务连接、媒体目录、回收站、备份与恢复、操作任务、暗黑模式、相邻视频、播放顺序、阅读偏好都在。没有看到“设置被大量删掉”的画面证据。但“备份与恢复”的副文案由原型的“标签、目录映射、回收站与阅读记录”改为“导出标签和管理记录”，媒体目录不再显示缺失内容数，回收站也不显示当前数量。截图不足以证明对应能力仍全，后续需要打开详情验证备份范围、恢复入口、缺失检查及回收管理，不能凭入口存在宣布设置能力齐全。

## 验证边界

未看到动效，也未运行点击、返回、键盘弹出、滚动恢复、大字体、横屏或真实触控。搜索、目录、范围预览、标签交集与两个来源的独立状态，只能确认入口及文字存在，不能声称操作流程已通过。settings-bottom 和 dark-bottom 的滚动距离也不完全相同，不应直接把所有纵向像素差都算成组件漂移。

保留：Paper 的克制纸色与墨绿、媒体库首行大封面的明确重心、固定四入口导航，以及“匹配范围—查看结果/预览”的清晰操作关系。

本次不打分。
