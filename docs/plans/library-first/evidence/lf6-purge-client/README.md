## 每轮实际核对

使用8761隔离公开合成花卉图包：27包×3张图片与27份附件，初始共108份文件。App从设置进入图包回收站，选择一个已逻辑回收的图包，核对包数/图片数/字节/附件保留，分页查看实际文件名。准备已受理后故意返回503，App GET原准备请求找回同一清单；取消之后全部108份哈希不变。

重新准备后必须重新勾选，再明确确认删除。夹具在 `2.jpg` 认领阶段触发权限错误，同时丢弃已受理删除的响应。App先显示未知结果，关闭后从待核对入口只GET原请求，确认已删2/3张、0包完成/1包未完成；现存106份内容哈希逐项与原始一致。回收条目说明“已有2张永久删除，恢复仅限剩余1张”，可重新打开原操作结果。

清除隔离故障后明确“重试原任务”，回到同一operation，最终3/3张完成，105份剩余内容哈希不变，27份notes.txt附件全部保留。每轮仅有2次准备POST、1次永久删除POST和1次原任务retry POST；删除响应未知到恢复结果之间没有第二次删除POST。最终待核对日志为空。`verification.json` 从原始文件/请求再次核验计数和仅移除的三个相对路径。

组件与协议另核对：过期/更新清单和连接切换禁用确认，关闭时的迟到准备不发布；1000包单批处理后其余27包继续保留选择；物理命令先写日志再POST，丢失响应后用新日志实例只GET恢复；成员/计数/路径/签名不完整拒绝；needs_attention保留命令和互斥，旧结果的确认不能清掉稍后受理的重试记录。没有记录的只读核对入口也不自动POST。
