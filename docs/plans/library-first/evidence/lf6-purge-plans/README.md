## 来源和运行

`source-sha256.json`覆盖97份服务端源文件、迁移与测试，已逐项核对本次运行文件及bdbd741的Git blob。`server-full.log`保存最终完整214项/Ruff结果；测试在禁网、只读源码挂载、/tmp临时盘和64MiB共享内存的既有Linux容器里运行，Python3.13.16/pytest9.1.1。保留Starlette/httpx弃用与pytest未知cache_dir两个既有警告，没有关闭断言或跳过失败用例。

新增32项精确清单检查，均通过公开FastAPI路由/SQLite及可丢弃图片树；使用TestClient的进程内HTTP，不称作真实TCP故障、Android或NAS实测。验证范围包括：

- 精确page ID/路径/签名/大小/SHA、目录树与图片明细分页，附件及空目录保持；准备前后字节树一致。只生成准备记录，不创建实际删除操作或文件步骤。
- 相同键/选择读原任务，不重复准备；同键改选择409，混入pack ID/不存在ID整体失败、不留半个任务；所有新接口鉴权与分页上限有效。
- 新增未索引图片、同内容不同inode替换、内容/时间改变、索引哈希伪造、缺页、目录替换、路径越界/穿越、链接/FIFO均不发布可确认摘要。目录树项数/深度超过上限会失败，不截断后报成功。
- 哈希期间/完成后改图片或附件、准备中恢复图包或改变根授权均拒绝旧清单；独立根和排除目录只记保留scope，未深入读取它们的图片。
- 暂停哈希时仍可读取信息、任务和创建图包标签，证明未持有数据库写锁；回执查询不排新任务。失败包与成功包同时存在时整份digest为空，不能用成功前缀冒充整份确认。
- 服务端15分钟期限、过期回执不延长；关闭并重建服务只恢复queued/interrupted准备，清掉旧进程中间数据，ready清单不重算或重置期限。不是SIGKILL或Android安全存储重开。
- historical清单仍可读但不ready、恢复启动不排队；正式备份v2将计划标为historical及管理代次隔离仍由LF7接线，不能据该标志测试宣称备份已完成。
- 从0009实际合成图包扫描/逻辑回收的非空管理数据升级0010，逐表核对所有旧列值；现有迁移前快照、外键/静态模型校验和旧视频/回收/阅读回归保留。

## 批量清单的摘要读取

明细按包持久化和处理，计划提交不先把所有包的完整source聚成数组；进度与结果查询只读独立的名称/路径/数量/大小/摘要/错误列。最终管理数据核对流式读取单包源快照，重新启动用SQL清理中间记录，避免装载所有manifest。

`memory-summary.log`用一份合成的8万条持久化明细（27,922,499字节）检查汇总API，包含进度更新和HTTP结果读取。实测新增Python分配峰值65,296字节，响应小于4096字节；上限断言为4MiB，若加载整个JSON会失败。它仅验证摘要读取，不是8万张真实扫描、实际删除、进程RSS或NAS性能指标。完整214项中也包含该用例。
