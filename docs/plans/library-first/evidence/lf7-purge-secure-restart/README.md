固定测试源码 `b8c823b`，基于 #44，见 [Draft PR #45](https://github.com/ShiJiJS/video_viewer/pull/45)。完整三轮均退出0，分别283.58、328.94、334.18秒；`verify.py`已独立核对全部进程、请求、成员和文件，结果见 `proof.json`。第一段均为受控强停的预期非零中断，只有重开段实际通过且独立证据吻合才记整轮通过。

## 两段真实进程流程

每轮从隔离8761重新生成1003个公开花卉合成图包，每包1张JPEG及1份notes附件，实际扫描并建立索引。扫描超过客户端单次两分钟等待后，再查询同一任务；原始轨迹与测试均验证扫描POST只有一次，没有直接写入索引来缩短准备。

第一段使用生产 `SecureCredentialStore` / `SecureFileCommandStore` 适配器和独立测试键。回收站全选1003，精确核对并明确确认第一批1000，批次上限仍为生产1000。已受理的POST故意返回503；测试断言原命令、整份选择与剩余3包已写入真实安全存储，再保持测试未结束，由宿主终止活跃Android PID。服务端受控门在首张图片认领之前暂停，强停后才释放。

宿主证明旧PID消失、App缺席期间原批次完成1000包、完成时App仍无PID。第二段启动新引擎，不输入口令，使用真实安全存储恢复同一请求和选择，原任务ID仍未知；通过任务入口只GET原回执，查看1000条真实结果的下一页，再从本机选择入口打开剩余3包的新清单。新确认框默认关闭，取消后没有第二次永久删除POST。

第一次2006个原文件（1003图、1003附件）；App缺席期间仅删除已确认1000张图，剩1006个文件。原1003个回收ID严格分成已提交1000和未提交3；删除路径必须正好对应原1000成员的图片，1003份附件与余下3张图的SHA保持。每轮7个检查点包含截图、请求、文件哈希和SQLite只读状态摘要，另有App缺席时的独立状态/文件快照。

## 中断不是通过

第一段特意不结束测试，宿主必须在收到明确标记后验证活PID并强停。其非零runner退出，以及did not complete / No tests found / Flutter临时目录清理错误按原样保留，是预期中断，不是测试通过。只有第二段实际All tests passed、PID不同、原请求及精确文件结果核对后，整轮才能通过。未修改SDK断言、关闭异常或把模拟器意外消失算为强停。

正式轮次为360双倍字号、390普通、390普通；命令、用时、源码和重开APK SHA见 `verification.json` / `source-sha256.json`。在仓库根目录执行 `python3 docs/plans/library-first/evidence/lf7-purge-secure-restart/verify.py` 可复核全部轨迹、成员分区、1000张删除路径、1003附件、24项之后的服务分页及源码哈希。`evidence-sha256.json`索引除自身外的完整证据。
