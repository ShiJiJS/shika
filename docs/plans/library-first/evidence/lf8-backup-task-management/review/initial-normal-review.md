## 问题

### 问题 1：取消保存与保存成功的持久状态没有区分

**位置与观察证据：**当前 `backup-cancel.png` 与 `backup-saved.png`，介绍段下面均为“备份内容已下载”。取消图的底部提示为“保存已取消，可在操作任务下载原备份”；保存图为“已导出管理数据备份”。这证明截图中的提示区分了结果，但正文没有区分。调整前同名两张亦有该措辞，属于保留下来的状态表达问题，不将其描述为本次新回归。

**影响：**“已下载”通常也会被理解为本机已有文件；取消图在同一画面里需要用户自行解释“下载”与“保存”的区别。截图无法证明提示消失后的实际状态，但当前正文已经存在歧义。

**修正目标：**让持久正文明确表达实际终态：若只是取得服务内容，说明尚未保存；若保存取消，明确取消且仍可从原任务取得；保存成功才表达本机已保存。沿用现有状态文字的位置，替换原句即可，不新增状态面板、不隐藏原任务补救入口。

**验收：**补取取消与保存成功两种截图，正文单独可读出是否留下本机文件，并与各自提示一致。实际下载、取消和保存行为仍由主流程证据验证，本报告不认证这些行为。

### 问题 2：同一次格式错误重复占据两个层级

**位置与观察证据：**当前 `backup-error.png`，页头下粉色错误条写“备份不是有效的 JSON 文件”，介绍下又以次级色完整重复同一句。调整前 `backup-error.png` 已有相同重复，本次仍未收敛。

**影响：**同一错误既作为全页警示又作为介绍正文出现，增加一整段垂直占位，且次级色正文会与正常备份说明混在一起。它没有提供第二个原因或补救信息。

**修正目标：**同一错误保留一次主要表达，保持真实失败原因及现有重选文件操作；删除另一处逐字副本。若错误条可关闭，应确保关闭后的信息策略明确，不能仅为减法让失败结果无处可查；具体状态策略不由静态图推断。

**验收：**同次格式错误截图只出现一次该失败原因，层级明确，重选文件行仍可见。其他真实错误不得因此被通用套话替换。

## 提升

### 提升 1：恢复确认行向冻结参考对齐

**位置与观察证据：**当前 `restore-preview.png` 中“我知道恢复会替换现有管理数据”从正文左边缘开始，空复选框靠最右；冻结 `restore-preview-390.png` 为左侧复选框、右侧紧接说明。当前目录标签、输入框、原目录都已遵循左侧 20dp 正文锚线，确认行却把对应控件移到另一端。

**目标与影响：**这是局部还原差距，修到确认控件先于说明被读到，并保持该行与参考一致。保留完整确认措辞与既有勾选规则，不添加二次警告，也不据此改变底部面板或映射字段布局。

**验收：**普通竖屏截图中确认框位于说明前，二者组成同一行；长说明换行仍属于该确认项。截图只能核对外观，点击区域、未勾选不提交需另验。

### 提升 2：同类筛选选中态统一

**位置与观察证据：**当前 `list.png` / `pending.png` 的“全部”选中为较浅、较灰的底色且保留明显轮廓；`detail.png` 的“全部”与 `historical.png` 的“未完成”使用更亮的浅绿填充。两者都以勾号表示相同的单组选中语义，旁边也都有未选项。调整前任务截图里的列表与详情更接近同一种浅绿选中态。

**目标与影响：**精致度上的一致性修正：使用已经确定的 Paper 筛选选中颜色、文字和描边规范，让跨页状态读法一致。仅统一外观，保留列表的五类状态、详情的子项筛选及换行，不为照抄单条参考删掉必要扩展。

**验收：**对照列表与详情普通浅色截图，相同选中语义的填充 / 描边一致；暗色也遵循对应既有色板。截图中的暗色任务列表本身文字、分隔线层级清楚，未发现需另换色的可见问题。

**设计感表态：**不另提方向。开放操作行、细分隔线、衬线页头与低饱和橄榄色已经形成冻结 Paper 风格；无需增加卡片、图标或装饰。真实任务列表有更多字段和筛选，不能按参考一条合成任务的总高度压缩对齐。除上述逐字错误副本外，没有确认必须直接删掉的业务文字；历史只读、原请求 / 原文件、路径、失败数量、分页应保留。

**动效表态：**没有录屏，也未操作设备或页面；没有看到动效。不能据此判断入场、滚动、键盘避让过程、手势、禁用按钮点击或反馈时序是否正确。`restore-keyboard.png` 只证明该帧键盘已显示、焦点字段和底部动作可见，不证明确认说明可滚达或完整流程通过。

- 没有读取 `lib/`、`test/`、请求日志、窗口文本或 JSON 运行记录；未操作设备、服务或原型，未做 HTML lint。没有把基线导航脚本失败推断成视觉或业务失败。
