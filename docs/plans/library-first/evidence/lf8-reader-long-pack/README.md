# LF8 长包与大图原生证据

本段补 Android 阅读链路，实施范围见[方案](../../LF8-READER-LONG-PACK.md)。实际大图链路发现响应头前断线后只停在手动重试态，现将SocketException/HttpException纳入原有两次自动重试（400/800ms）。持续失败仍保留手动重试/跳过，失败帧不推进进度，离页取消定时器。布局、服务业务、SDK与原型未改；另补测试夹具、原生触控脚本和宿主采集工具。夹具在服务tests目录，生产runtime镜像不包含它。冻结原型树`1cbf605af8f03fa067a4ce8e914bb809e3a487ca`继续独立保留。

生产代码固定`f8631ae`，最终三轮采集/驱动固定`df9d80c`（生产及组件测试字节与f8631ae一致），普通390×844、DPR3、字号1；同一API36 ARM64专用AVD以`-gpu software -no-window`运行，App无Skia等渲染参数覆盖。实际SwiftShader/ANGLE启动信息、Flutter/Dart/Emulator版本及崩溃后恢复基线见`checks/`。该环境与早期宿主GPU尝试分别记录，不冒称相同图形环境。

每轮只使用新建8769实例和本机合成目录。媒体挂载只读，原始文件前后SHA相同；独立口令、生成器标记和挂载路径检查约束夹具，只读SQL从该轮保留的管理数据库导出。连接、目录注册及扫描是公开API准备操作；扫描超过两分钟的明确提示由准备脚本继续查询原任务，核对仅一次POST扫描、同一task ID，不改App原有超时语义或重新提交扫描。

从媒体库实际图包卡片进入500页长包，先由阅读设置切成纵向，再由integration_test注入触控事件滚动到末页。每步读取当前页ID、实际已解码RawImage、窗口与provider，所有500个索引都必须出现，滚动保持单调且单步不跳过页面。末页横纵切换保留同一页，通过本次固定范围切换大图包、实际解码4000×6000、6000×4000与8000×8000图片，往返三次，再回媒体库重开长包。原范围ID、500页末页ID、偏好与进度用客户端/API和只读SQL分别核对；最近只有实际阅读的两个包，其他包封面预读不计历史。逐页图片请求与SQL页表交叉核对，不用“缓存数量”替代业务完成。

`native/normal-1..3/`分别保存最终同源完整轮次。每轮13个保持的前台点，宿主采集PNG、窗口焦点及dumpsys meminfo后才确认继续；定期保留PSS/RSS原始文本，另保留实际390×844手势录屏、ffprobe结果、Flutter帧时序、服务请求和管理数据投影。screenrecord单段上限180秒；有多段时段间衔接不认证为无缝录制。截图用于状态核查，本段未新增设计方向或独立视觉评审，也未重新认证所有原型像素/手势组合。已抽看初稿首屏、纵向末页、8K页与重开图，最终组的像素/前台/业务另由只读脚本核对。

三组均通过只读复核，结果见`verification.json`，记录各轮手势数、驱动打开至就绪墙钟、滚动墙钟、观察到的缓存/待解码峰值、原生采样PSS/RSS与已处理图片警告。元数据120项、reader provider6项/48MiB估算预算是源码边界；provider估算、Flutter缓存字节和整个进程PSS/RSS是不同指标。所有数值是指定debug驱动及采样间隔下的观察值，打开与滚动墙钟含测试固定pump/轮询节奏；不当作用户速度、真实首帧基准或硬件绝对峰值。帧时序分位数保留原始样本统计，未与目标手机阈值比较。
