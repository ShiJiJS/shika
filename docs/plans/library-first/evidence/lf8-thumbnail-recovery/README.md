## 已核验

22项组件检查（新增11项，既有11项），静态分析／格式／Ruff。组件使用实际本地HTTP响应及解码，覆盖连续两次503后恢复、持续失败达到3次后停止、手动恢复、手动重试与计时器并存、401不重试、关闭未完成响应，以及同一单元格改变地址／凭据／版本／图包／active后旧socket断开。active由总览分页busy连接，清单请求期间即取消旧单元格；本段原生为六张样本，未实走超过24张分页。

[原生记录](native/result.json)8点为普通390×844／字号1的专属API36 ARM64 AVD、软件GPU／主机AVC2，未修改renderer；四图包共24PNG＋2公开视频，26源文件前后SHA一致。六张缩略图各先注入一次503，实际生产服务其它并发忙碌也计入同一两次预算，最终各2–3请求后6张真实解码。持续失败逐页恰3次、真实等待3秒没有继续请求；关闭故障后逐张手动重试，6张均读回200并解码。

随后6个200响应只发PNG前16字节并保持未完成；实际Android返回只关总览，服务端记录6个流全部cancelled，之后3秒每页仍只有1次请求。重开面板遇到的生产忙碌也在原上限内恢复，六张最终200并解码。全部总览阶段没有新增非GET请求；生产API读回的图包完整详情与进入前相同，固定范围、当前第3页、横向模式、最近／进度均未被总览操作改写。入口本身的登录、创建阅读范围和真实主图opened共3次写入另计。未做SQL七表快照，不把API详情／写请求核对称SQL逐行验证。

## 诊断边界

旧请求复查发现503后本已有200重试，只是发生于关闭阶段，故修正“完全没有自动重试”的初步判断。旧组件基线5项通过，在途socket取消1项失败。首个测试草稿清理debug变量与等待实际解码不足，另存before-components；不计产品失败。components-1主阅读覆盖层变化曾重建Image导致既有横屏错误页测试超时，已分离取消代次与Image重建标识，后续相关检查通过。components-3命令误含不存在的reader_images_test.dart，其加载失败不计成功；最终有效四文件22项另存。

原生开发1：每图注入2次503后，实际生产并发仍可返回503，达到上限的两图未成功；没有增大上限。开发2：已实际在2–3次内恢复，但驱动遗留全部3次的错误断言而失败。开发3：pending截图误等spinner settle，拖到15秒超时后又发6请求，取消断言见12条而失败；最终只在该场景泵一帧并在截图后再次确认1请求，真实返回完成6个取消。原始失败日志、固定源码、请求及已拍图片均保留，不与最终8点相加；测试活动期间未改运行源码／驱动。
