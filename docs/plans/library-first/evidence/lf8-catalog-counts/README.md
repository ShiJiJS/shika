# LF8 媒体库分类总数：阶段证据

固定实现及原生取证源码 **910cfb2**，分支 `codex/lf8-catalog-counts`，基于 PR #59。冻结原型树 **1cbf605** 独立未改，可单独移除；LF8/#33与总任务/#24继续开放。

## 实际行为

媒体库类型栏显示服务端同次只读快照的全库视频/图包数量，沿用15dp类型名、12dp计数、7dp间距。搜索和分页结果不改写总数，标签/最近不展示全库标记。旧服务隐藏标记；失败或不完整响应显示“—”，点分类可只读重试，实际空库正常显示0。

现有 `/api/v1/library-state` 新增 `media.video.indexed` 和能力 `media_catalog_counts`，两类使用实际目录的可浏览条件。显式SQLite读事务保证并发提交时的一对计数来自相同快照，不枚举媒体摘要或触碰媒体源。顶层旧 `indexed` 与扫描计数保持原义。初次同步和已有准备状态轮询复用响应；直接重试拥有独立取消通道，连接代次与请求次序拒绝旧响应。图包管理完成后使计数失效并只读重取。

完整 VideoViewerApp、真实 ServerLibraryRepository、已有AVD与每轮新建8768隔离服务实际扫描2视频、4包、24PNG。原生流程验证搜索零匹配仍为2/4，跨标签/最近返回保留查询；实际回收/恢复通过管理网关得到2/4→2/3→2/4，故障返回未知，点击类型重试恢复。网关调用用于验证库存更新，本段不重新宣称删除确认UI已验收。完整阅读进度前后相等，最近0、会话0，无 opened 或扫描写请求；最终回收记录为restored，26个源文件SHA不变。

## 修正与诊断

- 首次服务端顶层导入引起streaming/library_state/catalog循环，改为函数内导入；旧精确能力集测试增加新能力，未放松断言。
- 原生驱动跨页返回后注入空IME编辑值未触发查询，改走界面已有“清除”动作；不宣称由此验证所有IME路径。
- 初次视觉自查发现类型栏滚动容器收缩居中、视频封面未解码，分别设整宽约束并等待实际解码图像后取证。
- 短横屏键盘过渡曾使非当前标签页只余61dp、固定底部区溢出79dp。Scaffold已消耗inset，不能只靠inset判断；操作区按实际可用高度60%设置滚动上限，保留列表空间，普通高度仍自然排布。两类标签组件验证缩高、滚动到操作、恢复可达；原生重跑不忽略异常或增加固定等待。
- 新操作区增加独立滚动后，原分页测试的泛化Scrollable定位变成多匹配；定位明确到标签列表，原50/61分页与失败重试断言保留并通过。

诊断日志单列，失败轮次不计入正式45图。没有操作正式8760、真实NAS、SDK或发布APK，生产backup_v2保持关闭。
