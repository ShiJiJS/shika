# LF7 备份与恢复：存量界面润色评审

评审方式：按 oil-ui-pro `reviewer-manual.md` 第 2 节，只对照既有 Paper 规范和冻结原型，不打分，不查看实现源码，不修改产品文件。

## 速查清单

- [问题 1] 360×740、双倍字号的目录输入框：目标路径末尾不可见 → 目标路径按实际字号自然换行，静止时能完整核对路径，输入框随内容增高。
- [夹具偏差] 备份页的标题层级：截图页标题呈无衬线，正文段落标题反而呈 Serif → 验收夹具复用生产共享 Paper 标题，再补截图；不据此判断生产 UI 存在标题缺陷。
- [可选精简] 备份页最下方历史入口：与上方直接快照入口重复出现“恢复前快照” → 历史入口文案聚焦操作记录，保留上方直接快照入口的辨识度。

## 当前实现需要修正的偏离

### 1. 大字号下目标目录无法在静止状态完整核对

证据：`/tmp/lf7-archive-confirm-360.png`，最后一项“分页目录24 · 视频”。目标输入框只显示 `/media/videos/目录`，末尾 `24` 不可见；下方“原目录”则将 `/media/videos/目录24` 完整换行显示。这不是截图页边切掉整项：输入框左右边界都在截图内。

影响：这页的核心任务是恢复前核对目录。大字号用户能读到原路径，却不能直接读完实际待恢复的目标路径，容易漏掉仅末段不同的映射。即使输入时可横向滚动，也未满足 LF7 文档“标题、长路径和说明自然换行”的要求。

调整目标：保留现有 Paper/Material 输入框，使长目标路径在可用宽度内自然换行并撑高。不得靠缩小文字来容纳路径；辅助原目录和停用说明继续自然换行。

验收：在 360×740、双倍字号，输入末段只相差数字的长目录，收起键盘后不用横向拖动或定位光标就能读完目标路径；滚到末屏仍能看到确认区和取消，且没有叠字、裁切或第二个嵌套滚动区。

## 验收夹具偏差（不是已确认的生产 UI 问题）

### 备份页的截图字体角色与既有标题规范不一致

证据：`backup-start.png`、`backup-restore-point.png` 中，“备份与恢复”呈无衬线，下一层“保存你的整理结果”呈 Serif，二者视觉字号接近。冻结 `backup.png` 的页标题使用 Serif，内容小标题明显从属于页标题；当前 `restore-first-page.png` 的“恢复备份”也已使用 Serif。

来源补充：主 Agent 确认，该备份截图来自测试专用 Scaffold 的默认 AppBar；生产页面已有共享 Paper 标题。因此本条是可见截图与规范的差异，归因为验收夹具，不作为生产 UI 的既定缺陷。

影响：当前证据画面中，同一流程的两个页面标题使用不同字体角色，且备份页正文小标题与页标题争夺层级。夹具若与生产标题不同，会误导视觉验收。

调整目标：只让验收夹具复用生产共享 Paper 标题，再补证据截图；本轮不要求修改生产标题或生产页面层级。保留 20dp 内容边距、现有按钮和纸白/橄榄配色。

验收：并排查看备份页、恢复页与冻结原型，页标题使用一致的字体角色；“保存你的整理结果”清楚从属于页标题。大字号时两者可自然增高，不压缩按钮或说明文字。

## 可选文案精简

备份页已提供独立“恢复前的快照”行，随后又有“查看后台操作结果与恢复前快照”。这两个入口可以有不同目的，但当前文字重复了同一对象。可将后者缩为“查看后台操作记录”或既有历史页的准确名称，具体以该目的页真实内容为准。只精简入口文案，不删除历史中原导出和恢复前快照的下载能力。上方快照副文案“查看并恢复上一次替换前的管理数据”已交代来源，不建议再增加解释段落。

其余说明承担文件边界、覆盖风险、留空含义和不可恢复项的告知，未发现应直接删除的填缝文字。

## 应保留的实现

- Paper 纸白背景、墨绿/橄榄文字和主动作、20dp 内容边距及既有原生按钮/输入框已形成一致表面；无须换色、增加装饰卡片或模拟网页系统栏。
- 视频/视频标签与图包/图片/图包标签分开展示，比冻结小面板更能表达本轮两套标签独立的任务要求。不要为了压缩高度合并为“标签总数”。
- 目录核对独立完整页面；24/27、27/27 的载入计数和末页 2/2、禁用“下一页”都清楚。完整页面相较冻结底部面板是 LF7 明确授权的长表单适配，不属于偏离。
- 当前确认截图中勾选框为空、“确认恢复”禁用，取消可见。360 双倍字号下确认文案、边界说明和取消均可读，未见重叠；保留其随字号增高的行为。
- “恢复前的快照”位于同一备份页，快照预览复用目录核对视觉结构，符合先核对再恢复的北极星。

## 证据边界与原型差异

本次查看了五张 390×844 普通字号实际 Android 截图、360×740 双倍字号确认末屏、两张冻结原型和 LF7/LF5 规范。截图为设备像素导出，评审按所给逻辑尺寸理解。允许 Android 系统与网页原型的控件差异；没有因主按钮使用原生实心样式、全页返回样式或独立完整核对页提出重构建议。

备份页显示“文件上限 64 MiB”，规范要求显示协商值。静态截图不能判断 64 MiB 是否来自服务协商，不能据此认定写死或不符合上限规则。

360 双倍字号只提供确认末屏，备份页快照行未被对应脚本截到：不能声称该入口的大字号布局已通过，也不能把脚本未滚到当作界面缺陷。长路径问题有这张确认末屏的直接画面证据。

没有录屏、动效或可操作会话，本次没看到动效，未验证 140ms 状态尺寸变化、降低动态、页面过渡和按钮反馈。静态截图也不能证明跨页草稿保留、恢复前快照的服务端来源、系统保存、断线任务找回、确认首次默认值、恢复成功或异常状态已经通过；这里只确认提供画面中的可见状态。

冻结原型的恢复面板仅有两根目录；LF7 明确改为可分页的完整页面，因此不能以原型底部面板高度要求当前 27 根表单。原型本身未提供大字号和长路径状态，此次不把缺少这些参考状态归为实现缺陷。

保留：分媒体统计、完整目录核对页、默认关闭的确认视觉状态，以及同页直接进入恢复前快照的路径。

本评审不打分。
