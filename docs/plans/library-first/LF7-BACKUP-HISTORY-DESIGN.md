# 完整替换后的只读管理历史

本模块接在 [v2设计](LF7-BACKUP-V2-DESIGN.md) 的文件校验之后、恢复协调器的原子提交之前。它保存原库或导入库中完整的关联数据，提供任务标量分页、原成员分页和原请求回执；不读媒体、不写活动库、不含入队/重试/停止接口。完整v2仍须实现恢复预约、前快照、根映射/物理真相、数据库替换、权威代次、公开任务协议和App文件流程，本模块不能单独完成恢复。

## 存储与发布

只接受服务器用已知schema完整校验过的 StagedArchive。复制时对实际复制字节重新计算SHA，要求匹配校验时的摘要和源文件身份。每个独立图保留全部33表及原外键；新生成的随机路径不来自用户输入。索引只保存任务标量摘要及原请求位置/指纹，不复制巨大的结果或清单；它与图文件置于0700目录、0600文件。

全部图复制和索引完成、SQLite FULL提交、文件/目录持久化后，用禁止覆盖的原子rename发布新目录。取消或可捕获错误移除本次临时目录，不消耗输入或覆盖已有目标。SIGKILL可能留下完整或不完整的未引用准备目录；恢复父任务必须记录该次准备归属，重启只认其事务提交的正式引用并清理孤立目录，不能扫描临时目录并擅自激活。该协调与清理仍待接线。发布后父目录fsync错误也不证明没有发布，调用者必须按原事务核对。

准备成功仅返回可重新打开的 HistoryArchive；不会改变当前服务可见历史。恢复协调器后续在同一管理数据事务中替换活动数据、设置该历史引用并轮换权威代次。导入历史永不注册到启动执行器；公开历史查询的响应适配和旧POST拒绝/原回执只读仍待该协调器实施。

## 新旧身份与查询

来源按旧到新排列，每个来源的活动library优先于其附带历史。相同任务ID/同命名空间请求键的默认查询使用最新图；可指定graph_id查看更早版本，不能把相同ID的父/子/成员交叉拼接。按媒体类型筛选在“选定最新身份”之后执行，最新记录类型已变化时不会回退到旧图。共享的同ID历史图只有摘要及挂载说明完全相同时才复用，不一致拒绝准备。

任务列表复用当前标量投影，只标记历史，不改原状态、结果、时间或错误。整份恢复父任务作为列表入口，执行批次仍可按ID查；成员从该任务所属的同一不可变图分页，避免非空根/图包外键丢失。所有返回含明确历史及graph_id。原回执按8类命名空间分别索引，避免相同文本在不同命令族里相互冒充；只有显式读取某个原回执才加载它的原结果，这仍受单记录上限约束，不能宣称这一路是任意大结果的流式输出。

重新导出时把全部历史图作为v2的history记录，原ID、父子/成员/步骤/回执保持；历史媒体不会混入当前媒体库，也不携带旧备份文件本体。统计和任务/成员读取不每页重算整个大库SHA；重新应用/导出前显式核对不可变图摘要。外部SQLite文件依旧不支持导入。

## 验证范围

针对真实HTTP受理的图包永久删除、27成员整份恢复和执行批次验证分页及回执；独立比较准备/查询前后的输入图、历史文件与源媒体SHA，原活动操作仍非历史。验证同ID不同结果、来源/类型优先级、共享图去重与冲突、取消/索引空间失败/复制后变化/已有目标与只读数据库。测试中还使用真实子进程在发布前后SIGKILL，并从正式目录重开；这是历史包发布的进程证明，不等同完整恢复提交或断电证明。18,000条带大结果的任务用实际大文件测量Python分配和标量索引分页，完整结果不进列表。

实际测试结果在运行后写入阶段证据；设计中的验证项不能当作通过记录。公开v2能力保持关闭，LF7、总任务和LF8继续开放，冻结原型与真实NAS不修改。
