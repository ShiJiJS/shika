# 管理备份 v2 与兼容迁移

基于PR #47（7111fa7），分支`codex/lf7-backup-v2`。本阶段目标仍是完整设置和备份往返，不以格式编码器、只导出或只保留旧视频协议代替完成。v1保护在新流程验收前保留，未接齐前不发布`backup_v2`能力；冻结原型不改。

## 完整数据范围

保存根配置、目录、视频、图包/页身份、两类独立标签和关联、逐包进度/阅读偏好、最近、固定视频/图包范围及成员；完整保存视频文件操作、图包文件操作/步骤、回收、永久删除计划/成员/执行/逐文件步骤、整份恢复父任务/成员/批次、缺失清理父任务/成员、原请求及操作任务。默认播放顺序和阅读默认值是类型化管理设置；活动范围指针与已打开图包归属按关联校验。

媒体字节、缩略图、扫描暂存、身份核对缓存、凭据/口令/会话令牌、server_id及当前写入代次不导出。旧dev/inode等字段如作为操作历史存在，也不构成新挂载位置的授权证据。恢复必须重新核对实际文件；不删除、移动或复制源媒体。永久删除身份和已删除源图片不能因旧备份成为可用内容。

## 文件与校验模块

采用UTF-8逐记录文件（`.vvbackup`），不使用压缩或用户提供的数据库/SQL。首记录声明format/version/schema/created_at，随后按图分组：一个library图及零或多个只读历史图。每图有小型配置头、逐表逐行记录和按表计数尾记录；最后记录前文全部字节的SHA-256及图数，必须到EOF。图ID只用于关联，不用作接收端路径。

版本适配集中在备份模块：v1先按既有签名/字段/关系校验，转换成video/enabled根、旧范围语义、隐式默认及空图包状态；v2逐行校验、绑定已知SQL表和列，在私有临时目录生成已知schema的SQLite暂存图。数据库/表名及SQL从代码白名单生成，导入数据只作绑定值。主库在全部校验、文件核对和恢复前快照完成前不替换。

单行和整份文件分别有明确上限，读取/写出按块，不把全库行列表、完整页清单或整个文件装入App或任务JSON。计数和预览从暂存库做标量查询与分页。导出从一致的本机数据库快照读取，网络、编码、实际媒体核对不持有主库写锁；不在长WAL读事务中无限拖住日常写入。临时文件0600/目录0700，生成式路径；中断或校验失败不留下可被当成已完成的暂存图。

## 全量替换与历史

活动集合完整替换，不把当前无关标签/图包混回恢复后的媒体库。另一方面，恢复前已受理的命令、父子/成员图与原回执仍须可查，不能因当前媒体没有进入旧备份而丢失外键依赖。

因此保留只读历史图，由统一历史查询模块提供任务/成员/原回执查询；不靠复制虚假的活动目录或丢弃非空成员外键来保全历史。历史图使用由已验证记录生成的私有已知schema暂存库，备份逐记录包含其完整关联；不接受外部SQLite文件。历史任务不进入任何启动队列，原POST不启动历史命令，查询不重放。恢复前快照及当前恢复控制任务保持可查、可下载；旧备份文件本体不递归装入管理备份，异机历史下载应明确文件不可用。

恢复流程：受理固定preview和映射 → 维护预约/阻止新写 → 完整恢复前快照 → 保全当前命令历史 → 校验根映射（含明确空映射）→ 按实际文件重建可用/缺失/回收与删除真相 → 校验完整关联 → 单事务替换管理数据和轮换写入代次 → 完成原任务。阶段/文件持久化；重启继续同一任务，提交前故障回滚，不重新删除或移动文件。

## 代次与跨设备

新写入代次由当前服务生成，永不从备份恢复。新客户端的请求持有捕获的代次，检查必须与写入共用数据库写锁，避免检查后恢复提交的竞态。旧客户端未传代次时使用登录令牌的签发代次，恢复后的旧令牌保留只读核对能力，写入需重新连接。已升级客户端确认恢复/检测异机恢复后，失效旧网关、读取、选中范围和请求发布；旧安全日志/剩余删除选择历史化，不能拿未受理的旧命令作用于新库。同地址server_id不变也不能绕过。

## App 与验收

新流程接真实系统文件选择器和流式上传/下载，取消不提交；显示格式版本、两类内容/标签/进度/历史统计、每个活动根的映射及完整替换影响。恢复前快照可保存；重开未知状态只GET原ID。旧服务继续v1客户端适配，旧客户端配新服务得到可解释保护。

验收须包含：含所有父子图的v2完整往返、v1转换、当前及导入命令历史不重放、重复原请求、永久删除/根重映射/空映射、损坏/截断/超限/存储失败、并发写入与恢复预约、提交前后进程中断、跨设备旧命令代次、真实选择器取消与响应丢失。大文件测试必须超过旧客户端32MiB限制并量测工作窗口；不以小字典的JSON往返代替有界传输。随后继续LF8的完整视觉与目标设备验收。

当前实现进度：文件编码/校验、在线一致快照、磁盘暂存和v1适配已落地，29项针对检查及Ruff通过。真实HTTP夹具生成所有33张管理表的非空记录，逐表逐行核对暂存结果；包含两类标签、进度/偏好、范围、视频文件命令，以及图包恢复/永久删除/缺失清理全父子图。18,000任务行生成约39MiB文件（超过旧32MiB限制），Python分配峰值约2.8MiB；这是模块分配量，不是App或整个进程RSS验收。

新格式单记录上限256MiB，整份文件上限由调用者传入并独立执行；v1兼容解析保留原有最大256MiB及既有完整校验，v2不走整份JSON内存解析。扫描discovered行仅在私有快照中排除；若有页以外的用户/任务关联则拒绝导出，等待同步，不能借CASCADE丢弃关联。v1原先允许的待发布视频保留ID并归为待物理核对的missing，避免丢失已备份的标签/范围。
