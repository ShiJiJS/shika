# LF8 当前视频预览的原生手势与生命周期

对应 PRE-04/05、NAV-02、UI-02，基于PR #76。早期I2播放器记录不替代当前媒体库→二级预览完整链路；本段复用公开3视频/4包（第三项沿用同一公开横屏字节，仅专用夹具变体启用；其它原型场景仍2视频）的独立8768服务，实际走当前入口、播放器及设置。

先检查开启相邻准备时当前/相邻原生播放器、有界数量与仅当前可播放/音量。通过真实控件暂停、拖动进度、选择1.5倍；实际旋转进入全屏，断言同一控制器及暂停时间线不变。检查恢复播放、左右亮度/音量手势、按住临时2倍，通过宿主ADB Home触发合法后台生命周期，要求释放全部网络播放器；返回后继续暂停、恢复基础速度和窗口亮度。系统返回先退出全屏，预览/固定范围仍在；普通预览另补一次后台返回，再实际上下快速切换固定范围。设置中关闭相邻准备后从媒体库新建明确范围，核对只保留当前控制器及切换/离页释放。

原生触控脚本与宿主操作分别留证，保持检查点采集真实PNG、前台窗口、内存及旋转分段录屏；固定成员/序号、最近、HTTP和媒体SHA独立核对。合成/公开小视频及软件GPU/debug不当作目标手机性能或真实NAS吞吐。需要修复生产行为时单独冻结实现并按同一源码复跑关键链路三轮；失败另留，不拼接为成功。

首轮驱动在第二个新范围断言position=0失败：服务端默认随机顺序与保留当前锚点使其合法位于1，属于驱动假设错误。最终驱动改为在实际范围面板明确选择顺序并点原库第一项，不修改生产默认；另扩展专用三视频变体，覆盖中间项实际三个控制器。首轮完整日志单列，不计最终三轮。7fd7b27三视频版完成一轮；5575873补控制器身份与逐次切片记录后，下一轮QEMU挂起/139退出、设备消失，未完成，另存失败。恢复同一AVD的userdata与显示/音量基线；按SDK advancedFeatures.ini明确支持的HardwareDecoder启动覆盖，关闭宿主视频解码并保留软件GPU，App无渲染覆盖，未改SDK。宿主录屏回收失败现在独立留错，仍继续设备恢复与精确容器清理；原型元数据可空。关闭宿主解码后的首轮暴露驱动在顺序切换已更新、异步队列行尚未挂载时调用ensureVisible；新增实际队列行及顺序控件就绪检查，不修改生产逻辑。25f575a首轮另在隐藏控制条时使用“显示后再点暂停”的驱动步骤失败；改为按当前可见控件直接暂停（画布点击本身就是暂停），并同时等待UI播放意图与原生状态一致，避免把两次切换混为一步。最终98507ea在同一软件GPU/关闭宿主解码环境连续三轮行为通过：45个前台点、21次实际fling、6次Home往返及12段完整可解码录屏，相关15项组件检查和App analyze通过。控制器身份/暂停位置、每次切片、UI暂停意图及原生状态、SQL成员/最近、27源SHA及显示/音量恢复分别核对。实际原图另发现右侧绿边，与宿主解码对照无该条，登记[#78](https://github.com/ShiJiJS/shika/issues/78)；原图保留，根因未证，UI-02不据行为通过而关闭。生产App/服务业务树未变，见[完整证据](https://github.com/ShiJiJS/shika/blob/c9c6363ab1ca3bb7d72c96499432a289de33f187/docs/plans/library-first/evidence/lf8-preview-lifecycle/README.md)。不据本段关闭全部PRE或UI项目；其它来源/解码故障/迟到回执、强停凭据、目标手机/NAS及原签名升级继续。冻结原型1cbf605独立保留且可移除，不改正式8760/NAS、SDK、生产backup_v2开关或发布APK。
