# 默认纵向与操作文案：源码阶段

跟踪[#137](https://github.com/ShiJiJS/shika/issues/137)及[#141](https://github.com/ShiJiJS/shika/issues/141)，[草稿PR #145](https://github.com/ShiJiJS/shika/pull/145)，基于返回修复PR #144。本轮改实现并执行隔离检查，不更新NAS、参考原型或已交付code22两包。

## 默认值与兼容

客户端ReaderPreferences、服务端DEFAULTS、Preferences请求缺省及新建ORM偏好对象统一为纵向；不做数据迁移，不更新既有reader_defaults或pack_preferences。方向/间隙/适配方式保持。

源码核对发现，既有协议在图包实际首次打开时就保存当时偏好，之后显示overridden=true。这不一定是用户主动切换。当前数据没有可靠的“自动固定/主动选择”来源标记，不能按猜测将已有横向全部改掉。因此保留所有既存偏好；未固定偏好的图包才继承新的默认。已有进度但无偏好行时沿用新默认，页ID和37%页内位置保持。显式全局横向和图包横向都保留。这个边界补充了原规划中的“单独设置”，不删除旧协议的冻结规则。

当前NAS仍运行旧服务，其返回的权威默认仍可能是横向；新App不能无视服务端设置强制覆盖。本轮没有直接PATCH真实默认，实际交付需同步核对服务/默认值与App。

## 自然文案

菜单/确认/通知改用“移入回收站”“已移入回收站”“撤销移除”；跨类型标签入口使用“图包标签”。源文件、标签、阅读记录保留的说明和永久删除警告保留。处理客户端及服务端可见错误，不改任务键、请求体、接口、选择集合、文件操作或8秒撤销规则；不重写已有历史回执/备份文字。

当前生产客户端与服务源码中没有该票要求去掉的旧措辞。测试仅同步明确的文字定位；保留操作断言。旧历史文档和冻结证据不全库替换。
