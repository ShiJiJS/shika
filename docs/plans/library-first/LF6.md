# LF6 图包快速整理（实施中）

对应 [#31](https://github.com/ShiJiJS/video_viewer/issues/31) / [草稿PR #40](https://github.com/ShiJiJS/video_viewer/pull/40)，基于LF5 #39。逻辑操作后端、普通卡片和阅读器整包整理/撤销/待核对入口已接入；双类型回收站与跨页恢复已接线；限定图片清单永久删除、完整后台批次与完整验收仍需继续，本阶段保持开放。

## 已接入的行为

普通图包卡片封面仍进入阅读，更多菜单提供阅读、整包标签与服务支持时的整包回收。确认显示包名/图片数量与保留源文件、标签、进度的规则。成功后刷新原查询与原位锚点，提供绑定原operation的撤销；失败不报成功。

客户端在POST前用独立SecureFileCommandStore保存不可变请求。响应未确认时可继续浏览，原卡片即使已消失，也能从列表待核对入口读原回执。404不清掉记录或自动重发；已知任务不再POST。仅同一资源互斥，连接范围独立，旧连接与管理数据代次的迟到结果不应用到新连接。类型、成员、计数或任务身份异常不当作成功。详见[客户端契约](LF6-CLIENT-DESIGN.md)。

后端整包逻辑回收/恢复保留源图片、附件、稳定ID、标签、页进度、偏好和最近记录；普通与最近按可用状态隐藏回收项。恢复禁用根只改逻辑状态，不绕过目录授权。图包回收列表、完整跨页选择、逐包结果、失败只重试未完成项与独立只读重试回执已接入。

快速整理后端携带实际opened的会话/位置/清单/进度版本，排队提交前再验证；回收成功和原固定范围向后推进同一事务，跳过失效项、不重筛、不绕回，尾项明确结束。8秒撤销绑定原操作，只有原阅读归属/版本仍一致才恢复原位置，不覆盖较新进度或抢走新会话；已受理撤销不因排队超时失效。客户端已接先flush并冻结写入、查询原回执、成功后同范围下一包/末尾返回来源，以及撤销回原阅读位置。普通阅读回收使用advance=false返回来源，保留原会话返回守卫；从来源撤销可只读恢复原session。

新受理的图包回收使旧图包撤销失效，重放旧请求不改变因果顺序。期限从原实际提交起算，回执带当次server_time；客户端按服务端剩余时间计时、最多8秒，最终以服务端为准。重启恢复不重复回收/推进或重置期限，historical不执行。扫描发布前再核对回收/预留，目录修改与操作受理在写事务中互斥。

公开 `pack_logical_trash` 与 `pack_reader_cleanup` 能力，尚无图包永久删除路由。逻辑回收的元数据清单不是永久删除授权，后者仍需重新核对文件版本、路径、签名与新增/替换。见[后端契约](LF6-DESIGN.md)。
