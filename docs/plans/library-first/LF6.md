# LF6 图包快速整理（实施中）

对应 [#31](https://github.com/ShiJiJS/video_viewer/issues/31) / [草稿 PR #40](https://github.com/ShiJiJS/video_viewer/pull/40)，基于 LF5 草稿 #39。`abe0ab8` 接入逻辑回收、恢复、阅读位置撤销和持久化操作模块。本阶段还需原生界面、限定图片清单的永久删除及完整验收，保持开放。

## 本次已接入

- 图包整包逻辑回收与批量恢复；保留图片、附件、稳定 ID、标签、进度、偏好和最近记录。普通与最近查询按可用状态隐藏回收内容，恢复后继续使用原阅读记录。
- 快速整理命令携带实际 opened 的会话/位置/清单/进度版本，提交前再次验证。回收成功和固定范围向后推进在同一事务；跳过失效成员，不重筛、不绕回，尾项明确 finished。普通回收不隐式推进阅读。
- 8秒撤销绑定原操作 ID；期限从实际提交起算，受理后的撤销不因排队超时失效。新受理的图包回收使旧撤销失效，重放旧请求不能改变因果顺序。
- 撤销恢复内容后，仅在原会话与该回收产生的位置仍一致、原进度与偏好未改时恢复阅读位置；否则只恢复内容，不覆盖新阅读状态。
- 类型化回收站列表与完整跨页选择、逐包结果、幂等请求、只读请求回执、显式失败重试和服务重启恢复。提交后的恢复不会重复标记或推进，不重置撤销期限。historical 操作不执行。
- 扫描发布前再次核对回收/预留，保护读取期间被回收的图包。目录修改和操作受理在数据库写事务中互斥。恢复禁用目录的图包只改逻辑记录，不能绕过目录授权。

仅公开 `pack_logical_trash` 能力；尚无图包永久删除路由。实施契约见 [LF6-DESIGN.md](LF6-DESIGN.md)。逻辑回收清单记录不是永久删除授权，后者必须另做文件版本、路径、签名和增删核对。

## 验证范围

新增17项鉴权 HTTP / 真实 SQLite / 临时图包测试已通过；`ee9d975` 完整180项服务端测试和Ruff通过（235.29秒）。完整服务端结果及源码校验见 [后端证据](evidence/lf6-logical-backend/README.md)。当前客户端没有修改，既有197项客户端检查只按LF5原提交记录保留。

测试覆盖27项完整与随机固定范围、跨页选择/恢复、嵌套图片和附件哈希、最近隐藏/恢复、页内比例和偏好保留、只读维护期回执、重复键与部分失败、排队期间进度变化、撤销期限和新意图竞争、历史任务、提交前/提交后的模拟中断恢复及真实扫描发布竞态。重启专项使用TestClient关闭/重建与故障钩子，不把它写成真实SIGKILL或Android杀进程验收。
