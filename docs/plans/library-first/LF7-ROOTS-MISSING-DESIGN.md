# 目录类型、启停与图包缺失管理

本阶段补齐真实App的目录接入和缺失管理，不改冻结原型。入口为设置→媒体目录；名称、挂载路径、视频/图包类型和启用开关均接真实服务。停用保留标签、阅读记录与原文件，界面明确类型和停用状态；已有内容不能直接改类型，服务端拒绝后保留全部输入。旧服务继续使用原视频目录表单。

短编辑面板沿用Paper尺寸并可滚动；选择类型或启停时结束路径输入，收起软键盘。表单在打开时捕获连接，切换服务后不能保存旧表单；保存中的输入不可改。路径尾斜杠规范化保留根路径本身，实际挂载边界、符号链接和类型冲突由服务端验证。

## 分类型缺失页面

新服务从媒体目录进入全高度“缺失内容”页，视频与图包分别查看、计数、24条分页及明确清理。只保留当前页，不把已加载内容当成总数或全选范围。读取失败保留可定位错误，不据空缓存报告没有缺失。连接或本机管理数据代次变化后原页面失效，不能操作新连接。

视频沿用既有缺失查询/清理协议和安全条件；本阶段的新持久父任务专用于图包。确认清理图包时说明会移除失效管理记录、标签关联、阅读进度/偏好及最近记录；不删除任何源字节。离线、停用、未完成过扫描、内容重新出现、目录归属变化或其它文件操作占用时保留，并给出逐项原因。

## 持久任务与固定范围

迁移0013新增 `pack_missing_cleanups` 和 `pack_missing_members`。父任务使用既有Task；受理时通过SQLite INSERT SELECT一次固定当时缺失的成员、路径、根和generation，不把全库ID或页清单装入HTTP响应/Task JSON。受理后的新缺失不加入原任务，重复原request_id返回同一任务。

鉴权 POST `/api/v1/packs/forget-missing` 需要明确confirmed=true，返回202；GET `/api/v1/pack-missing-requests/{request_id}`只查询原受理记录。能力名 `pack_missing_cleanup`。有扫描或原清理正在排队/运行时拒绝新的清理；已有幂等记录仍可查询。新任务在独立单工作线程中按最多100个待处理ID读取，每个成员独立短事务核对与结算；未提交的事务在崩溃后回滚，启动只继续同一父任务的pending成员。

执行时再次核对缺失状态、generation、原路径/根、启用/可访问/扫描证据、最深有效目录归属，以及原文件/恢复任务预约。使用不跟随符号链接的目录描述符核对路径是否仍不存在，并重新验证根目录身份；无法可靠判断时保留。扫描在受理后启动时保留相关成员，不与扫描争抢身份。

成功扫描在同一结算事务中保存本机可重建的根目录证据：路径、last_scan、设备号/inode和可用时的创建时间。清理必须匹配该证据，不能只比较清理前后两次打开的目录；否则扫描后同路径被替换为空目录会被误判。旧库尚无证据、证据损坏或根已替换时保留记录，要求重新成功同步。该缓存不进入管理备份，不能用另一台机器的目录身份授权清理。测试覆盖受理前/后替换、证据缺失/损坏/时间不匹配，以及明确重扫后才可清理。

成功将包改为deleted墓碑、释放location_key并增加generation/content_version；删除本包活跃标签关联、阅读进度、偏好和最近记录。保留包/页和会话成员墓碑以支撑历史文件回执及固定范围；旧图片不可读取，扫描不复用deleted身份。原路径后来出现内容时作为新包入库，不继承被明确清理的标签/进度。整个模块不调用删除、移动或重命名源文件的接口。

成员结果和父计数同一事务提交；processed=succeeded+skipped，failed为0，完成时processed=total。skipped显示为“已保留，未清除”，不充当成功删除。任务中心归入图包，提供真实逐项结果分页；原清理历史标志阻止启动和重放。异常失败保留尚未处理的成员，不自动扩大范围或静默标成功。

## 本机原请求与未知结果

`missing_cleanup_v1`与现有文件命令共用同一受保护日志、串行写队列，按endpoint+server_id隔离。先写盘再POST，写盘失败不发送。响应丢失、404或不完整受理/任务摘要都保留原request_id；重开只读取本机记录，明确查询只GET原回执，不自动重发。确定未受理的4xx只移除该请求；受理后的GET失败不能误清日志。

只有原任务身份/类型和权威摘要完整核对后，才清除本机待核对入口；受理任务始终可从操作任务列表找到。本机恢复将旧入口标为历史，旧网关失效；跨设备权威代次和完整导入历史化仍由v2阶段完成。未知本机记录还可明确移除：提示这不会停止后台任务，原任务仍可在任务中心查询，新清理必须重新确认；移除本机记录不提交任何服务端命令。

## 验证与后续边界

服务端新增检查覆盖真实扫描后缺失、活跃元数据清理/历史保留、重新出现获得新ID、停用/离线/未扫描/符号链接保留、固定1003成员及新缺失排除、24项后分页、原ID重建继续、历史不运行与确认/扫描互斥。1003检查主要验证持久范围和有界投影，不替代NAS性能。客户端HTTP、日志写入/未知/404/错误回执/连接隔离、组件取消/分页/大字号与目录表单测试分层记录；原生结果按实际源码及证据单独归档，不能据本文设计标为通过。

此阶段仍不完成管理备份v2。新父/成员表、默认设置、所有恢复/永久删除父子图和回执均须进入类型化v2管理数据，支持v1转换、根映射、前快照、完整替换、跨设备代次和历史只读；有界文件传输及真实系统选择器也继续。其它命令/来源强停、旧图片失败根因、全原型暗色/横屏与手势、真机/NAS性能及原签名升级仍未验收。LF7和总任务保持开放。
