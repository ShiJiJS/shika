# LF1：兼容迁移与媒体类型边界

对应 [#26](https://github.com/ShiJiJS/video_viewer/issues/26)，基于 LF0 / [PR #34](https://github.com/ShiJiJS/video_viewer/pull/34)。本阶段先提供真实服务数据基础；新导航、图包扫描和阅读器按 LF2–LF7 继续接入。

## 已实施

- `0004 → 0005` 增量迁移新增根目录 `kind/enabled`，旧根默认 `video/true`。旧客户端省略新增字段的 PUT 保留已有配置；目录存在已索引内容时拒绝直接改类型。
- 停用与离线独立。停用不抹掉索引、标签、进度；视频列表、计数、播放、身份匹配和缺失清理服从即时策略，扫描跳过停用/图包根。嵌套图包或停用根是边界，外层视频根不能穿透；同类型重叠仍保留旧版外层归属以保持身份。
- 图包独立实体：包、页、包级标签与关联、进度/偏好、最近、固定会话/队列及回收操作/步骤/清单。进度页必须属于同一个包，最近记录必须且只能引用对应媒体类型。没有单图标签接口。历史路径允许复用，当前占位另由唯一 `location_key` 管理；旧缺失包和新同路径包可保留不同 ID 和页清单，不按路径继承标签/进度。
- `/pack-tags` 与 `/pack-tag-links` 独立 CRUD、搜索、分页、可用包计数和批量 add/remove/replace。视频与图包可同名；跨类型 ID 在变更前整次拒绝，重放按独立命名空间核对。
- `/info` 新增 `schema_version: 0005`、`typed_roots` / `pack_tags`。未接好的扫描/阅读器不宣告能力。客户端解析目录类型/启停和能力，旧服务默认视频模式，旧写入不发送新字段；需要新能力时清晰报错。迟到连接不能覆盖新连接的能力。
- App 增加独立的 `PackQuery` / `PackBrowseContext`：目录、标签、搜索、阅读状态、排序与返回位置；视频方向/时长不能混入图包查询。

## 升级、回退与备份边界

升级前用 SQLite backup API 留下包含 WAL 的完整管理快照，目录 0700、文件 0600。迁移前先落盘恢复标记；异常恢复旧库，中途进程终止则下次启动先恢复再重试。成功后同步清除标记。快照留在服务端管理目录 `migration-snapshots/`，不上传仓库。

回退旧服务前必须停服务并恢复升级前完整快照，不能把旧服务直接指向 0005。这样会舍弃升级后的管理修改；这与普通业务备份恢复不同。

LF7 尚未实现备份 v2。本阶段冻结 v1 的原有视频逻辑格式（schema 0004，保留旧根列），纯视频且全部启用的旧库仍能导出/校验/恢复。一旦有图包表数据或非默认目录状态，导出和恢复明确返回 `409 backup_upgrade_required`；接受前及执行前再次检查，避免“成功但漏掉新数据”。LF7 必须移除临时门禁，完整备份两类数据并支持明确确认后的 v1 转换替换。

## 验证

Android I1 两阶段通过，含真实服务分页/目录/断线恢复和进程重启后的已保存凭据/深层目录恢复。软件渲染两次导致 QEMU 图形线程卡死，改为 Mac host GPU 且关闭 Vulkan 后通过；脚本默认与实测配置保持一致，失败运行不算通过。

详细结果见 [LF1 证据](https://github.com/ShiJiJS/video_viewer/blob/c9c6363ab1ca3bb7d72c96499432a289de33f187/docs/plans/library-first/evidence/lf1-results.json)。冻结 0004 夹具对升级前所有旧表/旧列逐行比较，视频、标签、轮次、物理/逻辑回收和待确认命令不变；升级不执行旧命令。异常与中断后的恢复、跨包进度外键、标签类型隔离、停用不缺失、嵌套类型隔离、旧备份安全门禁和 OpenAPI 字段均有自动验证。

静态迁移与 ORM 的结构对照排除唯一既有差异：0004 的 `trash_active_video` 索引原本没有在旧 ORM 声明；新增结构必须完全匹配。原有 Ruff 格式基线尚有 10 个未修改文件未通过，全量业务测试与格式检查分别记录，不合并成“全绿”。

原型仍由 tag `design-lf-2026-10-23` 固定在独立的 `design/reference/`，本阶段未修改参考。最终产品与原型的一致性验收留在 LF8。本阶段未改真实 NAS 文件、未发布升级 APK。
