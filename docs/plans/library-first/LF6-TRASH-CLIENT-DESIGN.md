# LF6 双类型回收站与图包恢复

沿用冻结原型P2的设置→回收站入口和视频/图包分区。视频保留旧操作接口、选择和回收记录；图包使用独立的回收条目ID、分页查询、搜索、选择与操作回执，不能把pack ID作为trash ID发送。恢复入口先行，图片清单永久删除仍是LF6必需的后续工作，不据此关闭阶段。

## 读取与选择

PackTrashCatalog固定服务连接与管理数据代次，page和完整selection各有独立的可取消读取范围；不取消视频读取或文件命令。页数据验证类型、分页计数、唯一回收/图包身份、回收状态、图片数与时间；全选验证kind=pack-trash、唯一ID和完整总数，最多五万，拒绝伪完整前缀。接口不受理时明确报错，不用Demo或视频列表代替。

PackTrashSession持有一个搜索条件、24项分页及完整ID选择；翻页不丢选择，全选后可逐项排除。搜索改变清选择并拒绝旧列表/旧全选的迟到结果；读取失败保留同查询已有页。最后一页恢复为空时按当前总数回到有效页，不误显示为全站空列表。该界面不会把全部图包数据一次载入，只为完整选择领取轻量ID快照。

页面按原路径、数量、阅读状态呈现整包记录，说明恢复会保留标签、位置与阅读偏好。列表、全选、恢复与待核对状态分别展示；全选可取消。一次只有24项行数据，多个待核对命令由独立入口进入滚动面板，避免撑满整屏。普通字号保留紧凑排布，双倍字号允许正文/路径自然换行；错误与重试分行，计数与选择按钮复用MediaCatalogToolbar分行规则。搜索字号与媒体库相同为14，不缩小系统字号。首次读取失败明确显示错误与重试，不误报零项或空回收站；已有页的读取失败保留原数据。

## 恢复与未知结果

恢复冻结所选trash IDs，按每批最多1000项提交。每批先落盘不可变请求，再POST；明确完成才处理下一批。成功项从选择中移除，失败项仍选中并显示未完成提示；后续重试只处理未完成项。批次结果按实际成功/失败汇总，不把部分成功当全成功。

响应未知时停止后续批次，原命令保留在独立PackFiles日志中；当前界面保留尚未确认和未提交项的选择。查询只GET原request/task，404不自动重发；显式重新提交仍用原键与负载，已知任务不再POST。当前尚未持久化整份多批次计划，关闭App后未提交选择需要重新选择，这是实施限制。最终仍须接入统一管理任务，让整份计划和进度可恢复；不能把每批请求日志当成完整后台续作。其它页面和媒体类型继续可用。

切到视频或离开页面时取消只读请求/全选，已受理命令继续由后端处理，客户端不再提交后续批次；回到图包页可查询原结果。连接/管理数据代次改变时清掉旧视图，迟到结果不应用到新连接，旧持久化命令仍留在其原连接分区。初始化碰到恢复门禁时显示可重试错误，不让构造异常破坏整个设置页。

图包回收站的恢复属于内容恢复，不抢占正在使用的阅读路由；阅读器及其来源的限时撤销仍由原阅读上下文处理。全局任务、管理恢复门禁与实际安全存储重开继续由LF7整合。
