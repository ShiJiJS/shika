# 服务端默认值与旧本机设置迁移

设置里的默认播放顺序只影响下一次进入预览，阅读偏好只影响尚未实际阅读的图包。媒体库、标签和最近仍分别确定入口范围；保存默认值不创建范围、不推进位置、不改当前会话或已阅读包的偏好。冻结原型继续独立保存在 `design/reference/library-first/`，本阶段不修改它。

## 权威值与兼容

视频默认顺序使用管理设置 `playback_defaults`（order、revision）。服务启动时若不存在，以旧 `active_round` 的顺序建立 revision 0；没有旧范围时采用原有随机默认。建立后独立于轮次，旧客户端改变播放顺序也不回写默认值。不需要增加数据库表或更改旧客户端的创建范围协议。

新增鉴权 GET/PATCH `/api/v1/playback-defaults` 以及 GET `/api/v1/playback-default-requests/{request_id}`，能力名 `managed_playback_defaults`。写入绑定 expected_revision 和 request_id，幂等命中先返回原结果；不同载荷重用ID拒绝，版本冲突不覆盖。不提供修改当前轮次的副作用。

新 App 每次从媒体库、标签或最近进入视频预览前读取当前服务的默认值，再提交该次范围；读取失败保留入口并显示错误，不静默使用另一台服务的值。已打开的范围不随默认值变化而重排。缺少新能力的旧服务沿用原本机默认和原视频协议。

图包复用既有 `/reading-defaults`、`WriteReaderDefaults` 与只读原请求接口，不建立另一套设置。模式、方向、间距、适配方式一起以同一revision保存。实际第一次打开图包时才冻结本包偏好；已读包的revision 0也是独立偏好，不能因全局默认改变而覆盖。

## 迁移与连接隔离

旧 `appearance.json.videoOrder` 保留用于旧服务兼容，不自动上传，也不继续作为支持新能力服务的权威值。设置面板先展示当前服务值，并提供“选用本机旧顺序”与“沿用服务端设置”：前者只改草稿，仍须明确保存；后者只保存本机迁移决定，不写服务。

迁移决定按规范 endpoint + server_id 保存于本机 `defaultMigrations`，和主题/相邻准备共用串行落盘。换端口、地址或实例分别选择；其它设备修改服务端默认不会被旧本机值自动覆盖。保存时版本已变则要求重新读取后再决定，保留错误说明；保存服务端成功但本机标记写入失败时如实区分，不能重发并当成第一次保存。

设置网关绑定连接及现有管理数据代次；切换连接、备份恢复或销毁后，旧请求不再发布或操作新连接。未来v2导入后使用新的服务端权威代次，本阶段现有本机代次不能代替跨设备恢复历史化。

## 面板与未知结果

沿用 Paper 设置行和短底部面板，内容可滚动；先读取、编辑草稿、明确保存，关闭/取消不提交。默认值没有文件删除权限。确定未受理4xx保留草稿并要求重新读取；超时、503或不完整成功响应保留原命令，只读核对原ID，不自动重发。404保留未知状态，提供继续查询或明确读取当前服务值；后者只采用权威当前值，不把原请求算作成功。

离开面板后再进入会重新读取当前权威值；本阶段默认值草稿和未知回执不加入破坏性文件命令日志。文件删除/恢复命令的持久核对机制保持独立，不能把默认值的只读重开策略套用到这些命令。

## 备份边界

正式v1不包含这些管理默认值。保护检查必须拒绝会遗漏明确保存默认值的旧格式导出/恢复；未修改的revision 0仍可使用原v1。合法v1完整恢复后，从导入轮次重建隐式默认，不能继承被替换库的默认。v2仍须完成类型化默认值、图包/两套标签/进度/最近/会话/回收及完整父子成员回执图、根映射、前快照、原子替换、权威代次与历史只读，以及有界文件传输。当前拒绝遗漏只是保护，不是v2实现。
