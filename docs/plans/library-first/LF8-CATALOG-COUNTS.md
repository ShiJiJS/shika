# LF8：媒体库两类权威总数

本段补齐冻结原型媒体库类型栏的“视频 N / 图包 N”，沿用 Paper、40dp普通类型栏、15dp类型名、12dp数量与7dp间距。用户选择的完整原型不修改，参考目录独立可移除。只在媒体库显示两类全库数，标签和最近继续表达各自范围。

## 统计口径

计数指服务端当前目录元数据中、实际无条件媒体库可以浏览的成员数量，不是缓存页数、扫描任务的新增/处理数、图片页数或当前筛选结果数。一个图包计一项；只有启用且在线的相应类型根目录、拥有正确路径归属且可读的内容进入计数。图包至少有一张可读页；视频错误、缺失、回收以及图包错误、无可读页、缺失、回收不计入。根目录/内容状态由实际扫描与管理命令维护，统计读取不重新探测NAS文件。

复用现有 `GET /api/v1/library-state`，新增能力 `media_catalog_counts`。具有该能力时，`media.video.indexed` 与 `media.pack.indexed` 使用目录本身的查询规则，并在一个显式SQLite只读快照中计算；不会为计数生成媒体摘要、图像或阅读范围。顶层 `indexed` 与扫描任务 `counts` 保留原兼容含义，客户端不得将其代替类型总数。

## 发布与失效

`LibraryRepository.catalogCounts` 只承载同次响应的一对已确认整数或未知状态，`refreshCatalogCounts()` 只读重试。初次连接/既有扫描状态轮询复用同一份状态响应，不为每个类型、搜索或分页额外查询。轮询仍沿用建库/扫描约2秒、闲置约10秒的现有节奏。

计数读取独立于两类分页、标签、阅读和管理写请求。连接代次与最新请求次序共同约束发布，较早响应和旧连接不能覆盖新计数；同一数值不重复通知。图包操作完成时使计数失效，重新读取状态，不触发扫描。视频与根目录的现有同步路径也发布新计数。

不支持该能力的旧服务隐藏数量标记，不猜零。失败、缺字段、负数、非整数或断线为未知；界面显示“—”，类型名及选择仍可用，点选分类可只读重试。实际空库返回的零正常显示。搜索/标签/阅读状态/目录条件只改变结果区，不改写类型总数。大字和极长数字保留完整值，类型栏允许水平滚动以到达另一类型，不缩字或省略精确数量。

## 验证范围

服务端覆盖27项超出24条首屏、搜索结果与总数分离、空库、两类不可浏览状态、权限、只读历史/进度，以及两个计数之间并发提交的快照一致性。客户端覆盖旧服务、未知与真实零、请求晚到/换连接、分页互不取消、图包操作后重读及正常扫描轮询复用；组件检查类型切换、搜索保留、其它来源隐藏、大字号长数和失败重试。

原生验证使用已有AVD、真实服务适配器与每轮新建8768隔离服务/DB。公开2视频、4包、24PNG；从界面验证全库计数、零匹配筛选、标签/最近隐藏和失败重试，通过真实管理网关执行整包逻辑回收/恢复，验证2/4→2/3→2/4。管理网关命令用于测试计数更新，本段不重新宣称删除确认UI已验收。前后页码、最近、源字节和设备配置分别核对；不使用正式8760或NAS。

横屏原生验证还覆盖从搜索导航到标签的键盘收起过渡。IndexedStack会对非当前页参与布局，而Scaffold已消耗键盘inset，标签底部操作区因此按实际可用高度的60%设滚动上限，保留列表空间；普通高度仍按内容自然排布。组件验证61dp缩高、滚动到操作与恢复高度，不通过延迟或忽略Flutter异常规避。
