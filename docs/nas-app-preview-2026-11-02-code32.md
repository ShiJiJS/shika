# 第32版：大批量图包删除清单持续等待

App为`0.2.0-preview.26`，Android版本号32；沿用原包名和Windows签名。正常安装包为`video-viewer-0.2.0-preview.26-arm64.apk`，同号旧视频界面回退包为`video-viewer-0.1.4-rollback.26-arm64.apk`。

对应[#184](https://github.com/ShiJiJS/shika/issues/184)：大量选择后准备永久删除清单时，持续查询同一份任务，显示已核对/总共图包数和已核对图片数。短暂超时自动继续查询，不直接误报整个准备失败。保存当前批次准备编号，关闭、重新打开或明确重新准备后均可续查。正在准备时不提供再次准备；完成、有效且重新勾选后才能确认删除。

[设计、边界及实现](plans/library-first/PURGE-PREPARATION-WAIT.md)。本次只改App等待与反馈，不减少文件指纹校验，不承诺核对时间缩短；旧版未保存编号的已有任务不会被自动接管或取消。NAS服务preview.8、地址、口令、原型目录与媒体文件均不变。

本次`flutter analyze`无问题，20个相关测试文件共171项通过。含真实等待超过26秒、丢失准备响应、读取短暂超时、同一批次续查、更新准备编号持久化、关闭后的迟到结果保护，以及622项普通/2倍字体布局。其他相关检查涵盖图包回收、文件操作日志、选择批次、任务和历史页面；没有重新执行全套客户端或服务端检查，未做实体手机操作验证。NAS排查只读取已有清单任务状态，没有对真实收藏执行恢复或永久删除。

交付到NAS原`SATA存储11/docker/video-viewer/packages/`，Mac本地位于`tmp/releases/`。正常及回退APK均经过原签名、同号覆盖、ARM64、正式入口和不含测试插件/原型资产检查，并核对NAS副本SHA256后才记为交付完成。直接覆盖安装，不要卸载或清除数据。

本地只保留最新正常/回退APK、原服务包和清单说明；临时构建与日志在交付后清理，保留回归测试、SDK和签名。用户要求保存的图包回收站记录继续保留在私有本地`backups/`与NAS，不上传GitHub。其他开发和旧验收仍暂停。
