# 视频与图包怎么存放

视频按文件收录，图包按文件夹收录。文件名可以自由取，不需要准备清单、标签文件、封面或特定编号。先在 Docker 中挂载媒体路径，再在 App 的设置中添加对应类型的目录。

## 推荐目录

```text
NAS 媒体目录/
├── videos/                   → 容器内 /media，添加为「视频」目录
│   ├── 旅行/海边.mp4
│   └── 记录/片段.mkv
└── packs/                    → 容器内 /packs-cos，添加为「图包」目录
    ├── 图包 A/               → 一个图包
    │   ├── 001.jpg
    │   ├── 002.jpg
    │   └── 010.jpg
    └── 图包 B/               → 另一个图包
        ├── 01.png
        └── 02.webp
```

例如 `.env` 中填写 `SHIKA_PACK_DIR=/srv/media/packs`，Compose 将它挂到 `/packs-cos`。App 中添加的是 **`/packs-cos`**，不是 NAS 的 `/srv/media/packs`，也不是电脑上的 SMB 路径。`mounts.json` 中还需允许访问这个容器内范围，具体配置见[部署手册](deployment.md#3-设置路径)。

## 图包的划分与阅读顺序

- 接入目录的**每个一级子文件夹**是一个图包。将上图的 `/packs-cos` 接入后，会出现图包 A、图包 B。
- 一级子文件夹里面还可以有子目录，其图片会递归加入**同一个图包**。例如 `图包 A/第一部分/01.jpg` 与 `图包 A/第二部分/01.jpg` 都属于图包 A。
- 直接放在接入目录中的零散图片不会自动组成图包。如果现有目录本身就是一个图包，应接入它的父目录。
- 图片按相对路径的自然顺序排列，数字按数值比较，例如 `1.jpg`、`2.jpg`、`10.jpg`。分组子目录也参与排序；建议用 `01/`、`02/` 和 `001.jpg` 这样的编号固定阅读顺序。
- 文件夹名用于图包的默认标题；标签和阅读进度保存在服务端数据库中，不要求在名称中加标签，也不要求旁边放 JSON 或其他资料文件。

如果有“作者 → 多个图包”的分组：

```text
packs/
├── 作者甲/                   → 把这一层接入为图包目录
│   ├── 作品一/001.jpg
│   └── 作品二/001.jpg
└── 作者乙/                   → 另外接入这个目录
    └── 作品三/001.jpg
```

在 App 中分别添加 `/packs-cos/作者甲` 和 `/packs-cos/作者乙`，会得到三个独立图包。若只接入 `/packs-cos`，则作者甲和作者乙会各自成为一个图包，里面的作品会合并阅读。已有分类可以保留，按实际分组添加多个目录即可。

命名不是强制要求。若希望界面自动区分作者、编号和标题，当前支持 `作者名 NO.001 - 作品标题` 这样的文件夹名；普通名称会完整显示，不会仅凭上级目录、方括号或连字符猜测作者。名称中的标签不会自动导入，标签在 App 或相应接口中维护。

## 支持的文件

| 类型 | 当前扫描范围 |
| --- | --- |
| 图包图片 | JPG、JPEG、PNG、WebP，扩展名大小写均可 |
| 视频 | MP4、MOV、M4V、MKV、WebM、AVI、MPG、MPEG、TS、MTS、M2TS、3GP |
| 压缩图包 | ZIP、RAR、7z、CBZ 等不会自动解压或作为图包阅读，请先解压成文件夹 |

GIF、BMP、HEIC、PDF 等不属于当前图包扫描格式；带动画的图片也不能当作普通静态页使用。视频被收录不代表每台手机都能播放其中的编码，服务端目前不实时转码。

没有可读图片的子文件夹可能显示为没有可阅读图片的图包；扫描问题页面可以查看原因。服务不跟随符号链接，NAS 的回收站及系统缓存目录等会按扫描规则排除。封面自动取可生成缩略图的可读图片，不需要额外放一份封面。

## 标签、删除与迁移

- 在 App 添加标签即可，视频标签与图包标签独立；图包内没有逐图片标签。
- 移入回收站只改变管理记录，原目录和文件不移动。**永久删除图包会删除所选文件夹，包括其中的其他附件**，不要把需要独立保留的文件放在图包里面。
- `data/` 保存标签、阅读进度等管理记录，媒体另行备份。升级或迁移时保留 `data/`、目录 ID 和容器内路径；移动文件后重新扫描，身份不明确时不会猜测继承旧记录。

以上说明对应当前扫描器的实际行为，文件格式以[图片扫描](../services/server/shika/images.py)和[视频扫描](../services/server/shika/paths.py)为准。
