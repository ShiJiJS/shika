## 已取得的目标条件与仍缺少的信息

用户确认 NAS 为**极空间**，实测 Rockchip RK3568、4 核 ARM64、Linux 5.10.110，内存约 3.63 GiB。Docker Engine 24.0.0 / API 1.43 / linux-arm64 可通过 `sudo -n docker` 访问，普通账户直接访问 socket 被拒绝。现已在项目目录安装并校验 Compose v2.39.4 ARM64 独立二进制，保留全局 Docker 设置。用户指定的媒体位于本地 btrfs 卷，扫描前统计 4,065 个视频（4,049 MP4、16 MOV），总计 445,766,885,749 字节；只挂载该目录，不扩大到整个个人资料盘。具体商业型号和目标手机系统仍待确认。

目标手机为 **OPPO Find X8**。厂商参数列出天玑 9400、2760×1256 屏幕、最高 120Hz 及 Wi-Fi 7；它们只用于规划目标测试，实际系统版本、Wi-Fi 条件和解码能力需以用户设备为准。[OPPO 官方参数](https://www.oppo.com/cn/smartphones/series-find-x/find-x8/specs/)

本机已生成仅用于本项目的 SSH 密钥，私钥在仓库之外，Windows ACL 仅允许当前用户。用户已自行安装公钥，不提供密码；登录及当前账户的 `sudo -n` 管理员权限均已验证。密钥本身不提升权限。详细连接信息和公钥指纹登记在私有 infos，私钥仍只在本机；密钥内容、个人地址和凭据不进入本仓库。

用户已授权部署并指定实际媒体目录；本次只扫描和读取现有收藏，不用它们做故障注入或永久删除测试。后续破坏性验收仍需可丢弃副本。手机安装包、服务地址和专用口令定位已交付给用户，由用户在同一局域网进行 Find X8 体验测试。

## 目标验收步骤

1. **只读盘点**：SSH/权限/架构/Docker、媒体卷与文件系统、Compose 部署已完成；继续确认商业机型及 Find X8 的当前系统、ABI、屏幕刷新率和实际 Wi-Fi 连接。
2. **安装与持久化**：在专用应用目录配置数据、媒体、回收位置和口令，构建匹配架构的 runtime 镜像，单端口启动。手机连接后扫描、播放及打标签，再重建容器核对实例、标签、轮次及数据。
3. **目标文件与界面**：以明确的可丢弃副本测试目录选择、随机/顺序、交集筛选、快速整理、删除/撤销、回收冲突与确认永久删除、外部变化和断线重开；完整回归已确认的滑动、进度、长按、横屏、亮度/音量和暗黑两个入口。实际手机系统选择器检查保存、取消及重新选取正式备份。
4. **恢复与边界**：保存管理导出及媒体字节证据，在另一个空管理实例显式映射恢复，核对媒体不被移动；检查未认证媒体/备份、越界和篡改拒绝。恢复测试保留原实例目录与数据，不能拿一次重建当成新实例恢复。
5. **测量和约定**：按下面相同样本/条件记录基础表现，再与用户明确可接受阈值并复测。问题和不支持编码逐项记录，不能以文件扩展名宣称全部兼容。
