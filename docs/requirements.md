# 私人视频库需求对齐

状态：用户已整体确认第一版需求基线，并授权编写方案。尚未开始实现；技术选型及设计细则见第一版规格，仍需实际验证。

## 产品目标

为个人 NAS 中的横版、竖版短视频提供 Android 优先的 App：日常随机观看，通过标签快速查找，快速删除不想保留的视频，并在需要时主动整理物理目录。

## 已确认

- 服务端部署在 NAS 上，采用 Docker，暴露服务端口。
- 手机端直接提供 App，主力设备为 Android；希望采用可跨平台的框架。用户现暂定使用 Flutter，已授权配置本机开发环境与模拟器。
- 第一版只管理视频，包含横版和竖版；暂不考虑图包。
- 仅个人使用，第一版只考虑局域网访问。
- 日常浏览收藏是主要入口，另设集中整理模式。
- 文件已有 NAS 文件夹结构；初次接入时不改变原文件。
- 支持接入多个指定媒体目录及其子目录，定期扫描并提供手动刷新。
- 新视频由用户通过现有外部工具放入 NAS；第一版不做 App 上传、下载或离线缓存。
- 归档分类与标签分开：每个归档分类对应用户指定的物理目录，目的是离开 App 后也方便查找。
- 选好分类后由用户主动执行归档，先展示目标路径，再移动文件；修改标签不触发文件移动。
- 用户会继续在 App 外管理文件，需支持外部新增、改名、移动等变化；同一视频改名或移动后应尽可能保留标签。
- 接受外部移动后的新位置，不自动搬回；移入另一个已配置分类的目录时更新归档分类。
- 文件缺失时保留标签记录，暂时移出可播放列表；重新找到并确认是同一视频后恢复关联。
- 整个目录不可用时显示连接异常，不视为批量删除。
- 同一视频支持多个手动标签，并可多选标签筛选。
- 多选标签采用交集，即同时满足所选标签；第一版不要求并集或排除筛选。
- 支持单条快捷打标签与多选视频批量打标签，文件夹名不自动转为标签。
- 标签先平铺，支持搜索、新建、改名、删除；删除标签只解除关联，不删除视频。
- 横竖屏、时长、文件类型等可识别属性作为独立筛选条件。
- 同时支持单条滑动播放与缩略图列表，可连续浏览标签筛选结果。
- 默认随机浏览，当前视频播放结束后循环；一轮内不重复，退出 App 后继续本轮，支持主动重新随机和向回滑看上一条。
- 随机浏览的位置独立于保留或删除，不代表视频已整理。
- 横版视频默认完整显示，支持横屏全屏观看。
- 支持暂停、拖动进度、倍速和横屏全屏；切换到一个视频时从头播放，第一版不做每条视频的断点续播。
- 实际收藏基本为短视频。
- 整理只区分保留或删除；所有未删除视频都视为保留，不增加已整理、待决定、跳过状态，也不要求未整理队列。
- 删除立即移入回收站并播放下一条，不逐条弹确认，支持撤销上一次删除。
- 回收站支持恢复和批量永久删除；永久删除时确认，默认不自动清空。
- 整理模式使删除操作更容易触达，不增加额外的保留状态。
- App 首次填写 NAS 地址与端口、输入个人访问口令；之后记住连接并进入浏览，不做注册或多用户系统。
- 标签、归档配置等管理数据持久保存在 NAS 上，容器重建后保留，并提供备份与恢复；管理数据备份不额外复制整套原视频。
- 不需要电影、剧集刮削。

## 第一版验收场景

以下是待实现功能的验收依据，不代表已经实现或测试通过。

| 场景 | 预期结果 |
| --- | --- |
| 初次接入多个含子目录的视频目录 | 发现视频且保留原路径与文件名，不主动移动原文件。 |
| 通过外部工具放入新视频 | 定期扫描或手动刷新后可以发现并浏览。 |
| 手机首次连接与后续重开 | 使用地址、端口、个人口令连接，后续记住连接；不要求注册账户。 |
| 随机刷与重开 App | 当前视频播完循环，一轮向前刷不重复；重开继续本轮，支持回看和主动重新随机。 |
| 浏览横版或竖版视频 | 默认完整显示，可暂停、拖进度、倍速和横屏全屏；切换到视频从头播。 |
| 按多个标签筛选 | 仅显示同时满足所选标签的视频，可在缩略图列表与连续播放间使用结果。 |
| 给一批视频打标签 | 批量关联所选标签；删除或改名标签不删除原视频，文件夹名不自动转为标签。 |
| 快速清理 | 点击删除成功后视频进入回收站并切换下一条，不逐条确认；可以撤销上一次删除。未删除视频默认保留。 |
| 回收站管理 | 支持恢复和批量永久删除，永久删除需确认，默认不自动清空。 |
| 主动归档 | 先展示目标目录，经用户执行后才移动；修改标签不会移动文件。 |
| 外部改名或移动 | 扫描后接受新位置，不自动搬回；确认是同一视频时保留标签，移入其他已配置分类目录后更新分类。 |
| 文件缺失或目录暂时不可用 | 保留管理记录，不把目录异常当作批量删除；缺失视频暂不进入播放列表。 |
| 重建容器或恢复管理数据 | 持久化数据在重建后保留；备份可恢复标签、归档配置等管理数据，不依赖复制整套视频。 |

## 后续方向

- 用户希望未来接入 AI 自动打标签；第一版先完成手动标签和批量打标签，不实现 AI 打标。建议未来优先使用已有标签；模型、标签生成规则、审核流程留待后续决定。

## 下一阶段：技术验证与设计

### 技术验证，尚未定选型

- 用户确认先配置 Android 开发环境与模拟器，在模拟器中测试完整 App 流程；真实手机留作后续兼容性验证。
- 需核实媒体规模、文件格式与编码分布、NAS 配置、手机播放能力和局域网加载表现；目前尚未提供媒体库位置或可用连接。
- 当前先按 Flutter 配置开发与模拟器测试；后续根据真实样本验证播放器方案及是否需要服务端兼容处理，必要时重新评估选型。不能仅凭扩展名承诺所有视频可播。
- Android 为首要交付和验收设备；其他平台的具体交付计划尚未确定。

### 设计阶段需要明确的细节

- 分类目录嵌套或重叠时的匹配规则、移动到未配置分类目录后的显示。
- 文件身份识别、重复副本、同路径文件被替换时的标签归属。
- 归档或回收站恢复时的同名冲突、移动失败及撤销失败处理。
- 随机一轮结束、切换筛选、浏览期间新增或删除视频时的队列规则。
- 扫描间隔、备份触发与保留策略，以及备份恢复时的现有数据处理方式。
- 上述细节尚未确认，不应作为用户已经接受的规则；在设计稿和验收场景中明确提出，涉及新的产品取舍时再对齐。
