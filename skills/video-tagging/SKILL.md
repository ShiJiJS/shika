# 拾刻配套视频打标 Skill（选装）

把识别原答、标准标签和软件关联分层保存。完成意味着每个输入都有明确状态、每个标准标签有依据、导入关联已读回核对；运行成功不等于识别正确。

## 安装与 CLI

本技能随 `ShiJiJS/shika` 仓库发布，属于选装工具。首次安装或本机 CLI 缺失时，读 [安装与设备配置](references/portability.md)，运行随包 `scripts/install.py --cli-only`，核对 `--check` 返回 ready。安装只配置独立 Python 环境中的 shika CLI；模型、媒体根和服务登录由本次任务另行配置。使用 `python "$skill_dir/scripts/shika.py" ...` 调用配套 CLI，无需修改系统 PATH。通过 Skillshare 只复制文件的安装，也需完成这一步才具备 CLI。

## 选择与隐私

1. 先确定本次范围：新视频识别、仅整理已有标签、仅同步，或全流程。已有标签整理与同步无需抽帧。
2. 新识别必须由用户选择 **线上** 或 **本地**；沿用本次任务已给出的选择，否则只问这一项并继续清点元数据，不先运行识图。线上选择意味着将本批抽帧交给指定线上服务，模型或服务不明确时先补齐。禁止因本地失败自行切线上。
3. 默认当前助手不观看原视频、帧图、总览图、缩略图或播放页面；本地模型可以按选择读取本地图片。选择线上后，仅把所需图片交给已选识别服务，不自动授权当前助手展示或阅读它们。没有独立且获准的服务时说明缺少执行能力，保留准备好的任务。
4. 标签文本权限与图片权限分开。沿用用户已有授权；未明确时默认标签和原答也留在本地，工具只输出匿名编号、计数、状态和错误类型。标签可读时才能检查文本和制定具体映射。严格隐私模式下，按本地已有映射处理，未知项留空并保存本地待核清单，不把内容转交其他 Agent。
5. 原视频只读；原始标签和原答不可覆盖。修订写入新版本标准文件，保存快照和差异。是否移动视频、删除异常文件、变更服务挂载另按用户的具体授权处理，不由打标自动触发。

## 工作流程

1. **准备输入**：定位工作区、原始记录、旧目录索引和软件入口；连接通过配套 CLI 的用户配置或用户指定的私有配置读取。读取 [数据与运行约定](references/data.md)，生成稳定编号清单、隐私选择和运行配置。运行前用 protect 保存原始文件散列；归并与同步计划必须通过 verify。换电脑、工作区移动或依赖缺失时读 [跨设备配置](references/portability.md)。凭据、个人文件名和运行结果留在私人工作区，不入技能 Git。
2. **识别分支**：只在需要新识别时读 [模型与抽帧](references/inference.md)，使用随包入口准备线上任务或本地运行。抽帧参考已安装的 video-understanding，但只复用抽帧工具；本技能的隐私选择优先于它要求当前助手读图的步骤。缺依赖只列出缺项，不擅自改模型、联网下载或重新处理已有结果。
3. **标准化**：读 [严格归并](references/normalization.md)。原目录分类与原始肯定标签分别作为事实输入；确定的中文别名可以映射，不确定项保留在原记录及待核清单。生成独立标准 JSON、MD、逐条依据、增删差异。禁止为达到覆盖率强加类别。
4. **软件同步**：用户要求导入时读 [同步与迁移](references/sync.md)。先完成备份、完整扫描快照和 match 唯一视频匹配，再生成绑定库实例与挂载快照的计划，再进行已授权的差量写入并读回。已有授权无需重复确认。
5. **交付**：说明本次使用的路线和实际模型、成功/错误/待核数量、标准文件与备份位置、软件核对结果和未完成范围。严格隐私模式只报告统计，不展示内容标签或带内容的路径。

## 随包工具

- [识别入口](scripts/infer.py)：`prepare` / `local` / `import`；原答按配置指纹分版本保存，复用需核对视频大小与修改时间，强校验时提供内容散列。
- [图片模型](scripts/image_tagger.py)：本地 ONNX，模型权重是外部依赖。
- [归并与同步计划](scripts/catalog.py)：`protect/verify` 保护原始文件，`normalize` 校验原字段，`match/plan` 核对新索引并生成差量计划；不直接写服务器。
- [选装安装器](scripts/install.py) 与 [CLI 入口](scripts/shika.py)：安装 Skill 时配置 CLI，或为已安装 Skill 单独配置 CLI；声明见 [依赖](assets/dependencies.json)。
- [默认配置](assets/config.json) 与 [识别提示词](assets/prompt.txt)：复制到私人工作区后调整；实际模型与提示词随批次留档。

Windows、macOS、Linux 使用同一数据格式；依赖、路径、Ollama、模型权重和认证按设备检查。处理归并、迁移或同步时按 [常见问题核对表](references/pitfalls.md) 自检。新封装只经离线模拟验收，真实模型推理与服务写入的历史经验不等于新包在各系统已实测。
